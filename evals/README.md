# evals/ —— L0 地基的第二部分：评测集骨架

> 本目录落地 [docs/07 §3.2](../docs/07-自我迭代能力.md) 描述的三类用例，是
> [ADR-0032](../docs/adr/0032-地基复审三-M1收尾前的原则符合度审查.md) #4 的产出。
> **这一轮只补骨架 + 真实案例的数据结构，不实现评测运行器**——运行器（跑用例、
> 出指标看板）是 [docs/08](../docs/08-路线图与里程碑.md) M5 的交付项，本轮没有
> 载体去验证一个运行器的设计对不对，提前写等于再造一个"测试全绿、从未跑过"的
> 东西（同 ADR-0020 决策三、docs/09 G2 的处理方式）。这里要解决的是更早的一步：
> **L0 要求的数据没有地方放**——docs/07 明写"M1（地基，必须先有）"，但在这次
> 复审之前，这个目录根本不存在。

## 三类用例（docs/07 §3.2）

| 类型 | 内容 | 判定方式 | 目录 |
|---|---|---|---|
| **单元级** | 单个函数/工具/内核规则的行为 | 断言式，确定性 | `evals/unit/` |
| **任务级** | 真实任务（"给这个函数加测试并跑通"），带初始工作区快照 | 结果检查（文件状态/命令退出码）+ LLM 评判 | `evals/task/` |
| **回归级** | 历史上失败过的真实 case，修好后固化 | 同单元级或任务级，取决于失败的性质 | `evals/regression/` |

docs/07 的纪律："**每修好一个真实失败，必须往 `evals/regression/` 加一个用例**。
这是防止小明'改好一个坏掉两个'的唯一手段。"

## 当前状态：只有 `evals/regression/` 有一条真实案例

`evals/task/` 与 `evals/unit/` 目前是空目录（用 `.gitkeep` 占位）——本项目至今
没有一次"真的跑起来、独立于单元测试之外"的任务级评测需要固化，硬造一个没有
真实场景支撑的样例，比留空更容易误导人。

`evals/regression/g4-session-replay-superlinear.json` 是第一条：会话回放超线性
（docs/09 G4，[ADR-0032](../docs/adr/0032-地基复审三-M1收尾前的原则符合度审查.md)
#1 修复）。**这条 JSON 是一份结构化记录，不是一个当前能被独立执行的用例**——
真正锁住这个行为不再退化的手段是
`packages/runtime/tests/session-runtime.test.ts` 里的两条单测（`每 500 条持久
事件存一份快照` / `重新打开时...只从快照之后补读尾部事件`）。这份 JSON 的作用
是让"这个失败发生过、量化数字是多少、被哪条 ADR 修的"这件事有一个独立于代码注释
之外的、机器可读的落点——等评测运行器在 M5 落地时，它可以直接读这份记录去跑
性能回归，不需要再翻一遍 ADR 找数字。

## 案例文件的最小 schema

```jsonc
{
  "id": "字符串，kebab-case，全局唯一",
  "kind": "unit | task | regression",
  "title": "一句话描述这个失败/场景",
  "source": {
    "issue": "指向 docs/09 或类似文档里的问题编号",
    "fixedBy": "指向修复它的 ADR",
    "discoveredAt": "YYYY-MM-DD",
    "fixedAt": "YYYY-MM-DD"
  },
  "scenario": "复现步骤的自然语言描述",
  "assertion": {
    "description": "判定标准是什么",
    "measuredBefore": { /* 修复前的实测数字，如果有 */ },
    "measuredAfter": { /* 修复后的实测数字 */ }
  },
  "regressionTest": "真正锁住这个行为的测试文件/用例名（当前阶段这才是可执行的部分）"
}
```

## 为什么不现在就补历史上其它已修复的真实失败

这个项目的 ADR 历史里有不少值得固化的例子（注入降级从未生效、Windows 8.3 短
文件名绕过红线、`sh -c` 的四种写法判定不一致、多条 ask 主张连续发 request 导致
"点了没反应"……）。**不在这一轮批量补**，理由和"不提前建运行器"一样：批量把
历史 ADR 转成 JSON 是纯体力活，不是这一轮复审要解决的问题（复审要解决的是
"这个目录还不存在"），而且没有运行器之前，批量转换出来的文件只是摆着好看，
不会被任何东西读取或验证格式是否真的够用。留给以后真正设计运行器时，用
`evals/regression/g4-session-replay-superlinear.json` 当模板逐条补，那时候
"格式够不够用"这件事已经被至少一次真实使用验证过。
