# M2 · 阶段划分

> **状态**：M2-b 已于 2026-08-12 完成并通过全量验收；下一阶段 M2-c 尚未开始。
> **总目标**：达到“日常写代码可以用它”的水平；每个阶段结束时仓库都必须处于可运行、可单独验收的状态。

## 1. 拆分原则

1. **一次只实现一个阶段。** 当前阶段通过验收并更新文档后，才开始下一阶段；不跨阶段预埋空包、占位接口或半成品 UI。
2. **每阶段交付一条可使用的纵切。** 不能只交契约、只交后端或只交界面；用户或 headless runtime 必须能实际使用该阶段能力。
3. **阶段可独立回归。** 每阶段都有自己的聚焦测试与失败用例，后续阶段不能成为前一阶段测试通过的前提。
4. **先保退路，再扩大写能力。** M1.5 已有单文件写前 checkpoint；M2 在开放多文件编辑前，先把目录、大文件和整组回滚补齐。
5. **不恢复第二套权限系统。** M2 沿用 ADR-0039 的 `allow | deny`。diff 审阅是变更工作流，不得借机恢复 `ask`、审批档位或会话授权。
6. **架构决定先写 ADR。** 涉及事件、IPC、存储格式、索引生命周期、编辑提案或子 Agent 生命周期的决定，必须在对应阶段实现前定案。

所有阶段共同使用以下基础门槛：

- 开始前记录当前 `pnpm verify` 基线；结束时再次全量通过。
- 新能力至少包含确定性单元测试、跨层集成测试，以及一个与实际使用入口一致的 smoke/桌面验收。
- 护栏类改动必须先做一次反向演练，证明缺少护栏时测试确实会红。
- 真实体验失败进入 `evals/regression/`；阶段体验材料归档到 `docs/experience/m2/`。

## 2. 阶段总览

| 阶段 | 独立交付 | 主要依赖 | 单独验收入口 |
|---|---|---|---|
| **M2-a · 可见任务清单** | 模型可按需创建、更新、完成 todo，桌面端实时展示进度 | M1.5 事件流与工具分发 | scripted provider 驱动 todo 工具，重启回放后 UI/状态一致 |
| **M2-b · 文本检索与结果展开** | 可用 ripgrep 搜索仓库，并可按范围读取被截断的完整工具结果 | M1.5 文件网关、BlobStore | headless 在夹具仓库检索；截断结果可通过 blob 引用继续读取 |
| **M2-c · Checkpoint v2 与整组撤销** | 目录、大文件和一次变更涉及的多个目标可形成同一还原点并一键撤销 | M1.5 checkpoint/BlobStore | 文件、目录、删除、新建及受控 shell 改动均可恢复；失败不留下伪 checkpoint |
| **M2-d · 精确编辑与多文件事务** | 精确字符串替换、预览、应用、多文件冲突检测；无桌面 UI 也可完成编辑 | M2-b、M2-c | 对夹具仓库预览并应用批量修改；内容漂移时零文件被改动 |
| **M2-e · diff 审阅 UI** | 桌面端预览改动并逐块接受/拒绝，最终落盘结果与展示一致 | M2-d | renderer 组件测试 + IPC 集成测试 + 一次桌面人工验收 |
| **M2-f · 本地 Git 工作流** | status、diff、branch、commit 形成可用闭环，错误仓库/脏状态均显式报告 | M2-d；M2-e 只影响体验、不作硬依赖 | 临时仓库完成建分支、查看改动和提交，全程不访问网络 |
| **M2-g · 符号与全文索引** | tree-sitter 符号检索 + FTS5；索引未就绪时自动退回 M2-b 文本检索 | M2-b | 冷启动、增量更新、删除/重命名和 fallback 均在夹具仓库可复现 |
| **M2-h · 上下文预算与压缩** | ContextBuilder 执行 token 预算、75% 阈值分层压缩和稳定前缀复用 | M1.5 快照/事件流、Provider | 长会话在预算内继续；摘要只生成一次并可从事件重建，近期原文不丢 |
| **M2-i · 隔离子 Agent** | 主 Agent 可派生串行、受限的只读探索子 Agent，父会话只接收结论 | M2-b、M2-h | 独立 session/seq、取消、失败、预算及污点回传均有真实派生链路测试 |

依赖表示“复用已完成能力”，不表示必须把多个阶段合并实现。例如 M2-e 只消费 M2-d 已经可独立使用的编辑提案，不反过来改变 M2-d 的验收条件。

当前进度：**M2-a ✅、M2-b ✅ 已完成**；M2-c 至 M2-i 均未开始。

## 3. 各阶段范围

### M2-a · 可见任务清单

**做什么**

- 在现有 `Todo`、`todo.updated` 和 `SessionState.todos` 契约上落地模型可调用的 todo 工具。
- 支持整表写入或等价的创建、改序、状态更新；输入必须拒绝重复 id、非法状态等无效数据。
- 桌面端展示当前清单与完成进度；简单任务不强制生成 todo。
- 提示词只对明显的多步骤任务引导使用，不新增 Planner 状态机。

**不做什么**

- 不做任务依赖图、截止时间、后台调度或跨会话项目管理。
- 不让 renderer 维护第二份 todo 状态。

**完成判据**

- 工具调用落一条可回放事件，刷新和重启后得到同一清单。
- 两步以内的普通任务不因本阶段增加强制模型往返。
- 现有会话没有 todo 时，UI 不出现空面板噪音。

**验收证据（2026-08-12）**

- `todo.update` 已进入生产工具装配；真实 scripted provider 调用可写入 `todo.updated`，重开 `SessionRuntime` 后清单一致。
- 桌面端按 `SessionState.todos` 渲染完成数、进行中 `activeForm` 与各状态；空清单不渲染面板。
- 提示词只在工具实际可用时引导三步以上任务使用；配置禁用工具后，工具描述与引导同时消失。
- 新增 [ADR-0041](./adr/0041-M2-a可见任务清单与窄事件写入口.md)，保持 `ToolContext` 无通用事件写入口。
- 本地 `pnpm verify` 全绿：87 个测试文件通过、1 个按既有条件跳过；1056 个测试通过、21 个跳过；headless 构建产物已覆盖 todo 的调用、落库与重开放回放；体积 7.39 kB / 15 kB。

### M2-b · 文本检索与结果展开

**做什么**

- 集成 ripgrep，提供文本、glob、大小写、上下文行和结果上限等最小必要参数。
- 返回稳定的 `path:line:column` 位置，二进制文件、忽略规则和超量结果均显式说明。
- 落地 `result.expand`（最终命名以阶段 ADR 为准），按范围读取运行时截断后写入 BlobStore 的完整结果。
- 搜索继续经过工具注册、能力网关、策略与统一结果截断，不允许另开 I/O 旁路。

**不做什么**

- 不在本阶段引入 tree-sitter、FTS5、向量检索或常驻索引进程。
- 不重新实现一个内建正则引擎。

**完成判据**

- 在固定夹具上验证普通匹配、Unicode、空结果、忽略文件、超量截断和中断。
- 模型从截断标记取得 blob 引用后，能只展开所需范围而不是把全文重新塞回上下文。
- ripgrep 不可用时明确报告平台/安装问题，不静默返回“无匹配”。

**验收证据（2026-08-12）**

- `search.text` 通过现有路径网关声明 `fs.read`，以 argv 方式执行 ripgrep JSON；普通匹配、Unicode 列号、glob、大小写、上下文、空结果、ignore、二进制跳过、全局上限、中断和可执行文件缺失均有确定性用例。
- 统一截断标记携带完整 `blob:sha256:<hash>` 定位符；`result.expand` 只解析当前会话已持久化的 `tool.end.fullRef`，跨会话/不可达 hash 被拒绝，读取按行范围流式完成。
- 新增 [ADR-0042](./adr/0042-M2-b文本检索与会话内结果展开.md)，没有新增事件类型、文件 I/O 旁路、常驻索引或内建正则引擎。
- headless 构建产物在真实夹具仓库完成 `search.text → 统一截断 → BlobStore → result.expand(95..97)`，随后重开事件库回放一致。
- 本地全量验收通过：89 个测试文件通过、1 个按既有条件跳过；1063 个测试通过、21 个跳过；kernel coverage 47 个文件、662 个测试通过；依赖边界与 headless/写租约 smoke 通过；体积 7.4 kB / 15 kB。

### M2-c · Checkpoint v2 与整组撤销

**做什么**

- 用一份 ADR 定义 checkpoint 集合、生命周期、状态事件、目录快照方式和 Blob 引用关系。
- 一次工具调用或一次编辑事务只生成一个逻辑还原点，覆盖新建、覆盖、删除、多文件和目录树。
- 补齐大文件的流式快照、受控 `shell.exec`/`shell.session.run` 已声明文件目标的快照，以及失败后的显式降级。
- 提供 checkpoint 列表、详情与一次性撤销入口；撤销本身也必须可审计。
- 只有在引用关系可证明后才做 Blob GC；不能按“看起来没用了”直接删 blob。

**不做什么**

- 不承诺恢复未声明目标的任意第三方进程副作用。
- 不把 checkpoint 当 Git 替代品，也不在本阶段做任意历史时间旅行。

**完成判据**

- 同一夹具分别覆盖文件、目录、大文件、新建、删除和多文件半途失败，撤销后字节级一致。
- 快照读取或落盘失败时，执行路径遵守 ADR-0040 的失败语义，不产生不可用的 `checkpoint.created`。
- 重启应用后仍能看到并执行尚有效的撤销；GC 不删除任何仍被事件或 checkpoint 引用的 blob。

### M2-d · 精确编辑与多文件事务

**做什么**

- 提供精确字符串替换，要求调用方给出旧文本和期望命中数；零命中、歧义命中一律失败。
- 支持一个请求内编辑多个文件；应用前完成所有路径解析、冲突检查和 checkpoint，任一前置条件失败时零文件落盘。
- 生成机器可消费的统一 diff，并提供“预览”和“应用”两条明确操作；headless runtime 不依赖桌面 UI。
- 用内容哈希或等价前置条件检测“预览后文件已变化”，禁止把旧 diff 套到新内容上。

**不做什么**

- 不做模糊猜测式 patch、内建 IDE、代码格式化器或 AST 重写框架。
- 不把多文件写循环伪装成事务；崩溃恢复语义必须由 M2-c 的还原点兜住。

**完成判据**

- 单文件、多文件、Unicode、换行符差异、重复匹配和内容漂移均有确定性测试。
- dry-run/预览绝不写盘；应用结果与预览 diff 完全一致。
- 第二个文件失败时，第一个文件不会以未记录、不可撤销的状态遗留。

### M2-e · diff 审阅 UI

**做什么**

- 桌面端显示文件列表、逐块 diff、上下文行和冲突状态，支持逐块接受/拒绝与整组操作。
- 最终提交前再次校验 M2-d 的内容前置条件；文件已漂移时停止并要求重新生成预览。
- diff 状态来源于持久事件/契约，renderer 只保存展开、滚动等瞬态视图状态。
- 先为 diff 做专用面板；通用插件渲染器注册表仍按当前路线图留在 M3，除非本阶段 ADR 明确改期。

**必须先定的决策**

- diff 确认是变更工作流，不是权限判定。阶段 ADR 必须说明它为什么不恢复 ADR-0039 已删除的 `ask` 路径。
- 明确模型自动应用与用户审阅的产品语义，不能靠 renderer 临时猜测。

**完成判据**

- 接受部分 hunk 后，磁盘内容与 UI 选中结果一致；拒绝全部时磁盘不变。
- renderer 刷新、切换会话和主进程重启不会把待审阅状态变成已应用状态。
- 大 diff 有有界渲染策略，不能把完整仓库 diff 一次塞进 DOM。

### M2-f · 本地 Git 工作流

**做什么**

- 提供只使用 argv 的 status、diff、创建/切换分支和 commit；所有 cwd、路径及参数经过现有命令主张和策略链。
- 用结构化结果区分“不是仓库”、冲突、空提交、钩子失败和命令中断。
- commit 前展示实际暂存/提交范围，默认不夹带未由当前任务产生的用户改动。

**不做什么**

- 本阶段不实现 `push`、凭据管理、PR 或远端仓库写入。
- 不执行拼接 shell 字符串，不绕过受控 argv 终端。

**完成判据**

- 临时仓库中可完成“查看状态 → 建分支 → 查看 diff → 提交”的完整闭环。
- 存在用户预先改动时，测试证明不会被默认一起提交。
- 所有测试使用本地临时仓库，不依赖公网或真实用户 Git 配置。

> **M2 关闭前的冲突项**：旧路线图写着“push 单独审批”，但 ADR-0039 已删除审批判定与审批 UI。`git.push` 开工前必须另写 ADR，在“不恢复第二套权限系统”的前提下重新定产品语义；未定案前保持不可用，不能在 M2-f 中顺手实现。

### M2-g · 符号与全文索引

**做什么**

- 按 docs/09 D3 的既有倾向采用“按需 + 后台增量”：索引未就绪时立即降级到 M2-b 的 ripgrep。
- tree-sitter 提供语言感知的符号定义与结构检索；FTS5 提供跨文件全文召回。
- 索引按规范化工作区身份隔离，处理修改、删除、重命名和忽略规则变化。
- 索引是可重建派生物，不进入事件真相，不污染用户仓库。

**不做什么**

- 不做向量数据库、语义 embedding、全磁盘预索引或记忆检索。
- 不因索引损坏阻断基本搜索。

**完成判据**

- 冷索引、增量更新、损坏重建、取消和 fallback 都有确定性夹具测试。
- 同一查询在索引完成前后可能排序不同，但不能遗漏精确文本 fallback 能找到的结果。
- 三平台要么使用同一解析能力，要么明确声明语言/平台降级，不做假成功。

### M2-h · 上下文预算与压缩

**做什么**

- 引入唯一的 ContextBuilder，统一构建 Provider 请求；`turn.ts` 不再直接拼完整会话消息。
- 实现 ADR-0006：稳定前缀、长期预留位、中期摘要、近期原文、当前消息，以及 75% 压缩阈值。
- 摘要由主模型生成一次并持久复用，显式保留未解决问题、用户约束和已做决定。
- 记录预算决策与摘要来源，使请求可解释、可回放；prompt-cache 前缀必须字节稳定。

**不做什么**

- 不做长期记忆、技能正文加载、embedding 或多 Provider 角色路由。
- 不修改原始事件流；摘要只是模型上下文投影。

**完成判据**

- scripted provider 下构造超过上下文上限的长会话，证明请求始终落在预算内且最近轮次原文保留。
- 同一历史区间不会每轮重复摘要；删除可重建缓存后能从事件重新生成。
- 工具动态可用性变化不会破坏已声明稳定的 prompt-cache 前缀。

### M2-i · 隔离子 Agent

**做什么**

- 提供主循环按需派生子 Agent 的能力；子 Agent 使用独立 `sessionId`、独立 seq 和隔离上下文，只向父会话返回结论。
- M2 首版限定为**串行、有限轮数、只读探索**；权限只能比父 Agent 更窄，不开放写文件、Git 写操作、任意第三方代码执行或后台无人值守。
- 在真实派生路径中实现 ADR-0033：`subagent.end` 把子会话粘性 `untrustedContext` 并回父会话，然后删除现有失败关闭闸门。
- 取消、超时、Provider 失败与应用重启都产生完整生命周期结果，不能留下父会话永久等待。

**不做什么**

- 不做并行子 Agent、递归无界派生、模型自动选型或子 Agent 之间通信。
- 不把子 Agent 做成 Planner 阶段，也不回传完整子上下文。
- 不把 M4 的受限执行器/OS 沙箱提前塞进本阶段。并行、插件、MCP、无人值守或第三方代码执行仍受 ADR-0040 前置条件阻挡。

**完成判据**

- 真实派生链路证明父子 session/seq 隔离、只回传结论、父级取消可贯穿到子级。
- 子 Agent 读取网页后，父会话在 `subagent.end` 后确实带上同一粘性污点；移除合并逻辑时反向演练必须转红。
- 越权工具不会出现在子 Agent 描述符中；即使手工构造调用也会在分发/策略边界失败。

## 4. 顺序与暂停点

实施顺序固定为：

```text
M2-a → M2-b → M2-c → M2-d → M2-e → M2-f → M2-g → M2-h → M2-i → M2 总验收
```

以下情况必须暂停当前阶段，先补 ADR 或请用户定方向：

- M2-c 无法证明目录/大文件快照与 Blob GC 的引用安全。
- M2-e 需要恢复通用权限审批才能工作。
- M2-f 试图加入任何远端写操作。
- M2-g 的 tree-sitter 依赖改变三平台发布/原生模块策略。
- M2-h 的稳定前缀与现有工具动态过滤无法同时成立。
- M2-i 需要并行、写能力、第三方代码执行或无人值守才能达到预期。

## 5. M2 总验收

所有阶段完成后才执行里程碑总验收：

1. 建立 `docs/experience/m2/测试方案.md`，覆盖搜索、编辑、diff、撤销、Git、长上下文和子 Agent 的组合场景。
2. 用当时已经完成的 M2 版本，在 mingAgent 仓库内完成一个**不属于 M2 实现本身**的真实、小而完整的功能开发：理解需求、检索代码、维护 todo、修改多个文件、审阅 diff、运行测试、提交本地分支。
3. 人只负责给出目标、观察与最终审阅，不用外部编辑器代替小明改代码；全过程保留 trace、checkpoint、diff 和 Git 证据。
4. 当次 `pnpm verify` 全绿；远端 Windows/Linux/macOS CI 全绿后，才宣称三平台 M2 验收完成。
5. 将结果与真实失败写入 `docs/experience/m2/体验报告.md`；失败修复同步进入 `evals/regression/`。

M2 总验收不是继续补功能的阶段。若组合验收暴露缺陷，回到对应的 M2-x 阶段修复并重跑该阶段验收，再重新执行总验收。

## 6. 明确不属于 M2

- MCP、插件宿主、Skill、多 Provider 管理、正式 CLI 与通用插件渲染器注册表（M3）。
- 浏览器自动化、Computer Use、并行/后台 Agent、受限执行器或 OS 沙箱、定时任务（M4；但 ADR-0040 指定的高风险能力必须等沙箱完成后才能开放）。
- 长期记忆、向量检索、技能提炼与评测看板（按当前路线图归 M5，不采用 `docs/07` 中早期的 M2 标注）。
- 模糊代码生成式 patch、内建代码编辑器、远端 Git 发布和 PR 工作流。
