# M3.5 阶段划分 · 桌面端界面与设置

- **状态**：M3.5-a 已完成（2026-08-16），b～f 待做
- **日期**：2026-08-16
- **总纲**：[12-桌面端界面与设置](./12-桌面端界面与设置.md)
- **前置**：M3 已收官（`docs/experience/m3/`）

> 每段**独立可用、独立验收**，不跨段堆半成品。这是 M2/M3 两次都守住的纪律，本次不例外。
> 每段结束时 `pnpm verify` 必须全绿，桌面端 `pnpm --filter @xm/desktop build` 三段产物必须能出。

---

## 段与依赖

```
a 设计 token 换轨 ──┬── b 布局骨架（两栏让位链）──┬── d 右栏：详情 + 工作区
                    │                              │
                    └── c 对话流重制 ──────────────┘
                                                   │
                                    e 设置中心 ─────┴── f 上下文占用环 + 收官
```

- **a 是所有段的前置**：token 不换完，后面每段都要写两遍样式。
- **b 与 c 可并行**（一个动壳、一个动流），但都依赖 a。
- **d 依赖 b（栏位）与 c（工具行可选中）**。
- **e 只依赖 a**，与 b/c/d 无耦合 —— 如果中途要停，**e 是最值得先落地的一段**（§收益里那 7 个字段）。
- **f 是唯一越出渲染层的一段**，放最后，可单独砍掉而不影响其余。

## ~~M3.5-a · 设计 token 换轨~~ ✅ 已于 2026-08-16 完成 → [ADR-0073](./adr/0073-设计语言换轨与三层token.md)

**只改 `styles.css` + `lib/cn.ts` + 一条新闸门。原则上不改任何组件文件。**

> **落地结果**：`lib/cn.ts` **一个字都没改**——别名的名字全部沿用旧的一套，
> 换的只是它们指向什么（ADR-0073 §决策一）。实际改动是
> `styles.css`（+254/−69）、新增 `scripts/check-design-tokens.mjs`、CI lint job 加一步。
> `components/` 目录零改动。

**做什么**

1. 三层 token 落地（总纲 §4.1）：调色板层住 `:root` 普通变量、语义别名层进 `@theme`、
   组件层由组件自己声明。
2. 亮暗分层反转（总纲 §1.1）：亮色四层同为纯白、层次靠四档描边 alpha；
   暗色逐层提亮、描边换白色 alpha。
3. 强调色换冷调蓝，四个别名集中一处（总纲 §4.2）。
4. 主题三档：`@media (prefers-color-scheme: dark)` 写成 `:root:not([data-theme='light'])`，
   另加 `:root[data-theme='dark']`（总纲 §4.3）。**本段只做 CSS 侧，开关 UI 在 e 段。**
5. 滚动条 thumb 按表面层级重绑（深浅两档）。
6. 新增 `scripts/check-design-tokens.mjs`，进 `pnpm verify`。

**验收**

- ✅ 组件文件**零改动**（`git diff --stat` 里 `components/` 为空），整个应用换色成立。
  改到组件说明有硬编码色值漏在别处——那正是本段要清的。
- ✅ `pnpm check:design-tokens` 进 `pnpm verify`，也进 CI 的 lint job（纯文本扫描，不需要构建产物）。
- ✅ 渲染层真编译通过，产物里 `bg-surface` / `bg-canvas` / `text-muted` / `shadow-pop` 等
  工具类逐个存在，两处深色块与调色板层都在 `:root` 上。
- 📌 **待补**：亮/深两档的实机截图，需要在有 GUI 的机器上跑 `pnpm --filter @xm/desktop dev`
  后补进 `docs/experience/m3.5/`。**这一条没有做，不是做了没记**——
  当前环境没有桌面会话，`electron` 起不来。

**反向演练（六条，逐条先看它红一次）** —— 2026-08-16 实测，全部红过：

| # | 构造 | 实际报错 |
|---|---|---|
| 1 | 组件里写 `text-[#ff0000]` | `ui.tsx：出现字面色值 #ff0000` |
| 2 | 组件里写 `text-[var(--p-blue-500)]` | `ui.tsx：出现调色板层 --p-b` |
| 3 | 组件里写 `text-white`（清零后静默失效的那一档） | `ui.tsx：出现Tailwind 自带色 text-white` |
| 4 | 往 `@theme` 加 `--color-success`、不改 `cn.ts` | `lib/cn.ts 的 color 表缺少：success` |
| 5 | 跟随系统的深色块退回裸 `:root` | `选择器是 ':root'，缺少 :not([data-theme='light'])——系统深色下用户手动选浅色会失效` |
| 6 | 把两处深色定义改得不一致 | `两处深色定义不一致——跟随系统与手动选择必须给出同一套颜色` |

第 3 条是原计划里没有的：清零命名空间之后 `text-white` **不报错、只是什么也不生成**，
这是一次静默失效，写闸门时顺手补上。
第 5、6 两条针对的是**本段自己引入的**重复（深色写两份）——
新增一个靠自觉的点，必须同批给它配一把锁。

> 主题手动切换的验证仍是手动的（devtools 里改 `document.documentElement.dataset.theme`）：
> CSS 的实际效果没法在 vitest 里断言。**能机械化的那一半已经机械化**——
> 闸门检查的是选择器写法本身，而那正是这条会失效的唯一原因。

**不做**：任何布局、任何组件结构、任何设置项。

## M3.5-b · 布局骨架：两栏让位链

**做什么**

1. `renderer/lib/columns.ts`：纯函数 `computeColumns(viewport, details)`，
   常量 `CENTER_MIN=640` / `DETAILS_MIN=300` / `DETAILS_MAX=520` / `DETAILS_DEFAULT=360`。
   让位顺序按总纲 §5.2 的三步，**自动关闭绝不回写偏好**。
2. 右栏可拖拽：8px 命中带 + 12×32 药丸把手，hover 才显形；拖拽期间关列宽过渡。
3. 右栏关闭 = 零宽但**保持挂载**；`[data-details-collapsed]` 去掉左边框。
4. 宽度 / 开关偏好存 `localStorage`（总纲 §5.3 的判据）。
5. 顶栏 tab 选中态换成 2px 底部指示条（形态不变，见总纲 §5.1）。

**验收**

- `columns.ts` 的单测覆盖三步让位链的每个分支与边界。
- 手动：拖窄到详情栏自动收起 → 拉宽 → **详情栏自己回来且宽度是拖拽前那个值**。
- 顶栏 tabs 的会话切换行为一字不改（ADR-0037 的既有用例仍绿）。

**反向演练**

1. 去掉 `CENTER_MIN` 下限 → 用例红。
2. 让自动关闭回写偏好宽度 → "拉宽后自己回来"的用例红。

**不做**：右栏**内容**（还是现在的工作区四块），对话流。

## M3.5-c · 对话流重制

本段是**视觉与信息密度的主体**，也是最容易做超范围的一段——只做下面六条。

**做什么**

1. 共享宽度轴：`--xm-chat-content-width` 等三个变量替掉 `lib/layout.ts` 的 `COLUMN` 常量；
   输入卡 = 正文 + 32，正文两侧 = clearance + 16。
2. hero → docked：会话空态时输入卡居中，发出第一条后位移贴底。
   **拆开现在被合并的 `HomeView` 与"会话空态"**（总纲 §6.1）。**不做背景光晕。**
3. 输入区进滚动容器、`sticky bottom:0` + 36px **像素**渐变遮罩；`scrollbar-gutter` 从
   `both-edges` 收成单侧。
4. **工具调用压成 24px 单行**（总纲 §6.3）：收起态是行，展开态才是四种卡片种类。
   点行 = 选中（本段先只写选中状态，右栏在 d 段接）；点箭头 = 就地展开。
   运行中用 300px 扫光带，不用 spinner。
5. 回合状态 shimmer + 等宽数字计时；回合结束一行居中统计（tokens / 用时 / 花费，
   数据来自已有的 `usage` + `costUsd`，**区分"未知"与 0**）。
6. 回到底部：零高度 sticky 槽 + 34px 圆钮，`margin-top:-34px` 不撑高 scrollHeight。

**验收**

- 同一段真实会话（含 10+ 次工具调用）改前改后各截一屏：**一屏可见的工具调用数**记进体验文档。
- ADR-0058 的四种卡片种类渲染用例全绿；**渲染层仍不认识任何具体工具**
  （M3-f 的检查项不得倒退）。
- `prefers-reduced-motion` 下 shimmer 与扫光带静止。
- 滚动到底 → 新消息自动贴底；手动上滚 → 不再抢滚动，回到底部按钮出现。

**反向演练**

1. 把回到底部按钮改成有高度（去掉 `margin-top:-34px`）→ "贴底判定"的用例红。
2. 渐变遮罩改用百分比 → 输入框长高时正文被糊掉的截图对照（人工，进体验文档）。

**不做**：右栏内容、设置、上下文环。

## M3.5-d · 右栏：详情 + 工作区

**做什么**

1. 右栏顶部两个 tab：**详情** / **工作区**；点工具行自动切到详情。
2. 详情内容：`Input`（入参 JSON，格式化）+ `Output`（结果），代码段 r12 / pad16 / mono 13-22。
   材料**由 `callId` 从已落库事件流反查**，与 ADR-0065 同一条路，不新增数据源。
3. **Code Mode 子调用可选中**：`run_code` 展开后每条 `tool.code.dispatch` 是一行、可点。
   详情的 `Output` 段对子调用只显示"已执行 / 失败原因"，**并写明结果正文本就未落库**
   （ADR-0072），不留"数据缺失"的误读。
4. 工作区 tab 收纳现有的 todo / 运行中调用 / 终端 / checkpoint 四块。

**验收**

- 点任一工具行 → 右栏显示该次调用的入参与结果；点 `run_code` 的子调用行 → 同样能开。
- 关闭右栏再打开，**滚动位置与展开状态保留**。
- 无选中时右栏落在工作区 tab；现有工作区四块功能一字不改。

**反向演练**

1. 详情栏关闭时改成 `unmount` → "保住滚动位置"的用例红。
2. 给 `tool.code.dispatch` 的详情硬编一个结果正文 → 应该拿不到（payload 里没有）；
   这一条是**确认设计**而非确认 bug，结论记进体验文档。

**不做**：设置、上下文环。

## M3.5-e · 设置中心

**最独立的一段。如果中途要停，这段是最值得先落地的。**

**前置（本段第一件事）**：处置 `logging.level` / `logging.redact` 两个死配置
（总纲 §9.1）—— 删 schema 字段、写 ADR-0076、确认加载器对旧 `config.json` 里
残留的未知字段行为明确（容忍还是报错，ADR 里写死）。

**做什么**

1. 形态换成**模态 + 左导航分节**，Esc / 遮罩关闭，焦点管理到位；
   `shellView === 'security'` 这个第三主视图退役（总纲 §8.1）。
2. 六节按总纲 §8.2 的表落地。新增的 `SettingsResult` / `UpdateSettingsRequest` 字段
   走 `@xm/contracts` 与 `shared/ipc.ts` 的既有校验姿势，**两侧都校验、不静默兜底**。
3. **`tools.presentation` 三档开关** —— M3-h 的能力第一次有入口。
   文案要写清 `code` 模式下模型看不到别的工具（ADR-0072 §二）。
4. **权限：只提供"新增拒绝规则"**，**`allow` 由主进程拒绝**，不是靠 UI 不显示。
   红线只读展示，且要**新开一条 `{ target, capabilities, why }` 的只读投影**——
   现在 `StatusResult.security.protectedResources` 是硬编码的四行中文概述，
   不是规则本身，拿它当清单显示等于给用户一段对不上任何一次拒绝的散文（总纲 §8.2）。
5. 模型与 Provider 三个角色 + Provider 列表 + 价目表；
   **API Key 走 `ui.setApiKey` → `SecretStore`**，不回显、无读回通道。
6. 主题三档与 Enter 行为两个 `localStorage` 偏好的开关 UI。

**验收**

- `config.json` 可从 UI 改的叶子字段 **3 → 10**，逐个改一次并确认落盘 + 生效。
- 换模型不需要重启（或明确标注哪些改动需要重开会话——**要标，不要装作不需要**）。
- 保存 API key 后 `config.json` 里搜不到它；`hasApiKey` 变 true。

**反向演练**

1. 从渲染层直接调 IPC 提交一条 `effect: 'allow'` 的规则 → **主进程**拒绝。
2. 从渲染层把 key 塞进 `UpdateSettingsRequest` → 主进程拒绝。
3. 提交一条会破坏 schema 的设置（如 `workspace.mode: 'nope'`）→ 两侧都拒绝且有可读错误。

**不做**：MCP / Skill / 插件相关的任何设置（那是 M4，本段不预留空节 ——
空节会让人以为功能已经在了）。

## M3.5-f · 上下文占用环 + 收官

**唯一越出渲染层的一段，可单独砍。**

**做什么**

1. `@xm/runtime` 的 `ContextBuilder` 在组装完请求后产出一份上下文占用投影
   （系统提示词 / 工具 schema / 对话 三段 + 路由容量），**随事件同行的纯函数投影**，
   与卡片投影同一姿势：**不落库、不参与 `reduce()`、不进模型请求**。
2. 渲染层：发送键旁 14px 环，点开三段分解。
3. 收官记录 `docs/experience/m3.5/收官记录.md`：改前改后对照、每条反向演练的红色证据、
   一屏可见工具调用数、可改配置字段数。
4. 同步 `docs/04` / `docs/06` / `docs/10` / `docs/README.md` / `CLAUDE.md`。

**验收**

- 环的读数与一次真实回合的 `usage` 对得上量级（估算允许偏差，但**偏差方向要一致**，
  不能一会儿高估一会儿低估）。
- 全量门禁：`pnpm verify` + 桌面三段构建 + headless 冒烟数字**一条不变**
  （本次不动事件流，数字变了就是改错了）。

**反向演练**

1. 把占用投影塞进事件流 → 不变量注册表 / `sample-events` 闸门必须有反应；
   如果没有反应，说明这条约束在写入路径上没有护栏，**当场补一条**。

## 全程不变的东西（每段结束都要确认）

1. **状态 = `reduce(events)`**，渲染层不维护第二份 `messages`（ADR-0015 / ADR-0021）。
   `localStorage` 只放 UI 偏好，判据见总纲 §5.3。
2. **渲染层零 Node 权限**：`contextIsolation` / `nodeIntegration:false` / `sandbox` 三个开关不动；
   preload 不新增通用入口，设置中心的每个写操作都是**具名 IPC**。
3. **契约单一来源**：新增的设置字段一律走 `@xm/contracts` 的 Zod schema，两侧都校验。
4. **渲染层不认识任何具体工具**（M3-f）：单行工具的图标与摘要只能来自既有卡片投影。
5. **权限只有 allow / deny**（ADR-0039）：设置页不得以任何形式重新引入"问用户"。
6. **依赖方向一字不改**：本次不新建包，`.dependency-cruiser.cjs` 不加规则也不改规则。
