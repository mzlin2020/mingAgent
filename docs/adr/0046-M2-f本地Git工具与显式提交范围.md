# ADR-0046 · M2-f 本地 Git 工具与显式提交范围

- **状态**：Accepted
- **日期**：2026-08-13
- **相关**：[ADR-0026](./0026-命令的主张分解与argv契约.md)、[ADR-0039](./0039-放弃审批模式.md)、[M2 阶段划分](../M2-阶段划分.md)

## 背景

M2-f 要提供可由模型稳定调用的本地 Git 闭环。直接复用通用 `shell.exec` 虽然能运行 Git，
却无法保证子命令范围、结构化区分仓库错误，也无法默认排除用户在任务开始前已经暂存或修改的
其它文件。另一方面，另写一套 `spawn` 旁路会跳过现有 argv 分析、命令主张和策略链。

## 决策

### 1. 四个窄工具仍以 argv 作为判权与执行的唯一命令值

新增 `git.status`、`git.diff`、`git.branch`、`git.commit`。入参中的命令必须是字符串数组，
网关先按 ADR-0026 分析同一份 argv，再把同一对象交给执行；实现一律
`spawn(bin, args, { shell: false })`。每个工具只接受自己的固定子命令和有限参数形状，任何
`push`、`fetch`、远端参数、shell 字符串或未列出的选项都在执行前拒绝。

只读工具声明 `shell.exec`；分支和提交同时声明 `shell.exec` 与 `git.write`。命令网关必须为
工具声明的每项能力保留主张，不能因 `git.write` 的 target 是 opaque 而漏掉它。

`git.diff` 还必须同时带 `--no-ext-diff`、`--no-textconv` 与 `--no-color`；所有 Git 子进程
通过进程级配置覆盖关闭 `core.fsmonitor`。这是因为仓库配置与 `.gitattributes` 可以把
看似只读的 status/diff 变成外部 helper 或 hook 执行，不能把“本地仓库可信”当作前提。

### 2. commit 必须显式列出路径，使用 Git 的 `--only` 语义

`git.commit` 只接受 `git commit --only -m <message> -- <path...>`。执行前以
`git diff --name-status HEAD -- <path...>` 展示实际范围；范围为空则返回 `empty_commit`。
Git 的 path-only commit 忽略其它已暂存内容，因此用户在其它路径上的既有修改或暂存不会被
默认夹带，提交后仍留在工作区/索引。调用方若确实要提交多个文件，必须逐一列出。

同一路径内“任务改动”和更早的用户改动无法仅凭 Git 工作树可靠拆分，本阶段不伪装能做到
hunk provenance；这种情况应先通过 M2-e 精确选择形成目标内容，再显式提交该路径。

### 3. 结果是稳定分类，不靠模型猜 stderr

所有工具返回 JSON 文本信封，至少包含 `ok`、`kind`、`argv`、`cwd`、`stdout`、`stderr`。
失败稳定区分 `not_repository`、`conflict`、`empty_commit`、`hook_failed`、`interrupted` 与
`command_failed`。commit 临时开启 Git Trace2；若失败轨迹中存在非零 hook 子进程，则分类为
`hook_failed`，而不是用某一句本地化 stderr 猜测。

### 4. 本阶段严格本地

不提供 `git.push`，也不接受会访问远端的子命令。测试只创建临时本地仓库并在仓库内配置测试
身份，不读取或修改用户全局 Git 配置。Git 命令禁用终端提示和可选索引锁，避免后台等待凭据
或只读 status 悄悄刷新索引。

## 后果

- 正面：常用 Git 闭环有稳定契约和错误分类，同时继续复用统一策略链。
- 正面：显式 path-only commit 在默认情形下不夹带其它文件的用户改动或已有暂存。
- 代价：工具不接受任意 Git 选项；超出窄工作流的命令仍需通用 shell 工具并承担相应风险。
- 代价：同文件混合来源不做虚假的自动拆分，调用方必须先在 diff 审阅阶段收窄内容。

## 补记（2026-08-13，M2 复审）：三处实现与本文决策不符

本文的决策没有改，改的是三处**实现与决策不符**的地方。

**一、失败回滚曾经裸写 `.git/index`。** commit 前把整份 index 读成字节，失败时原样写回。
写入不原子（没有 temp+rename）、不持 `index.lock`，而且会把这期间**任何人**对索引的改动
一起抹掉：用户在终端里 `git add` 的东西、钩子里 formatter 补的 `git add`，都会无声消失。
小明跑在用户桌面上、用户同时开着终端和 IDE，这不是理论风险。那次写入还完全绕开了策略链
与 checkpoint，写的是 `.git/` 下的文件。

现在只撤销**自己建的那几条** intent-to-add 条目：对本次 `git ls-files --others` 列出的
那批文件执行 `git rm --cached --force --ignore-unmatch`，走 git 自己的加锁，不碰别的条目。
第 2 节"不夹带其它路径的用户改动"这个承诺没变，只是兑现方式从"整份覆盖"换成了"精确撤销"。

**二、Trace2 临时目录建在用户仓库的 `.git/` 里。** 进程崩在 commit 中间就留下
`xm-git-trace-*`。现在由装配方给 `GitToolsOptions.tempDir`（桌面端用应用自己的 cache
目录，不是世界可写的系统临时目录）。没用 `os.tmpdir()` 是因为 ADR-0007 不让业务代码碰
`node:os`——那条 lint 规则这次正确地拦了一次。

**三、`not_repository` 靠英文 stderr 子串判定，而 LANG / LC_ALL 是透传给子进程的。**
装了中文 git 的机器上那句话是中文的，分类会悄悄退化成 `command_failed`。第 3 节专门批评过
"用某一句本地化 stderr 猜测"，结果自己在这条上犯了。现在给所有 Git 子进程固定
`LC_ALL=C` / `LANG=C`，先把判据钉稳。

顺带：`failedHook()` 的 `JSON.parse` 改为逐行容错——半截 trace 行（进程被杀、缓冲没刷完）
只该让分类退回通用失败，不该把整次 commit 打挂。
