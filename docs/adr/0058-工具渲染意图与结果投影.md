# ADR-0058 · 工具渲染意图与结果投影

- **状态**：🟢 Accepted
- **日期**：2026-08-14
- **相关**：[ADR-0021](./0021-流式渲染与第二份状态的边界.md) · [ADR-0045](./0045-M2-e-diff审阅不是权限审批.md) · [ADR-0050](./0050-编辑diff的行级hunk与提案投影.md) · [ADR-0055](./0055-Turn驱动器的扩展点契约.md) · [docs/05 §6](../05-可插拔与扩展体系.md)

## 背景

`packages/contracts/src/tool/display.ts` 里的 `DisplayHint` 从 M0 就存在，注释写得很清楚：

> 参考项目 2.14 的教训：展示信息在编排层按工具名 if-else 填充，每加一个工具都要改内核。
> 这里反过来——工具自报 renderer ID，编排层完全不认识具体工具。

**但它至今零个生产者、零个消费者。** 全仓库搜 `display:` 在工具实现里一个匹配都没有，
渲染层也没有任何渲染器注册表。这是本仓库第四次出现"契约写好了、没有任何调用点"
（前三次由 M1-c 的第一个真实文件工具一次引爆，记在 `docs/08`）。

与此同时，真实需求已经绕过它长出了专用通道：M2-e 的 diff 审阅走
`apps/desktop/src/main/edit-review.ts` + 渲染层专门的组件 + IPC 上的专门方法。
它工作得很好，但**它是"加一个工具改三处 UI"的第一个实例**，而 `docs/05` 承诺的正是
"新增工具不需要改 UI 代码"。

再看 `DisplayHint` 本身，它还有两个设计问题，现在补实现正好一起修：

1. **只有结果态，没有调用态。** 工具跑三十秒时 UI 该显示什么？`DisplayHint` 在结果里，
   那时候还不存在。
2. **payload 全量落库。** `data: unknown` 会把渲染需要的一切塞进持久事件，
   而 ADR-0050 刚刚因为"整文件对倒"把模型可见结果收窄过一次——展示数据同样会膨胀。

## 选项

### 选项 A：继续走专用通道，每个需要富展示的工具在 UI 里加一支

优点：直接，M2-e 已验证可行。
缺点：`docs/05` 的承诺永远兑现不了；三方插件贡献的工具必然白屏，
而这是发布前测不到的组合。

### 选项 B：补齐 `DisplayHint` 的生产与消费，形状不改

优点：契约不动。
缺点：上面两个设计问题原样保留。挂起态没有卡片，展示数据继续膨胀。

### 选项 C：升级为"两个纯函数投影 + 一份最小落库事实"

## 决策

**选择 C。** `DisplayHint` 被下面三件套取代（它的降级语义保留）：

| 成员 | 什么时候跑 | 落不落库 |
|---|---|---|
| `presentCall(args)` | 工具调用一开始，出**挂起卡片** | 不落 |
| `presentResult(args, result)` | 结果就绪，出**完成卡片** | 不落 |
| `presentationMeta(args, value)` | 结果就绪，投影出**回放需要的最小事实** | 落在 `tool.end` 上 |

### 一、卡片种类（先做四种）

| 卡片 | 用途 | 谁在用 |
|---|---|---|
| `generic` | 默认。标题 + 原始入参 + 可选内容 + `locations`（文件路径与行号，编辑器可跳转） | 大多数工具 |
| `terminal` | 这次调用就是一条命令 | `shell.exec`、受控终端 |
| `diff` | 这次调用会创建或修改文件。`diffs: [{ path, oldText, newText }]`，`oldText: null` 表示新建 | `fs.write`、`edit.apply` |
| `search` | 发现类结果：按文件分组的匹配，或一个扁平路径列表，带 `truncated` / `total` | `search.text`、索引检索 |

无匹配渲染器时降级为通用卡片 + 一行摘要——`DisplayHint.summary` 那条降级要求原样继承，
理由也一样：三方工具让 UI 白屏是我们发布前测不到的组合。

`search` 只有结果卡片、没有调用卡片：匹配只在 `execute` 之后才存在，
调用态老实显示通用卡片就好。这条看着琐碎，但它是"卡片必须是它已知信息的诚实投影"
这条原则的一个具体落点。

### 二、纯函数是硬约束

`presentCall` / `presentResult` **在实时流与日志回放两条路上都要跑**，因此必须是
`args`（+ `result`）的纯函数：

- 禁 I/O、禁读会话状态、禁时钟、禁随机。
- 需要"结果时刻才知道的事实"（例如 `edit.apply` 实际落了哪几个 hunk），
  走 `presentationMeta` 落库，回放时从库里读，**不是**在投影函数里现算。
- `fs.write` 的调用态卡片用 `oldText: null`——调用时刻的投影函数**没有**旧文件内容，
  想拿就说明这件事该由适配层或落库元数据提供，不该由投影函数去读盘。

这条约束与 ADR-0021 是同一条不变量的两面：不允许存在第二份、会漂移的状态。
一个会读盘的 `presentCall` 就是第二份状态——它在实时流里读到 A，在三天后的回放里读到 B。

### 三、畸形输入必须降级，不许崩

历史事件里可能有旧版本参数、或被截断的畸形参数。投影函数遇到它们**返回"没有卡片"
而不是抛异常**——展示路径永远不该让回放崩掉。这条在参考实现里叫
"defineTool soft-validates the display path"，对小明同样成立，且更重要：
小明的整个 UI 就是 `reduce(events)` 的投影，回放崩了等于会话打不开。

### 四、`edit-review` 专用通道退役

M2-e 的 diff 审阅改为：`edit.preview` 工具产出 `diff` 卡片，逐块接受/拒绝仍走
ADR-0045 的"选择生成收窄提案 + 复用完整 apply 分发路径"——**权限语义一个字不改**，
变的只是这块 UI 从"渲染层认识 edit 工具"变成"渲染层认识 diff 卡片"。

> **2026-08-14 补正**：本 ADR 的三件套**全是只出不进的数据投影**，
> 它只能退役"展示"那一半。逐块接受/拒绝需要一条反方向的路
> （卡片上的点击 → 主进程 → 完整权限链），而那条路本 ADR 没有定义。
> 它由 [ADR-0065](./0065-卡片动作通道.md) 补上。**两半都完成，
> `main/edit-review.ts` 才可以删**；只做完展示就宣布退役，
> 等于把一条还在用的通道从文档里抹掉。

### 五、渲染器注册表

`ui.registerRenderer(cardKind, Renderer)`，插件可为**已有的四种卡片**贡献渲染器。
渲染层零 Node 权限的三个开关（`contextIsolation` / `nodeIntegration:false` / `sandbox`）
一个不动；渲染器是纯组件，拿到的是已经过 Zod 校验的卡片数据。

> **2026-08-14 更正**：初稿这里写的是"插件可贡献**新卡片种类**"，与本 ADR 后果段
> "四种卡片是一个闭集、加卡片种类比加工具贵"以及 `docs/10 §9.5.3` 的"卡片种类闭集"
> 直接冲突。以**闭集**为准：种类只有四种，插件能注册的是这四种的**渲染器**。
> 第五种种类需要新 ADR 并同批更新渲染层——门槛高是有意的。

## 后果

- **正面**：新增工具（含 UI）不再触碰渲染层任何文件。这是新 M3 的 DoD 之一，
  也是 `docs/05` 挂了两个里程碑的承诺第一次可兑现。
- **正面**：`presentationMeta` 只落"回放需要的最小事实"，比 `DisplayHint.data` 全量落库省得多，
  与 ADR-0050 收窄模型可见结果是同一个方向。

- **负面**：工具作者要多想一件事——"我的卡片长什么样"。参考实现把这条写成
  "a tool's UI render intent is part of its design, decided up front"，小明照此要求。
  这确实提高了写工具的门槛。
- **负面**：四种卡片是一个闭集，第五种需求出现时要么塞进 `generic`，要么加一种并同批更新
  渲染层。**加卡片种类比加工具贵**，这是有意的——否则卡片种类会随工具数量线性增长，
  等于换个地方重演"每加一个工具改一处 UI"。

- **代价与缓解**：纯函数约束会让某些自然写法写不出来（想在卡片里显示相对路径就要知道 cwd）。
  缓解：这类上下文由 UI 适配层提供，不由工具提供——工具给绝对路径，适配层负责相对化。

- **必做的反向演练**：
  1. 在 `presentCall` 里读一次文件 → 回放测试必须红（实时与回放两次投影结果不一致）。
  2. 喂一条畸形/旧版参数的历史 `tool.end` 事件 → 必须降级为通用卡片，
     **绝不能让会话打不开**。这一条要拿真实旧库跑，不能只用构造的小夹具（`docs` 里
     "复审要用真实尺寸输入"的教训）。
  3. 注册一个只有 `presentResult`、没有对应渲染器的卡片种类 → 必须降级为摘要，不白屏。
  4. 删掉 `edit-review` 专用通道后，M2-e 的逐块接受/拒绝全套用例必须仍然全绿——
     权限语义没变，是这次改造的前提而不是结果。

- **重新评估条件**：如果第五、第六种卡片种类在半年内接连出现，说明这个闭集切错了维度，
  应当重新按"UI 能力"而不是"工具类型"划分（例如"可跳转位置""可展开长文本""可交互选择"）。
