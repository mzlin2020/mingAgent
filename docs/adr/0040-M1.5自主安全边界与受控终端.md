# ADR-0040 · M1.5 自主安全边界与受控终端

- **状态**：🟢 Accepted（2026-08-12）
- **Supersedes**：[ADR-0031](./0031-shell-session-pty.md) 中“原始 PTY 输入且打开后不再判权”的设计
- **细化**：[ADR-0039](./0039-放弃审批模式.md) 与 M1.5 收官基线

## 背景

小明是本地自主通用 Agent，不是只能操作工作区的编程助手，因此不引入默认工作区硬沙箱。但 Agent 不能修改自己用于判权、脱敏、保存密钥与审计的核心。原 PTY 允许任意字节输入已打开的 shell，命令主张、红线与 checkpoint 都失去载体。

## 决策

1. 权限仍只有 `allow | deny`，不恢复审批、永久授权或权限档位。
2. 模型可修改普通业务代码，但内建工具和可分析命令不可直接读写：应用数据、SQLite 边车文件、审计库、checkpoint/blob；用户配置与密钥；权限引擎、能力网关、密钥/脱敏、运行时判权入口、关键装配与 CI 护栏。
3. 项目级 `.xiaoming/config.json` 仍可修改，权限规则只能收紧。用户 UI 与内部存储适配器可管理配置、密钥和数据库。
4. 删除 `shell.session.write`。`shell.session.run` 只接受 `{ ptySessionId, argv, cwd?, timeoutMs? }`，直接启动程序与 argv，不经 shell，复用命令主张、路径解析、环境白名单、红线、checkpoint 和超时。单会话只有一个在途进程。
5. `shell.session.status` 只返回状态、退出码和有界输出尾部。不提供模型原始 stdin，不支持 REPL、vim 和全屏交互。命令开始/结束持久化；重启后不能重连的会话记为 `interrupted`。
6. checkpoint 分级：已存在文件的读取或 blob 写入失败时拒绝工具；目录与超大文件允许继续但明确告警，不伪造 `checkpoint.created`；仅 `ENOENT` 表示“原本不存在”。
7. 安全面板明示边界、工具可用性、PTY 模式、密钥后端、脱敏状态与配置问题，不展示密钥值。

## 限制

这是**策略边界**，不是 OS 沙箱。任意解释器、第三方程序或不可分析子进程仍可能绕过文件策略。在开放并行子 Agent、MCP、插件、无人值守自动化或第三方代码执行前，必须先有独立的受限执行器/OS 沙箱 ADR 与实现。
