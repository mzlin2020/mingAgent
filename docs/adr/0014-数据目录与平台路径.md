# ADR-0014 · 数据目录与平台路径：env-paths，以及审计红线的补写

- **状态**：🟢 Accepted（2026-08-05）
- **日期**：2026-08-05
- **相关**：修正 [docs/06 §7](../06-安全与权限模型.md) 写死的 `~/.xiaoming/`；落实 [ADR-0007](./0007-平台支持分级.md) 保险 1 与保险 4；补上 [ADR-0012](./0012-地基复审与安全边界修正.md) ① 同一类失效的第三个实例

## 背景

M0-b 第一件事是让存储落到磁盘上，于是必须先回答"落到哪"。而这个问题在文档里有两个互相冲突的答案：

- **docs/06 §7** 写死：审计库是 `~/.xiaoming/audit.db`，「小明自身的策略规则禁止写入该路径」
- **ADR-0007 保险 4** 要求：路径处理零假设，用 `env-paths` 解析配置目录

两者在 Linux 上勉强能对上，在 macOS 与 Windows 上则完全不同。这不是措辞问题——**红线规则保护的是运行时真实传入的那个字符串**，选错等于红线保护了一个不存在的路径。

### 开工前发现：那条红线根本不存在

真正促成这份 ADR 的，是在接线时发现的一件事：

> docs/06 §7 那句「小明自身的策略规则禁止写入该路径」，在 `packages/kernel/src/policy/defaults.ts` 里**没有任何对应实现**。

原因很具体：`PolicyEnv` 只有 `{ home, appRoot }`，拿不到数据目录，**写不出那条规则**。于是这条防护从写下的那天起就没生效过，而文档里它一直在。

这与 ADR-0012 ⑧ 记下的那三个"文档里存在、代码里不存在"的扩展点是同一种东西，也是这个项目第三次撞上「规则存在 ≠ 规则生效」。

## 决策

### 一、数据目录走 `env-paths` 的平台规范目录

| 平台 | 数据目录 |
|---|---|
| macOS | `~/Library/Application Support/xiaoming` |
| Windows | `%APPDATA%\xiaoming` |
| Linux | `~/.local/share/xiaoming`（config / cache / logs 各归其位） |

理由是**外部工具认这些目录**：系统备份、迁移助手、卸载清理、磁盘分析都按平台约定工作，塞进 `~/.xiaoming` 就全都绕过了。代价是路径不再是一句能背下来的常量——所以它必须只有一个来源。

`suffix: ''` 是必须的：`env-paths` 默认加 `-nodejs` 后缀，那对库合适、对一个用户会在 Finder 里看见的桌面应用不合适。

**回写 docs/06 §7**：审计库改为 `<data>/audit.db`。

### 二、路径只有一条通路，且是整份传的

```
PlatformPort.paths()  →  policyEnvFromPaths()  →  builtinRules()
```

`PolicyEnv` 增加**必填**的 `dataDir`（加上去那一次，三个调用点当场编译失败——那正是想要的效果）。`policyEnvFromPaths()` 是唯一的转换点：调用方只能整份 `XmPaths` 交过来，不能这里传解析出来的 data、那里手写一个 home。

存储侧对称：`xmDataLayout()` 是文件名的唯一定义，`openStores()` 是打开存储的唯一入口。**红线与适配器用的是同一份定义**——一边写 `audit.db`、另一边打开 `audit.sqlite`，红线就会安静地护住一个不存在的文件，而 lint、类型检查、depcruise 全都发现不了。

`resolvePaths()` 出来的每一条都过 `normalizedOrThrow`：分隔符统一成 `/`、盘符大写、无尾斜杠——与红线处在同一个坐标系。ADR-0012 ① 的失效就是"两边各算了一次"。

### 三、新增审计红线，且必须盖住 WAL 边车文件

```
red.audit-log-write   fs.write  <data>/audit.db*
red.audit-log-delete  fs.delete <data>/audit.db*
```

`audit.db*` 里的 `*` 不跨 `/`（内核那个极简 glob 的语义），正好只盖住 `-wal` / `-shm` / `-journal`。

**这个细节写错就等于没写**：WAL 模式下尚未 checkpoint 的审计记录全在 `audit.db-wal` 里，只护主文件的话，删掉 wal 就能抹掉最近一段审计——而主文件的大小与 mtime 纹丝不动，看起来一切正常。

它拦的是"模型让某个工具去动审计文件"。小明自己往审计库追加记录走的是存储适配器，不经过 PolicyEngine，不受影响。

### 四、`events.db` **不设**红线

按 `defaults.ts` 开头写下的挑选标准——红线只留「做了就回不来，且没有任何正当的自动化理由」——清空自己的会话数据是有正当用途的操作，它属于 `def.fs-delete` 的 ask 加还原点。

红线一多，用户就会去找绕过的办法，那才是真的全面失效。

### 五、`process.platform` 的白名单按**文件路径**开，不用行内 disable

`packages/platform/src/detect.ts` 是全仓库唯一允许读 `process.platform` 与 `node:os` 的文件，放行写在 `eslint.config.js` 里。

区别是扩散性：行内 `eslint-disable` 会跟着复制粘贴一路传染，路径白名单传染不了——多放行一个文件就要多改一次配置，那次改动在 review 里看得见，而且 `eslint.config.js` 本身被 `red.self-modify` 护着。

### 六、能力探测报"地板"，由外壳往上抬

`@xm/platform` 只声明纯 Node 交付得了的能力（托盘/通知/截屏全 false，密钥后端 `encrypted-file`）。`apps/desktop` 用 `withCapabilities()` 抬高。

反过来做（先乐观声明、由外壳往下修）的问题是：忘了修就是静默的谎报，而谎报能力的表现是工具出现在模型视野里、调用之后才失败。ADR-0007 保险 2 要的「退化时明确告知用户」，前提是没人乐观。

⚠️ 密钥后端的地板刻意是 `encrypted-file` 而不是 `plaintext-unavailable`：后者的含义是**必须拒绝存密钥**，而纯 Node 下口令加密文件这条路永远走得通，谎报成不可用会让 M1 的 SecretStore 在本来能干活的环境里罢工。

## 后果

**正面**

- docs/06 §7 那句承诺第一次有了实现，且有一组按"攻击者会怎么拼这个字符串"写的用例（`./audit.db`、`//audit.db`、`../xiaoming/audit.db`、`-wal`、相对路径、Windows 大小写）
- 路径失效模式在结构上被消掉：只有一个来源、整份传递、构造期就抛
- 反向演练固化成了用例：把 `dataDir` 传成 `~/.local/share/xiaoming`（ADR-0012 ① 的原样重放）现在连规则都建不出来

**负面**

- 三平台的数据目录各不相同，排查用户问题时要先问清平台。缓解：`PlatformPort.paths()` 的结果应该在"关于"面板里直接可见（M1）
- `PolicyEnv` 多一个必填参数，所有构造点都要改。这是刻意的代价

**重新评估的触发条件**

- 出现需要用户手工编辑的数据文件（那时可发现性比平台惯例更重要）
- 需要支持便携模式 / 多实例（那时要引入显式的目录覆盖，而红线必须跟着覆盖后的值走）

## 遗留

- **`XM_DATA_DIR` 之类的环境变量覆盖没有做。** 代码里有 `dataDir` 参数供测试与 headless 使用，但没有从环境读。真要加时必须同时演练"红线跟着覆盖后的值走"，否则又是一次两个坐标系。
- 配置目录（`config`）目前没人用，M1 的配置中心才会落地。

## 补记（2026-08-17，[ADR-0078](./0078-自改红线的锚点与受保护清单闸门.md)）

本 ADR 定下的 `appRoot`（"小明自身仓库/安装目录"）**是两义的**，而自改红线只吃一个值。
桌面端喂的是 `app.getAppPath()`，那是入口所在目录——开发时 `apps/desktop`、打包后
`resources/app.asar`，两者都不是源码树。整族自改红线因此锚在不存在的目录上，
而用例喂合成路径所以全绿（地基复审四 A1）。

ADR-0078 把它拆成三个各有各名字的字段：`sourceRoot`（源码树，由平台层从入口位置
往上找标记认出来）、`extraSourceRoots`（会话工作区里那份检出）、`installRoot`
（打包安装目录，整棵树）。`ResolvePathsOptions.appRoot` 同时改名为 `appPath`——
它表达的只是"入口在哪"。本 ADR 其余部分（env-paths、数据目录布局、红线必须与
`paths()` 同一次解析）不变。
