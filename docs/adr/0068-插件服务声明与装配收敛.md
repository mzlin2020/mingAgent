# ADR-0068 · 插件服务声明与装配收敛

- **状态**：🟢 Accepted
- **日期**：2026-08-14
- **相关**：[ADR-0052](./0052-插件容器与效果模型.md) · [ADR-0067](./0067-子Agent作用域的两级扁平语义.md)

## 背景

ADR-0052 要求插件用 `inject` 声明依赖，并要求装配收敛时对缺失服务、等待链和依赖环失败关闭。
但原始插件草案只有 `{ name, inject?, apply(ctx) }`：一个等待中的插件尚未执行，容器无法从
`apply()` 函数体知道它本来会提供哪个服务。因此“缺少提供者”和“A 等 B、B 等 A”在运行时
看起来完全相同，依赖环检测没有足够信息可做。

## 选项

### 选项 A：执行插件后观察它调用了哪些 `ctx.provide()`

能自动推断提供物，但插件在依赖未满足时本来就不该执行；强行试跑会产生半套效果和回滚问题。

### 选项 B：只报缺少服务，不区分等待链与依赖环

实现简单，但直接放弃 M3-a 已写明的环检测与指名等待链验收。

### 选项 C：插件显式声明 `provide`

插件形状扩展为 `{ name, inject?, provide?, apply(ctx) }`。`provide` 只描述装配图，实际值仍必须由
`apply()` 调用 `ctx.provide()` 注册，并由效果生命周期负责撤销。

## 决策

**选择 C。**

1. 插件凡调用 `ctx.provide('x', value)`，必须在 `provide` 中声明 `x`；未声明即拒绝。
2. `provide` 声明的服务在 `apply()` 完成后必须真实存在于插件目标作用域；漏提供即回滚插件效果。
3. 同一作用域内一个服务只能有一个提供者；fork 作用域可以显式覆盖根服务。
4. 容器按注册序做确定性的固定点装配：依赖满足的插件启动，直到不再有进展。
5. 收敛后仍等待时：没有任何声明提供者的服务报“缺少提供者”；形成闭环的报完整插件/服务链。
6. 容器宿主在装插件前直接提供的基线服务不需要插件元数据，但仍走同一效果撤销机制。

## 后果

- **正面**：装配图在插件执行前可知，缺失、冲突与环可以确定性诊断；M3-b 的接缝图也有真实来源。
- **正面**：声明与真实注册会互相校验，不会出现文档说提供了、运行时其实没有的静默漂移。
- **负面**：插件作者要同时写 `provide` 和 `ctx.provide()`，存在少量重复。
- **必做反向演练**：缺少提供者、A↔B 环、未声明提供、声明后漏提供、同层双提供均须失败并指名。
- **重新评估条件**：如果未来插件由静态清单生成代码，可由生成器同时产出 `provide` 与注册骨架，
  但运行时双向校验仍保留。
