# ADR-0044 · M2-d 精确编辑与多文件事务

- **状态**：Accepted
- **日期**：2026-08-12
- **Superseded by**：[ADR-0050](./0050-编辑diff的行级hunk与提案投影.md)（仅第 4 节的 diff 形状与第 1 节的模型可见投影；preview/apply 的分离、路径清单相等与写前全量校验仍然有效）
- **相关**：[ADR-0024](./0024-路径能力网关.md)、[ADR-0043](./0043-M2-c-Checkpoint-v2与整组撤销.md)、[M2 阶段划分](../M2-阶段划分.md)

## 背景

现有 `fs.write` 只能整文件覆盖。模型若想改一小段，必须先读取全文、在上下文里重组后再整块写回；
它不能表达“旧文本必须恰好出现一次”，也不能在一个请求中证明多个文件仍与预览时一致。
桌面端下一阶段还需要消费同一份持久化 diff，而不能在 renderer 里另造提案状态。

## 决策

### 1. 编辑分成持久化的 preview 与 apply

新增 `edit.preview` 与 `edit.apply`。preview 接受按文件分组的精确字符串替换，每条替换都带
`oldText`、`newText` 与 `expectedMatches`；按给定顺序计算，零命中、命中数不符、重复路径或
读文件失败均整体失败，且不写盘。成功后生成 `EditProposal`，写入一条 `edit.proposed`。

提案记录规范化绝对路径、替换规则、预览前/后的 sha256 与统一 diff。renderer 和 headless
runtime 消费同一份契约，不从展示文字反解析数据。`edit.applied` 只记录提案 ID；会话当前的
待处理提案完全由事件回放得到。

### 2. apply 的路径清单必须与持久提案完全相等

`edit.apply` 输入带 `proposalId` 和提案文件的 `{path,beforeHash}` 清单。路径仍经能力网关解析，
由此为每个文件产出 `fs.read` / `fs.write` 主张并形成一个 M2-c checkpoint。工具随后从当前会话
事件投影取得提案，并要求 ID、路径集合与哈希逐项相等；模型不能靠只报一个无害路径、却应用
提案中的其它路径来绕过判权。

能力网关的 `pathInputs` 增加窄语法 `files[].path`，只表示“顶层数组内对象的字符串字段”。
网关逐项规范化、回写，并为每个目标生成主张；不引入任意 JSONPath。

### 3. 所有前置条件通过后才开始写

apply 先读取全部文件并逐字节计算哈希。任一文件漂移、缺失、路径不符或替换无法重新得到
预览后的哈希时，零文件落盘。所有检查通过后，逐文件使用同目录临时文件 `fsync → rename`
落盘。通用文件系统无法提供跨路径原子提交，因此不把写循环称为物理原子事务：若第二个文件
发生真实 I/O 故障，第一个文件可能已写入，但同一次调用的 M2-c checkpoint 覆盖整组目标，
可审计、可恢复。

若进程在文件写完、`edit.applied` 落库前崩溃，重试时允许“全部文件已等于 afterHash”这一
幂等收尾路径，只补记 `edit.applied`；before/after 混合状态拒绝继续，要求先恢复 checkpoint。

### 4. diff 是确定性的 UTF-8 文本

每个文件生成标准 unified diff，使用规范化路径和确定性换行；首版每个文件一个完整 hunk，
不引入模糊 patch、AST 重写或格式化器。大结果仍经过既有统一截断与 BlobStore 归档；M2-e
负责有界渲染和逐块选择，不改变这里的内容前置条件。

## 后果

- 正面：preview 不写盘，apply 可检测内容漂移，多文件调用只有一个整组 checkpoint。
- 正面：持久提案成为 M2-e UI 与 headless 工具的共同事实来源。
- 代价：事件会保存 diff 与替换规则；极大提案会增加事件行大小，后续如有真实压力再改为
  BlobRef，不能提前造双格式。
- 代价：跨文件写入不是物理原子；故障恢复语义由 ADR-0043 明确承担，不以“事务”命名掩盖。
