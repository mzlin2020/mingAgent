# ADR-0071 · 工具的规范 JSON 输出值

- **状态**：🟢 Accepted
- **日期**：2026-08-16
- **相关**：[ADR-0061](./0061-CodeMode与工具SDK生成.md)（这是它的前置二）· [ADR-0069](./0069-CodeMode的隔离机制.md)（规范值要跨的那道边界）· [ADR-0058](./0058-工具渲染意图与结果投影.md)（`presentation` 与它的分工）· [ADR-0009](./0009-工具Schema子集与结果截断.md)（可序列化子集与截断）· [ADR-0050](./0050-编辑diff的行级hunk与提案投影.md) / [ADR-0070](./0070-会话状态副表的有界化.md)（"同一份内容存两遍"这个形状已经修过两次）
- **实现**：`docs/10 §9.5.4`

## 背景

M3-h（Code Mode）有两个前置。前置一（隔离机制）已由 ADR-0069 定案。**这一份是前置二。**

ADR-0061 §五 原来写着"这一点在 ADR-0058 已经铺好，M3-h 只是把它用起来"，2026-08-14 的
规划复审判定这句话把工作量写小了：`ToolProgress` 的 `result` 分支当时只有 `forModel`
（给模型的散文）与 `presentation`（给回放期卡片投影的最小事实），**没有任何工具产出程序可用的结构**。

问题不抽象。举三个当时的真实形状：

| 工具 | 程序想要什么 | 它当时只能拿到什么 |
|---|---|---|
| `fs.read` | 文件正文 | 每行前面粘着行号和制表符的文本 |
| `shell.session.open` | 新终端的 id | `终端会话已打开：<id>` 这句中文 |
| `edit.preview` | `proposalId` 与每个文件的 `beforeHash` | 一段散文，且那段散文**专门为"模型能不能认出来"设计过** |

`edit.preview` 那条尤其说明问题。`previewEnvelope()` 有一整段注释解释为什么必须把
`proposalId` 和每个文件的 `path`/`beforeHash` 逐行自足地排在最前面：因为下一步 `edit.apply`
要靠模型**从散文里认出它们再抄一遍**，而结果截断会从中段下刀。那段设计是对的，
但它解决的是"如何让散文更容易被正确解析"——**程序根本不该解析散文**。

## 决策

**每个内建工具定义并返回一份规范 JSON 输出值。它与模型可见内容、回放展示事实三者分开。**

| 字段 | 给谁 | 谁校验 | 落不落库 | 受不受结果截断管辖 |
|---|---|---|---|---|
| `forModel` | 模型 | 契约层 `ResultBlock` | 落 | 受 |
| `presentation` | 回放期卡片投影 | 工具的 `presentationSchema` | 落 | 不受 |
| **`output`** | **程序**（Code Mode 子调用的返回值） | 工具的 `outputSchema` | **不落** | **不受** |

### 一、形状：`ToolProgress` 的 `result` 分支新增 `output?: unknown`

`ToolSpec` 新增 `outputSchema?: z.ZodType<O>`，`RegisteredTool` 新增 `parseOutput()`
与 `outputSchema` 原件（后者留给 M3-h 的 SDK 生成调 `z.toJSONSchema()`）。

三条注册期约束，`defineTool()` 当场拒绝：

1. **落在与入参同一个可序列化子集里**（`assertToolSchema(..., 'output')`）。
   规范值要跨 QuickJS 客体域边界（ADR-0069），能不能 JSON 化的约束与入参一字不差。
   共用同一个断言函数，只有报错措辞分"入参"与"规范输出值"——那句话决定看见它的人往哪找。
2. **顶层必须是 `z.strictObject()`**。标量和数组没法在不破坏已有程序的前提下加字段；
   对象可以。需要返回一列东西就包一层。
3. **没声明就不产出**：工具 yield 的 `output` 被丢掉。与 `presentationSchema`
   同形同理——没有 schema 就没有校验。

### 二、`output` 不落库

这是本 ADR 唯一一个可能被将来的人"顺手改好"的决定，所以理由写全：

- **它与另两个字段大量重复，且体积不受控。** `fs.read` 的规范值里带着文件正文，
  `shell.exec` 带着完整 stdout，`web.fetch` 带着响应体。落库等于把同一份内容存两遍，
  而且是**不受结果截断管辖**的那一份。ADR-0050（不落整份文件的前后两份全文）与
  ADR-0070（副表有界化）已经在这个形状上修过两次。
- **"模型可见 ⟺ 已落库"不要求落它。** 那条不变量约束的是**进入模型请求**的东西
  （`docs/01` 八点五）。规范值按定义不进模型请求——ADR-0061 §四 写得很明白：
  程序中间值不落库、不进提示词、不受截断管辖，那正是 Code Mode 省上下文的机制本身。
- **审计不靠它。** 一次调用做了什么由 `tool.start`（入参、能力、`origin`）与
  `tool.end`（成败、耗时、模型可见结果）记录，规范值不增加新的可审计事实——
  它是同一次执行的另一种呈现。

因此**校验时机也与 `presentation` 不同**：`presentation` 要活到 `record('tool.end')`
那一步，schema 是它进事件流前的最后一道关；`output` 永远不进事件流，
工具 yield 的那一刻就是它唯一的关口，所以 `executeToolBody` 一捕获就校验。

> **顺带更正 `docs/09` / `docs/10` 里的一句话。** 它们写着规范输出值"对结果截断、
> 卡片投影、审计都有价值"。逐条核过之后：**截断**那条成立（程序拿到的是未截断的规范值，
> 这正是 §四 的机制）；**卡片投影**与**审计**两条都要求先落库，因此按本节的理由**不做**。
> 记在这里，免得后来者按那句话去找一个不存在的实现。

### 三、失败关闭的方向是"丢掉"，不是"抛出"

规范值形状不对时丢掉，这次调用照常成功。理由是消费者：程序拿到一个字段名对不上的对象，
会读出一串 `undefined` 继续跑；拿不到至少是个能 catch、能断言的事实。

代价是**它静默**：模型照常拿到结果，程序拿到 `undefined`，哪里都不报错。
所以工具自己 yield 的规范值必须在**编译期**就对得上自己的 schema——
`pty-tools.ts` 那两个具名构造器（而不是一个收 `unknown` 的通用构造器）就是为这个写的。

### 四、内建工具必须都有；闸门在 `generate-docs`

`pnpm generate:docs --check`（在 `pnpm verify` 里）枚举全部内建工具，
缺 `outputSchema` 直接报错，并把顶层字段列进 `docs/generated/工具目录.md`。

放在这里而不是 `defineTool()` 里：测试夹具与临时工具没有理由被迫定义规范值，
而"内建工具集"这个概念只在那个脚本里被完整枚举过一次。

> 顺带修掉一处旧漏：`allTools()` 以前不传 `index`，于是 `search.symbol` /
> `search.indexed` 两个**真实工具**从来没进过那张表。一份声称"全部内建工具"的目录
> 漏掉两个，正是这张表最该拦住的那类漂移。工具数 20 → 22。

## 后果

- **正面**：M3-h 的前置二解除。SDK 生成有了唯一的类型来源，程序不必解析散文。
- **正面**：迁移过程本身抓到了几处"结构上说不出话"的地方，并当场修掉：
  - `fs.list` 的大小以前是渲染好的字符串，`"（读不到大小）"` 与 `"0 B"` 无从分辨；
    现在是 `size?: number`，**缺席就是读不到**。
  - `shell.exec` 的六种结局以前只存在于那句中文开头语里；现在是闭集的 `kind`，
    且 `exitCode` **缺席不等于 0**（被信号杀掉、被截断中止、根本没起来都没有退出码，
    而散文里的 `?? -1` 会让人把"没跑成"当成"跑失败了"）。
  - 两条搜索实现（ripgrep 与纯 Node 退路）以前各自把位置拼成 `path:line:col: 文本`。
    现在位置是结构，字符串由共用的 `formatHit()` 现拼——**Windows 绝对路径自带冒号**，
    从那种字符串里切行号是一件看起来能做、实际会错的事。
  - `git` 那一族的信封以前是 `Record<string, unknown>`，`kind` 那一列的十个取值
    靠口口相传；现在是闭集。
- **正面**：`git` 与两个索引搜索工具本来就把结构 `JSON.stringify` 给模型，
  规范值与那份同源——**这几个工具的模型可见内容一个字节没变**。

- **负面**：每加一个内建工具就多一份 schema 要写。缓解：闸门会提醒，
  且大多数工具的规范值就是它本来在算的东西。
- **负面**：`output` 静默丢弃的那条路径（§三）没有运行时信号。缓解只有编译期类型，
  以及 `packages/tools-core/tests/tool-output.test.ts` 里那条"必须能过自己的 schema"的断言。
- **负面**：`turn-tools.ts` 与 `git.ts` 因此越线，各拆出一个文件
  （`turn-guard.ts` / `git-argv.ts`）。两次都是拆分而不是加豁免。

- **必做的反向演练**（每条都看它红过一次）：
  1. 拿掉 `fs.write` 的 `outputSchema` → `generate-docs --check` 必须红。
     **已验证**：`这些内建工具没有声明 outputSchema：fs.write。`
  2. 把 `output` 写进 `tool.end` → "规范值不落库"那条用例必须红。
     **已验证**：`expected '[{"id":...' not to contain '仅规范值可见-9f3c'`。
     这条演练的形状值得留意：断言不是"某个字段不在"，而是**整份事件流的 JSON 里
     搜不到那个只出现在规范值里的哨兵字符串**——否则换个字段名就能绕过它。
  3. 顶层写成标量 / 数组、或用子集外的构造 → `defineTool()` 当场抛
     （`packages/kernel/tests/tool-output.test.ts` 的五条）。

- **重新评估条件**：如果 M3-h 落地后发现程序普遍还是要读 `forModel`
  （说明规范值漏了它真正需要的字段），那是**规范值定得不对**，
  应当逐个工具补字段，而不是给程序开一条"顺便把散文也给你"的口子——
  开了那个口子，这次迁移就白做了。

## 附：一处差点漏掉的静默失配

`search.symbol` / `search.indexed` 索引不可用时会退到 `search.text`，
实现方式是把内层工具的 `ToolProgress` 改一改再 yield 出去。

规范值加上之后，那条路会把**内层工具的规范值**原样透传出来——而两者形状不同。
后果不是报错，是 `parseOutput` 按失败关闭把它丢掉：模型照常拿到结果，
程序拿到 `undefined`，日志里什么也没有。

现在 `fallback()` 显式把内层的 `hits` 翻译进外层形状。记在这里是因为
**这类失配在每一处"包一层别的工具"的地方都会重现**，M3-h 的子调用尤其。
