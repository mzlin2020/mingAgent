# 架构决策记录（ADR）

一个决策一个文件，**只增不改**。决策被推翻时，新写一份并在新文件标注 `Supersedes: ADR-XXXX`，在旧文件顶部标注 `Superseded by: ADR-YYYY`。

命名：`NNNN-简短标题.md`，编号连续递增。

## 状态图例

- 🟡 `Proposed` — 已提出，待讨论
- 🟢 `Accepted` — 已采纳，实施中或已实施
- 🔴 `Rejected` — 讨论后否决（保留记录，避免重复讨论）
- ⚫ `Superseded` — 被后续决策取代

## 什么时候要写 ADR

- 引入或移除一个核心依赖
- 改变模块边界或依赖方向
- 改变数据格式或持久化结构
- 改变对外契约（事件、工具、插件 API）
- 安全策略的任何变更
- 否决了一个看起来合理的方案（**否决理由比采纳理由更值得记录**）
