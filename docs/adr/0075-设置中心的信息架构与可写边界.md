# ADR-0075 · 设置中心的信息架构与可写边界

- **状态**：🟢 Accepted
- **日期**：2026-08-16
- **相关**：M3.5-e；总纲 [12-桌面端界面与设置](../12-桌面端界面与设置.md) §8；
  放弃审批 [ADR-0039](./0039-放弃审批模式.md)；密钥归宿 [ADR-0022](./0022-Provider传输层与密钥归宿.md)；
  UI 偏好判据 [ADR-0077](./0077-UI偏好的存放判据.md)；
  Code Mode 呈现 [ADR-0072](./0072-CodeMode子调用的记录面与再入口.md)；
  死配置处置 [ADR-0076](./0076-logging死配置的处置.md)

## 背景

`config.json` 在删掉 `logging.*` 之后仍有模型、Provider、价目、权限规则、呈现模式
这些字段，桌面端却只能改工作目录与工具停用。M3-h 做完的 Code Mode 没有开关；
ADR-0039 之后唯一的用户侧权限入口是 `permission.rules`，UI 上零暴露。

现有设置是 `shellView === 'security'`，与 Home / 会话并列——进设置等于离开会话，
和顶栏 tabs 的心智冲突。本决策要同时定形态与可写边界，避免设置页在落地时
把「问用户」「明文 key」「allow 规则编辑」从门缝里放回来。

## 选项

### 选项 A：保留第三主视图，只往现有页加节

- 优点：改动面小。
- 缺点：进设置仍会卸掉会话主区。顶栏 tab 还在，主区却不是会话——ADR-0037 的
  导航心智被第三视图持续破坏。

### 选项 B：系统原生偏好窗口（macOS Settings / Windows 独立 BrowserWindow）

- 优点：平台惯用。
- 缺点：又一个窗口、又一套焦点；preload / IPC 要再接一次。为六节表单不值。

### 选项 C：模态 + 左导航分节；可写边界写进 IPC（选定）

- 优点：会话不被打断；每节对应总纲 §8.2 的一张表；渲染层不可信，边界在主进程。
- 缺点：要做焦点管理；`UpdateSettingsRequest` 会变宽。

## 决策

选 **C**。

### 形态

设置是**模态面板 + 左侧分节导航**，不是第三个主视图。`ShellView` 只剩 `home` | `chat`。
Esc / 遮罩关闭；打开时焦点落在关闭按钮；关闭后焦点回到打开它的控件。
不预留 MCP / Skill / 插件空节。

六节：通用、模型与 Provider、工具与呈现、权限、数据与存储、关于与安全边界。

### 可写边界（主进程强制，不是靠 UI 隐藏）

| 允许 | 通道 | 禁止 |
|---|---|---|
| `workspace.*` / `tools.disabled` / `tools.presentation` / `model.*` / `providers`（无密钥）/ `prices` / 用户 `deny` 规则 | `ui.updateSettings` | `effect: 'allow'` 的规则；任何密钥字段；红线；`logging.*`（已删） |
| API Key | **只走** `ui.setApiKey` → `SecretStore` | 把 key 放进 `UpdateSettingsRequest` 或 `config.json` |
| 主题三档、Enter 行为 | `localStorage`（ADR-0077） | 写进 `config.json` 或事件流 |

`UpdateSettingsRequest` 是 `strictObject`：多一个 `apiKey` / `key` / `allow` 即拒绝。
权限子集的 `effect` 是 `z.literal('deny')`，主进程在落到磁盘前再扫一遍——
两条闸门缺一不可，因为 schema 以后可能会被改宽，扫一遍的那条不会跟着一起消失。

手写在 `config.json` 里的 `allow` **保留**（那是覆盖「不可信上下文」三条 deny 的唯一出口，
ADR-0039）。设置页不展示、不编辑、保存时不删除它们。`userAllowRuleCount` 只读提示「还有 N 条允许规则写在配置文件里」。

红线只读。投影形状 `{ target, capabilities, why }`，由 `redLineRules()` 按 target + why 归并——
同一条路径挂在 `self.modify` / `fs.write` / `fs.delete` 上会显示成一行三个能力
（ADR-0017 的教训终于能在界面上读出来）。`UpdateSettingsRequest` 不得出现红线字段。
`StatusResult.security.protectedResources` 那四行中文概述不再当作红线清单。

### 生效时点（要标，不要装作不需要）

`updateSettings` 改的是主进程里那份 `config` / `layers`。`buildTurnDeps` 每一轮现取，
所以模型、Provider、价目、呈现模式、工具停用、权限规则都在**下一回合**生效，不必重启应用。
**工作目录只影响之后新建的任务**；已经打开的会话 cwd 不变。
主题与 Enter 立刻生效（纯 UI）。

## 后果

**正面**

- Code Mode、权限拒绝清单、换模型第一次有入口。
- `allow` 与密钥两条攻击面在 IPC 上关闭，不依赖「设置页没画这个按钮」。

**负面（必须写）**

- 手写 `allow` 仍然只能改 `config.json`。这是刻意的：设置页一旦能加 `allow`，
  渲染层被 XSS 之后就能给自己放行。代价是「放开不可信上下文的 push」对普通用户不友好。
- 已打开会话的 cwd 不随设置变。用户改了「固定目录」会以为当前任务也换了地方——
  通用节必须写明。
- 呈现模式改成 `code` 后，模型在下一回合看不到别的工具（ADR-0072 §二）。
  开关旁边必须写清，否则会当成故障。

**什么条件下重新评估**

- M4 要加 MCP / Skill / 插件节：往左导航加节，不要新开一个第三主视图。
- 若出现必须重开应用才能生效的设置（例如换密钥后端），在该项上单独标注，
  不要把「下一回合生效」改成一句笼统的「部分设置需重启」。
