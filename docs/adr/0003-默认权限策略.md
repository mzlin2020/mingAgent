# ADR-0003 · 默认权限策略：平衡档 + 无条件还原点

- **状态**：🟢 Accepted（2026-08-04 确认）
- **日期**：2026-08-04
- **相关**：[06-安全与权限模型](../06-安全与权限模型.md)

## 背景

小明运行在用户真实的电脑上，拥有文件读写、命令执行、网络访问能力，而驱动它的模型会读入不可信内容（网页、README、issue、MCP 返回值），存在被提示词注入诱导的固有风险。

默认严格度是一个体验与安全的直接权衡：拦得太狠，长任务被审批打断到无法使用；放得太松，一次模型误判就可能造成实际损失。

参考项目 manusAgent 在这一层是空白——它假设自己跑在一次性容器里。小明必须自建。

## 选项

### A. 保守档：所有写操作都要确认
- 优点：最安全
- 缺点：打断极其频繁，长任务体验崩坏；用户会因疲劳而无脑点"允许"，反而降低实际安全性

### B. 平衡档：工作区内写放行，工作区外 ask，危险操作 deny
- 优点：日常工作流几乎无打断，真正危险的动作仍被拦
- 缺点：工作区内的误操作不会被拦（依赖还原点兜底）

### C. 激进档：默认全放行，只拦绝对红线
- 优点：最流畅
- 缺点：完全依赖还原点；网络外发、GUI 输入这类**不可撤销**的操作没有防线

## 决策

选择 **B：平衡档**，并配套三条硬性要求：

1. **还原点无条件建立**——不论哪一档，破坏性操作前必须建立可一键撤销的还原点（文件内容快照 / git 轻量快照）。这是放宽默认策略的前提条件，不是可选项。
2. **绝对红线不受档位影响**——敏感路径（`~/.ssh`、`~/.aws`、`**/.env*`、钥匙串、系统目录）、毁灭性命令（`rm -rf /*`、`mkfs`、磁盘格式化）、审计日志自身，恒为 deny，YOLO 模式也不放开。
3. **提示词注入的权限降级**——本 Turn 读入过不可信内容后，高危操作策略自动收紧一档。降级**只作用于不可撤销的能力子集**：网络外发、文件删除、`git push`、GUI 输入注入。普通的"读文档 → 改代码"工作流不受影响。

> 第 3 条的范围限定是关键。全局收紧会让降级机制在正常工作流中频繁误触发，用户很快会关掉它——**一个总被关掉的安全机制等于不存在**。

## 后果

**正面**
- 日常编码工作流基本无审批打断
- 攻击面集中在"不可撤销"的少数能力上，防御可以做深
- 用户敢于放手让 Agent 干活（有可靠撤销兜底），这比多加确认框更能提升实际产出

**负面**
- 工作区内的误删误改不会被事前拦截，完全依赖还原点的可靠性
- 还原点机制本身成为关键路径：**它失效等于安全模型失效**

**缓解措施**
- 还原点机制需要独立的完整性测试，纳入 M1 的 DoD，且列入回归评测集
- 还原点存储不受策略引擎管辖之外的任何工具触碰（写入路径恒为 deny）
- UI 常驻展示"可撤销到"的位置，让用户随时知道兜底在哪

**重新评估的触发条件**
- 真实使用中出现还原点无法覆盖的损失场景
- 权限降级机制的误触发率高到用户想关掉它（说明范围划错了，需重新界定能力子集）
