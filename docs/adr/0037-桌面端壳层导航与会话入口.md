## 背景

M1 桌面端主壳是「左栏 `SessionList` + 右栏当前会话」。这在 docs/09 E3 里曾倾向为
「侧栏列表 + 单主视图，后台有活动指示」。真实使用与对照产品（openCode）后，问题变成：

1. **常驻侧栏占宽**，对话区被挤窄；会话切换的信息架构与「顶栏 tabs + Home 看全部」的
   常见形态不一致。
2. **运行时已能多会话并存甚至后台跑**（主进程 `Map<SessionId, SessionRuntime>` /
   `running`），但 UI 只有一个 `currentId`，`applyEvent` 丢弃非当前会话事件——侧栏靠
   状态徽标暗示「别处在忙」，没有「打开集合」的显式表达。
3. 窗口顶栏是 Electron **默认应用菜单**（File / Edit / View / Window），与应用内
   自定义控件脱节；用户要求合并进一个按钮下拉（同 openCode 汉堡菜单）。

约束（产品拍板，2026-08-10）：

- 布局/导航**参考 openCode**；**主题色仍与 Claude Code 一致**（不换 openCode 灰白调）。
- 去掉常驻侧栏；顶部要有**多个会话 tab**；有 **Home** 查看最近会话。
- Home **暂不展示 cwd / 项目列**（当前也没有「项目」实体）。

## 选项

### A. 保留侧栏 + 单主视图（E3 旧倾向）

优点：与改前实现一致；切换成本低。  
缺点：占宽；打开集合不可见；与用户明确要求的 openCode 壳层冲突。

### B. 仅 Home、无顶栏 tabs

主区在「最近会话列表」与「当前唯一会话」之间切换，顶栏只有标题。  
优点：实现最简，store 仍单 `currentId`。  
缺点：多会话来回要反复进 Home；无法表达「我同时开着这几个」；用户已明确要 tabs。

### C. 顶栏会话 tabs + Home 最近会话（选定）

去掉常驻侧栏。顶栏：汉堡菜单 | Home | 已打开会话的 tabs。Home 展示按 `updatedAt`
倒序的最近会话，并承载「新建会话 / 从目录创建」；从 Home 打开则加入 tabs 并聚焦。
关 tab = 移出打开集合，**默认不删除**会话数据。

优点：对齐用户参照与拍板；打开集合可见；复用现有 `listSessions` /
`createSession` / `openSession` 等 IPC。  
缺点：多一套「打开集合 vs 全部会话」心智；关 tab ≠ 删会话需文案说清；tabs 状态要在
渲染层新增（见决策）；对话主视图内新建须先回 Home。

## 决策

选择 **C**。

### 一、壳层形态（不推翻 ADR-0004）

- **主内容**仍是对话流 + 可展开观察面板（0004）。本 ADR 只改**导航壳**。
- **主题**：继续用 `--xm-*` 暖色变量；不引入 openCode 的灰白主题。

### 二、多会话呈现 = 顶栏 tabs + Home（闭合 E3）

| 概念 | 含义 |
|---|---|
| **全部会话** | EventStore 投影（`listSessions`），Home 列表按 `updatedAt` 倒序 |
| **打开集合** | 渲染层 UI 状态：哪些会话以 tab 形式钉在顶栏 |
| **焦点** | 仍只有一个 `currentId`；主区只渲染焦点会话 |

- 点击 tab → 切换 `currentId`（等价于改前点侧栏项）。
- Home → 进入最近会话视图；实现为**保留** `currentId` / `openIds`，只把
  `shellView` 切到 `home`（离开对话主视图，tabs 仍可见）。
- **新建会话 / 从目录创建**只放在 Home（不再在顶栏放 `+`，也不在汉堡里重复）→
  `createSession`，新会话进入打开集合并聚焦。
- **关闭 tab**：移出打开集合；**不**删 SQLite 事件流（会话删除/归档仍未立项）。
  关闭控件文案避免「删除」措辞。
- Home 列表项：**标题 + 既有状态徽标**；**不**展示 cwd、**不**引入项目实体。

**打开集合本轮可不持久化**（重启后 tabs 清空、回 Home 即可）。若实现中发现痛点，
再单独补「恢复上次打开集合」，不在本 ADR 扩大范围。

### 三、事件与 IPC 边界不变

- **不改**事件契约、EventStore、`SessionRuntime` 多会话缓存语义。
- **不改**「消息真相 = reduce(events)」（ADR-0015）。tabs / Home 只增减渲染层导航状态
  （`openIds` / `shellView`），不维护第二份 `messages`。
- 非焦点会话的事件：与改前切侧栏相同——UI 可忽略；切回时靠 `readSession` /
  主进程已缓存的 runtime 状态对齐。真「一窗并排盯两个会话」仍留给 M4 多窗口。

### 四、菜单合并为汉堡下拉

- 主进程 `Menu.setApplicationMenu(null)`，去掉 Electron 默认菜单栏。
- 应用内汉堡下拉**只保留**：设置（M3 占位）、帮助（占位）。
- 不把「新建会话 / 从目录创建 / 最近会话」放进汉堡——这些已由 Home 与顶栏 Home
  按钮承接，再放一遍是冗余。
- **设置**实体页仍归 **M3**（密钥/Provider），本轮不做设置页。

## 补记 · 落地后去冗余（2026-08-10）

首版壳曾按 openCode 对照在顶栏放 `+`、在汉堡里重复「新建 / 从目录 / 最近会话」。
真实界面上 Home 已有同等入口，用户反馈冗余后去掉：

- 顶栏：**无** `+`（形状为：汉堡 | Home | tabs | 审批档/用量）
- 汉堡：**仅**设置、帮助

决策正文已按此现状书写；本补记保留「曾经多放过」的痕迹，避免后人按旧截图把入口加回来。

## 后果

**正面**

- E3 从「侧栏倾向」改为与产品参照一致的壳层。
- 打开集合显式化，匹配「后台可跑、UI 单焦点」的既有运行时事实。
- 主题与 0004 定位不漂：看起来像小明，导航学 openCode。
- 新建入口单一（Home），减少顶栏/菜单与主区三处重复。

**负面**

- 用户要区分「顶栏开着的」和「Home 里全部的」；关 tab 若被理解成删除会造成惊吓——
  关闭控件须避免「删除」措辞。
- Home 暂无 cwd：大量「新会话」同名时更难辨（缓解：可后续加相对时间或 cwd，本轮刻意不做）。
- 自定义汉堡替代系统菜单后，平台菜单习惯与部分快捷键归属变窄（仅设置/帮助占位）。
- 对话主视图内不能一键新建，须先点 Home。

**非目标（本 ADR 明确不做）**

- 配置中心实体页（M3）
- 会话删除 / 归档
- 项目实体与 Home 项目列
- 一窗内多会话并排双视口
- 无边框自定义标题栏（除非实现时与汉堡/系统菜单冲突再单开）
- 顶栏 `+`、汉堡内的会话创建/跳转入口（已否决为冗余）

**重新评估的触发条件**

- 打开集合不持久化导致每日重启后无法忍受
- 同名会话在无 cwd 下列表不可用
- 用户强烈需要并排盯两个会话（走 M4 多窗口，而不是把单焦点模型撕开）
- 对话主视图内频繁需要新建、回 Home 成本过高（可再评估是否恢复顶栏 `+`）

## 实现落点（与代码一致）

- `apps/desktop/src/renderer/App.tsx`：无常驻侧栏；主区按 `shellView` 切 Home / 对话
- `HomeView` / `SessionTabs` / `AppMenu` / `session-status`
- `store`：`openIds`、`shellView`、`goHome`、`closeTab`；`openSession` 写入打开集合
- `main/index.ts`：`Menu.setApplicationMenu(null)`

## 补记（2026-08-10，样式打磨）

导航结构落地后做了一轮纯视觉打磨，**不改本 ADR 的任何决策与非目标**，只补一层此前完全缺失的
设计 token。记在这里而不是新开 ADR：没有触及依赖方向 / 持久化 / 对外契约 / 安全策略，
按 `docs/adr/README.md` 的门槛不够格；但它给出了「以后所有样式怎么写」的约束，值得留痕。

- **`styles.css` 升级成 `@theme` token 层，并把 Tailwind 自带的 color / radius / text / shadow
  四个命名空间 `initial` 清零。** 清零是这次的核心：`bg-red-500`、`rounded-lg`、`text-4xl`
  之后**在编译期就不存在**，想跑偏必须先回到 `styles.css` 登记一档。此前一致性只靠 review
  用眼睛抓，结果是圆角四档、字号七档、三套互不对齐的内边距。对应 docs/01 原则七
  「不能被 CI 或代码审查检验的原则等于没有」。
  - 配套：`lib/cn.ts` 用 `extendTailwindMerge` 登记同一张档位表，否则 tailwind-merge
    会按默认档位误判冲突（`text-body` 会被当成文字颜色而被 `text-muted` 顶掉）。
- **主题仍是 Claude Code 暖色调**，没有换成 openCode 的灰白（本 ADR 决策一原样保留）。
  深色仍只跟随系统，应用内不加开关——配置中心是 M3 的非目标。
- **边框改成有含义**：助手回复不再套卡片，用户消息用浅色气泡，框留给「机器干的事」
  （工具卡 / 终端 / 审批卡）。`LiveMessage` 与 `MessageView` 的助手分支共用同一份容器类，
  否则 `message.end` 那一刻同一段文字会当着用户的面跳一下。
- **顺带修掉三处在结构重构里留下的视觉缺陷**：
  1. 顶栏底色与选中 tab 底色同为 `--xm-surface`，选中态几乎不可见，而未选中 tab 的 hover
     底色对比度反而更强——指示是反的。现在顶栏落到页面底色，选中的 tab 是唯一一片 surface。
  2. Home（`max-w-2xl`）与对话（`max-w-3xl`）栏宽不同，来回切时内容栏会变宽再变窄。
  3. 滚动条只占滚动区宽度而输入区在滚动区之外，有滚动条时消息栏比输入框往左偏 3px
     （`scrollbar-gutter: stable both-edges`）。
- **`UsageBadge` 撤下 `seq` 与英文 status**：那是调试信息，`seq` 挪进悬浮提示，
  状态由 tab 上的中文徽标表达。「未计价」的语义原样保留。
- **Home 列表补上相对时间**（`lib/relative-time.ts` + `tests/relative-time.test.ts`）——
  兑现上面「负面」里记的缓解手段（"可后续加相对时间或 cwd"）。这一列同时让
  「按最近活动排序」那句话变成可核对的，而不是用户只能选择相信。
  - `formatRelativeTime(at, now)` 收 `now` 作参数而不是自己取当前时间：否则 59 秒 /
    60 秒 / 跨午夜这些边界在测试里断言不了。超过 24 小时按**自然日**算而不是 24 小时的
    整数倍；不足 24 小时即使跨了午夜也说小时（凌晨看「昨天」会误以为是很久以前）。
  - `HomeView` 里挂了一个 30 秒的计时器自己走针。只在渲染时取一次 `Date.now()` 的话，
    用户停在 Home 上几分钟，一条「刚刚」会一直是「刚刚」——那正是本仓库反复在防的
    「一个自信的错数字」。
  - 状态徽标随之从行尾挪到标题旁：留在右边会把时间列挤得参差不齐（有徽标和没徽标的行，
    时间落在两个不同的位置上），而且徽标说的本来就是「这个会话现在怎么样」，属于名字那一侧。
