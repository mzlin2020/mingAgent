# ADR-0067 · 子 Agent 作用域的两级扁平语义

- **状态**：🟢 Accepted
- **日期**：2026-08-14
- **相关**：[ADR-0049](./0049-M2-i串行只读子Agent.md) · [ADR-0052](./0052-插件容器与效果模型.md) · [M3 阶段划分](../M3-阶段划分.md)

## 背景

ADR-0052 决定用 `ctx.fork()` 表达子 Agent 的能力作用域，但没有回答 fork 出来的作用域是否
继续继承父作用域的局部注册。这个答案会直接进入 M3-a 的接口，不能留到第一个消费者出现时再猜。

当前 M2 子 Agent 通过显式白名单重建工具注册表，不继承父会话临时得到的插件、MCP 或写能力。
如果容器改成普通的多级原型继承，孙级 Agent 能看到哪些服务和监听器就必须沿祖先链求解；
权限审查也会从“看本层显式装了什么”退化成“遍历整棵树后才知道”。

## 选项

### 选项 A：多级继承

每次 `fork()` 都继承调用方作用域的全部可见注册。表达力强，但能力集合随嵌套深度隐式增长，
与 ADR-0049 的显式白名单立场相反。

### 选项 B：完全独立

子作用域什么都不继承，连时钟、ID、事件总线等根服务也要逐项重装。边界最清楚，
但会把每个子 Agent 都变成一次完整应用装配，且基线服务容易漏装。

### 选项 C：两级扁平解析，生命周期仍按所有权级联

所有 fork 作用域只解析“根作用域 + 自己”两层。即使从子作用域再次 fork，新作用域也不继承
调用方的局部注册；但它仍由调用方拥有，调用方卸载时级联清理。

## 决策

**选择 C。**

1. 根作用域的服务与监听器对所有 fork 可见；它承载 `clock`、`ids` 和以后 M3-b 的特权基线。
2. fork 作用域的局部服务、监听器和插件只对自己可见，不向再次 fork 出来的作用域传播。
3. 解析关系固定为两层，但生命周期保留所有权树：卸载插件会卸载它创建的 fork，
   卸载父 fork 也会卸载其拥有的后代。**解析扁平不等于资源无人负责。**
4. 子树血缘继续由 `parentSessionId` / `parentCallId` 等持久数据表达，不用作用域嵌套充当业务事实。
5. fork 不自动复制父层工具。M3-d 接入子 Agent 时，允许进入子作用域的工具仍须显式注册或投影。

## 后果

- **正面**：任一子 Agent 的局部能力只需检查根层和本层；嵌套深度不会扩大隐式权限。
- **正面**：根基线只装一次，`clock` / `ids` 等稳定服务不需要每个子 Agent 重复提供。
- **负面**：确实需要把父层某项能力交给子 Agent 时必须显式重注册；这是有意的审查点。
- **必做反向演练**：根提供 `clock`、父 fork 提供 `secret`，从父再次 fork；孙层必须看得到
  `clock`、看不到 `secret`，且卸载父层后孙层全部效果消失。
- **重新评估条件**：若未来出现必须共享大量父层局部状态的真实场景，优先引入显式
  “能力投影” API，不先恢复多级隐式继承。
