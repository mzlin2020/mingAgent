# ADR-0074 · 桌面端两栏让位链与右栏详情

- **状态**：🟢 Accepted
- **日期**：2026-08-16
- **相关**：M3.5-b（壳）/ M3.5-d（详情内容）；总纲 [12-桌面端界面与设置](../12-桌面端界面与设置.md) §5 / §7、
  分段 [M3.5-阶段划分](../M3.5-阶段划分.md)；
  **细化** [ADR-0004](./0004-主界面形态.md) 的「可展开观察面板」；
  **不改** [ADR-0037](./0037-桌面端壳层导航与会话入口.md) 的顶栏 tabs / Home / 无侧栏；
  UI 偏好存放见 [ADR-0077](./0077-UI偏好的存放判据.md)

## 背景

ADR-0004 定了「对话为主 + 可展开观察面板」，但没规定窄窗口时面板怎么让位。
落地成固定 380px + `max-width: 900px` 改覆盖层：窄了就浮在正文上，宽了要再点一次才回来。
覆盖层把「两栏」临时改成「一层叠一层」，拖拽、偏好宽度、拉宽自恢复三条都没有落点。

M3.5 要把右栏从「工作区四块」升级成「详情 + 工作区」（总纲 §7）。
详情栏要保住滚动位置和展开状态，**关闭不能 unmount**。
覆盖层那条路会在切到绝对定位时丢掉这些，先把壳定死，d 段才接得上内容。

参考实现是三栏求解器（`sidebar | center | details`）。小明没有左侧会话侧栏
（ADR-0037），不能照抄三参数签名——一个恒为 0 的参数会让人以为侧栏只是没接上。

## 选项

### 选项 A：保留 900px 覆盖层，只加拖拽

- 优点：改动最小。
- 缺点：**没解决让位**。窄窗口仍然叠一层；拉宽不会自己回来；覆盖层与「保持挂载」冲突。

### 选项 B：照抄参考实现的三栏求解器

- 优点：与参考实现对得上。
- 缺点：签名里有侧栏。小明没有侧栏（ADR-0037），抄过来就是在布局函数里为一项
  明确不做的产品决定留位置。

### 选项 C：两栏纯函数让位链（选定）

`computeColumns(viewport, details)` 只吃两栏。自动关闭是派生结果，不回写偏好。
关闭 = 零宽但保持挂载。

- 优点：让位顺序可单测；拉宽自恢复是函数的性质，不是交互状态机；d 段的滚动位置有落点。
- 缺点：窄窗口不再用覆盖层「挤出完整右栏」——详情栏会先被压、再被关掉，
  用户要看工作区得把窗口拉宽，或接受正文暂时低于 640。这是让位链的代价，接受。

## 决策

选 **C**。六条具体决定：

### 一、让位顺序是契约，不可改序

常量：`CENTER_MIN = 640` / `DETAILS_MIN = 300` / `DETAILS_MAX = 520` / `DETAILS_DEFAULT = 360`。

1. 视口 ≥ `CENTER_MIN + 偏好` → 详情栏用偏好，正文吃剩余。
2. 再窄 → 正文守住 640，详情栏从偏好往 `DETAILS_MIN` 压（连续压，不是一步跳到下限）。
3. 视口 < `640 + 300` → 详情栏宽度为 0，正文吸收亏空，**此时才允许低于 640**。

第 2 步读成「压到下限」是地板，不是一次性跳到 300。
`viewport = 980、偏好 360` 得到 `{ center: 640, details: 340 }`，不是 `{ 680, 300 }`。
跳档会让拖拽时把手跟不上指针。

### 二、自动关闭绝不回写偏好

`resolveDetailsLayout` 只投影这一帧要画的宽度。
用户拖出来的 400 和用户点过的「开着」都留在偏好里；窗口拉回 1200，详情栏按 400 回来，
用户不用再点一次。

回写是这条链唯一会静默失效的方式：写成 0 之后，拉宽看到的是关着的栏，
跟「覆盖层关掉要再点」是同一个洞。

### 三、关闭 = 零宽，组件保持挂载

`[data-details-collapsed]` 去掉左边框，否则零宽也会画出一条 1px 缝。
内层按偏好宽度继续布局，被外层 `overflow: hidden` 裁掉——滚动位置和展开状态还在。
d 段的「关闭再打开保住滚动」依赖这一条，本段先落地，不许先 unmount 再在 d 改回来。

### 四、拖拽把手：8px 命中带 + 12×32 药丸，hover 才显形

命中带跨在列边界上（`margin-left: -4px`）。默认透明，指针进入详情栏或把手时才显形。
拖拽期间关掉列宽过渡，否则列会追不上指针。
拖的是偏好宽度，夹在 `[300, 520]`；这一帧画多宽仍走让位链。

### 五、右栏的壳是「详情 + 工作区」，内容分两段落

用户保留的交互不变：右上角图标展开右栏。变化在内容：

| tab | 内容 | 何时自动选中 | 落在哪段 |
|---|---|---|---|
| **详情** | 选中那次工具调用的 Input / Output；`run_code` 子调用同样可点 | 点击工具行 | **d** |
| **工作区** | 现有 todo / 运行中调用 / 终端 / checkpoint | 无选中时 | **b 维持原样** |

本段不改右栏内容，也不改「没内容就不出现开关」这条现有门槛。
d 段接详情时不得把本段的挂载/让位/拖拽重做一遍。

子调用的 `Output` 只能显示「已执行 / 失败原因」——`tool.code.dispatch` 没有 `forModel`
（ADR-0072），那是设计，不是缺数据。文案在 d 段落，本段记下以免有人提前给 payload 加字段。

### 六、顶栏 tab 选中态换成 2px 底部指示条

形态不变（汉堡 / Home / tabs / 右栏开关，ADR-0037）。
选中态从填充 `surface` 换成 13/16 wt500 文字 + 底部 2px 强调色指示条。
填充选中态要求顶栏与 tab 不同色；指示条没有这个约束。
右栏开关的按下态用已有的 `accent-weak`，不新开 `interactive-bg-active` 别名——
本段不扩 token 表，按下态要的是「别再写一笔 `bg-surface-2`」。

## 后果

**正面**

- 窄窗口不再叠一层覆盖层；拉宽后详情栏自己回来，可单测钉死。
- d 段的滚动位置有了结构上的落点（保持挂载），不用在内容段再改壳。
- 求解器只有两栏，签名不会引诱下一个人把侧栏接回来。

**负面（必须写）**

- 窄于 940px 时详情栏直接消失，不再以覆盖层形式可读。这是让位链换掉覆盖层的确定代价。
- 多了一处 `localStorage` 状态源（宽度 / 开关）。判据见 ADR-0077，但判据要有人守。
- 第 2 步连续压缩与总纲原文「压到 `DETAILS_MIN`」的字面读法不同。
  字面跳档在拖拽时把手会跳，连续压才跟「让位」一致；以本 ADR 为准。
- 顶栏 tab 不再是「浮起的一张纸」。习惯填充选中态的人会觉得指示变弱——
  这是为了让顶栏坐在 canvas 上，接受。

**什么条件下重新评估**

- 真机上 940px 附近关栏被抱怨为「工作区丢了」，且拉宽自恢复不够用。
- d 段落地后，详情内容在零宽挂载下仍有可见的布局抖动，再议内层宽度策略。
