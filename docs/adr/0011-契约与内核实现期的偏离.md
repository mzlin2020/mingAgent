# ADR-0011 · 契约与内核实现期的偏离与新增约束

- **状态**：🟢 Accepted
- **日期**：2026-08-04
- **相关**：[10-契约设计](../10-契约设计.md)、[ADR-0008](./0008-事件持久化分层与演进.md)、[ADR-0009](./0009-工具Schema子集与结果截断.md)、[ADR-0010](./0010-TypeScript双编译器工具链.md)、[ADR-0007](./0007-平台支持分级.md)
- **依据**：2026-08-04 M0-a 实现（`@xm/contracts` + `@xm/kernel` 落地并通过 136 个测试与 6 项违规演练）

## 背景

[10-契约设计](../10-契约设计.md)是按"可直接照写"的标准写的，但真正写下去仍然会撞上文档没覆盖、或者文档写错了的地方。本 ADR 逐条记录，避免这些判断只存在于代码注释里。

---

## 一、docs/10 未覆盖，本次补上的

### ① `Todo` 类型缺定义 → 新增 `contracts/src/session/todo.ts`

`todo.updated` 事件与 `SessionState.todos` 都引用 `Todo`，但 §1 的目录里没有对应文件。补：

```ts
{ id: string; content: string; status: 'pending'|'in_progress'|'completed'; activeForm?: string }
```

**契约层不对清单做语义约束**——不检查"是否只有一个 in_progress"、不检查顺序。那是提示词该管的事；在契约里强加规则只会让模型的合理用法被拒绝。

### ② 配置树只有合并语义，没有字段 → 定下 M0 最小集

`model` / `providers` / `permission` / `tools` / `logging`，`apiKey` 只接受 `SecretRef`。
`ConfigPatch` 定义为 `Record<string, unknown>`（**不是** `Config.deepPartial()`）——因为补丁里要能出现 `null` 表示删除，而 `null` 不是 `Config` 的合法取值。合并后整体按 `Config` 校验。

### ③ 瞬态事件**不占用 seq 空间**

docs/10 §4.1 要求 seq 无空洞，§4.2 又说瞬态事件不落库——两条放在一起就隐含了这个结论，但文档没写明。定死：

> `seq` 是**持久化流**的位置。瞬态事件携带的 seq 等于当时已持久化的最大 seq，仅供 UI 排序参考；`reduce` 处理瞬态事件时连 `lastSeq` 都不推进。

否则 `events` 表必然出现空洞，"从 seq N 起增量订阅"就需要额外元数据才能做。

### ④ 事件**信封**也用 `looseObject`

docs/10 §4.1 的示例写的是 `z.object()`。但"未知字段=版本漂移，丢弃=永久损坏数据"这条理由对信封层同样成立，没有理由区别对待。已实测 `.extend()` 会保留 looseObject 的宽松性，判别联合照常工作。

### ⑤ `z.record()` 纳入工具入参的合法子集

docs/10 §5.2 的表格没提 record。环境变量、HTTP headers 这类入参是真实需求，而 `record(string, string)` 是有约束的（不同于被禁的 `z.any()`）。放行，但 key 与 value 的类型仍要各自过一遍子集断言。

## 二、docs/10 与其它文档写错了、本次修正的

### ⑥ 🔴 `process.platform` 禁令不可能由 dependency-cruiser 执行

[03-技术选型 §4.1](../03-技术选型.md) 与 [ADR-0007](./0007-平台支持分级.md) 都写"由 dependency-cruiser 规则在 CI 拦截"。**这是做不到的**：depcruise 做的是依赖图分析，它看得见 `import 'node:os'`，看不见 `process.platform` 这个标识符。

改由 ESLint `no-restricted-properties` 执行，作用域限定 `packages/**` 与 `apps/**`（仓库脚本不受限）。平台适配器自身用 `eslint-disable` 并写明理由。已由违规演练验证生效。

### ⑦ 🔴 `tsc -b` 的退出码是 **2**，不是 1

[ADR-0010](./0010-TypeScript双编译器工具链.md) 记录"TS 7 退出 1、TS 6 退出 2"，那是 `tsc --noEmit` 的测量。本次实测 **build 模式（`tsc -b`）下 TS 7 退出 2**。

结论不变、反而更强：**CI 脚本一律只判断非零，禁止判断具体值**。这条已写进 `.github/workflows/ci.yml` 的注释。

### ⑧ 体积预算的分母

docs/10 §12 已修正为"契约包自身 < 15KB"。本次实测：契约包 **6.47KB**（min+gzip，不含 zod）。预算合理，无需调整。

## 三、实现中发现的新坑

### ⑨ 🔴 dependency-cruiser 的 `includeOnly` 会让规则静默失效

最初写了 `options.includeOnly: '^(packages|apps)/'`，本意是"只关心我们自己的代码"。实际后果是 **node 核心模块与 node_modules 里的依赖压根不进依赖图**——于是"内核禁 `node:*`"和"契约只许依赖 zod"这两条规则全部失效，而 depcruise 照样输出 `no violations`。

发现方式是**故意违规演练**：往 kernel 里加一行 `import 'node:fs'`，depcruise 依然全绿。

> **由此确立一条工程纪律**：护栏配置写完必须做一次故意违规，验证它真的会拦。
> **规则存在 ≠ 规则生效**，而失效的护栏比没有护栏更危险——它会让人以为已经被保护了。
> 6 项演练已固化进交付清单。

### ⑩ `@types/node` 会悄悄削弱"内核零 I/O"的编译期保证

测试与脚本需要 `@types/node`。但它一旦装在根上，默认对所有工程可见，kernel 里写 `process.cwd()` 就能通过类型检查——编译期的保证就没了，只剩 depcruise 一道。

对策：`tsconfig.base.json` 设 `"types": []` 切断自动引入，测试工程 `tsconfig.tests.json` 单独把 `["node"]` 开回来。

同理，`crypto.randomUUID()` 与 `TextEncoder` 在 contracts / kernel 里是**就地声明最小结构**取用的，不引入 DOM lib——否则 `document`、`fetch` 也会一并变得可见。

### ⑪ `assertToolSchema` 依赖 Zod 的半公开内部结构

判定合法子集必须遍历 `schema._zod.def`（`type` / `shape` / `catchall` / `innerType` / `options` / `discriminator`）。这不受 semver 保护。

对策：`zod` 在 `package.json` 里锁**精确版本**（`4.4.3`，不是 `^4.4.3`），`tests/tool-schema.test.ts` 的九个违规样例充当升级时的回归闸门；`tests/zero-deps.test.ts` 断言版本号不含 `^`。

顺带确认了 docs/10 §5.2 的那条结论确实成立：`.transform()` / `z.any()` / `z.lazy()` 在 `io:'input'` 下**导出都不抛错**，测试里对此有显式断言。

### ⑫ 提交前密钥扫描需要逐行豁免，且明文赋值检测只能对配置文件生效

第一版扫描器把**自己仓库的初始提交**给拦了：`redact` 的测试样本必须包含密钥形态；`apiKey: SecretRef.optional(),` 这类源码也被当成明文赋值。

两处修正：
- 明文赋值检测只作用于数据文件（`.json/.yaml/.toml/.env/...`），源码仍受特征前缀保护
- 增加**逐行**豁免标记 `xm-secret-scan:allow`

刻意不做整文件豁免：整文件豁免一旦加上就没人会再取消，而那个文件里后来贴进去的真密钥就再也扫不出来了。

## 四、推迟的决定

### ⑬ 暂不引入 Turborepo

[08-路线图](../08-路线图与里程碑.md) M0 写的是"pnpm + Turborepo monorepo"。当前只有两个包，且：

- `tsc -b` 自带项目引用图与 `.tsbuildinfo` 增量，套一层 turbo 只会有两套缓存语义
- typed lint 是 CI 最慢的一环，但根级 `eslint .` 单进程复用一个 TS program，比每包起一个 program **更快也更省内存**——turbo 的并行在这里是负收益

包数到 5 个以上、或 CI 时间成为实际阻塞时再引入。届时更新本条。
