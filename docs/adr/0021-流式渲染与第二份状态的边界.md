# ADR-0021 · 流式渲染：两条各自正确的约束，合起来产生了一个洞

- **状态**：🟢 Accepted（2026-08-05）
- **日期**：2026-08-05
- **相关**：关闭 docs/09 **G6**；细化 [ADR-0015](./0015-进程与IPC边界.md)「渲染层不持有第二份状态」；不改变 [ADR-0008](./0008-事件持久化分层与演进.md) 的瞬态恒等不变量

## 背景

两条约束，各自都对，而且都有测试守着：

- **ADR-0008**：瞬态事件（`message.delta`）在 `reduce` 里**必须是空操作**，
  不得改变状态的任何一位，包括 `lastSeq`。
- **ADR-0015**：渲染层**不持有第二份状态**，消息流全部由 `reduce()` 算出。

合起来的后果是：`message.delta` 推到渲染层之后**无人接收**——
`App.tsx` 只渲染 `session.messages`，而 delta 进 `reduce` 之后什么也没发生。

**模型正在输出的文字，在 `message.end` 落库之前一个字都不会显示。**

M0-b 看不出来，因为脚本化 Provider 是瞬间返回的。M1 接上真实模型，一次三十秒的
流式回复期间界面完全静止——而那恰恰是对话类产品最核心的体感。

> 这个洞的形状值得单独记一笔：它**不在任何一条约束里**，在两条约束之间。
> 逐条评审每一条决策都不会发现它。

## 决策

### 一、live buffer 是**在途事件**的投影，不是 `SessionState` 的副本

ADR-0015 禁的是「UI 自己维护一份**会和回放结果分叉**的 messages」。
分叉之所以致命，是因为它的表现是"刷新一下内容就变了"，而且没人说得清哪一份是对的。

live buffer 渲染的是**尚未持久化的瞬态事件**：它本来就不在回放结果里，
`message.end` 一到就归零。

这不是一句辩解，是一条**可执行的判据**：

> **任何时刻，同一段文字要么在 buffer 里，要么在 `state.messages` 里，不会同时在两边。**

两者在时间上互斥，没有重叠，就没有分叉的余地。用例围着这条判据写。

### 二、归零的时机是全部要害

四种归零，缺一不可：

| 事件 | 为什么 |
|---|---|
| `message.end` | 正文已经进了 `state.messages`，再留着就是重影 |
| `message.interrupted` | 用户按了停止，在途内容不该继续挂在屏幕上 |
| `turn.end` | 兜底。回合结束却还有在途消息，说明前两条漏了一条 |
| 新的 `message.start` | 上一条让位，同时也是新缓冲的起点 |

漏掉任何一条的后果都一样：屏幕上出现一段**回放不出来**的文字——
而那正是 ADR-0015 要防的那种"第二份状态"。

另外两条判断：不属于当前消息的 delta 一律丢弃；没有 `message.start` 就来的 delta
不凭空造出一条消息。订阅可以中途接上（`fromSeq` 续读），所以"没看见开头"是正常情况，
不是错误。

### 三、放内核，不放渲染层

`packages/kernel/src/state/live-buffer.ts`，纯函数。

CLI（M3）要渲染同一件事。写在 `store.ts` 里，CLI 就会再写一份，
两份的归零时机会慢慢分叉——那时"什么时候归零"就有了两个答案。
而且它是纯函数，放在内核才能被穷举测试。

### 四、端到端用例订总线，按渲染层一模一样的方式消费

单元测试只能证明 `applyLive` 这个函数对不对。要证明**它长在真实路径上**，
必须订总线、跑一遍真的 `runTurn`，然后检查两件事：

1. 流式期间屏幕上的文字**逐条变长**（G6 那个洞的正面证明）
2. 逐条 delta 拼出来的，与最终落库的 `message.end` **逐字一致**

第二条是 ADR-0008 的包含性不变量（*瞬态事件不得携带持久流中不存在的信息*）
在真实 Turn 循环上的检查点。它一旦破了，用户会看到打字机打出一段字、
在结束的瞬间被换成另一段——**而事件流看起来完全正常**。

这条纪律与 ADR-0017 建立的那条是同一条：护栏必须在它真正要拦的那条路径上被验证一次。

## 后果

**正面**

- 流式输出终于渲染得出来
- "什么样的第二份状态是允许的"有了一条可执行的判据，而不是靠下一个人猜
- 测试 358 → 372

**反向演练**（三条全部当场转红）

| 演练 | 结果 |
|---|---|
| `message.end` 不清 live | 3 红，含"回放持久化流与带 delta 的结果一致"那条 |
| 让 `message.delta` 改状态 | 6 红，既有的持久化包含性用例全部当场拦下 |
| `turn.ts` 让 delta 与 `message.end` 不一致 | 1 红 |

**负面 / 遗留**

- **停止按钮还没有。** live buffer 已经处理了 `message.interrupted`，
  但没有任何东西会发出它——M1-b 补。
- **工具调用的在途状态没有纳入。** `tool.progress` 同样是瞬态事件，
  同样在 `reduce` 里是空操作，所以"工具正在跑第几步"目前也显示不出来。
  形状与本 ADR 完全一致，M1-b 做工具卡片时按同一套判据扩展 `LiveBuffer`。
- G4 / G5（回放超线性、`readSession` 全量物化）不在本轮，随 M2 的状态快照一起做。

## 这次值得记住的

> **两条各自正确的约束，可以合出一个谁都不负责的洞。**
>
> 它躲过了逐条评审——因为每一条单看都对；也躲过了 M0-b 的验收——因为脚本化 Provider
> 瞬间返回，症状根本不出现。让它现形的是一个很朴素的问题：
> **"接上真实模型之后，这一秒钟屏幕上会发生什么？"**
>
> 约束之间的空隙，只有在把整条路径当成一件事去想的时候才看得见。
