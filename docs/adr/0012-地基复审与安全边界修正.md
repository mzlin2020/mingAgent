# ADR-0012 · 地基复审：安全边界的四处失效与契约补强

- **状态**：🟢 Accepted（2026-08-04）
- **日期**：2026-08-04
- **相关**：修正 [ADR-0003](./0003-默认权限策略.md) 的实现缺口；补强 [ADR-0008](./0008-事件持久化分层与演进.md)、[ADR-0009](./0009-工具Schema子集与结果截断.md)；延续 [ADR-0011](./0011-契约与内核实现期的偏离.md) 的护栏纪律

## 背景

M0-a 交付后做了一次全量复审，目标是回答一个问题：**这套地基能不能扛住 M1–M6 的业务，以及之后不断新增的能力？**

复审方法沿用 ADR-0011 的纪律——不看规则写没写，看规则**在真实输入下会不会触发**。为此对 PolicyEngine、事件读写路径、配置合并、工具注册分别构造了"运行时真正会传进来的那种输入"来打。

结论分两部分：**架构骨架是对的**（事件溯源、纯函数内核、契约单一来源、能力闭集，这些承重结构都站得住，M1–M6 不需要推翻其中任何一条）；**但安全边界的实现有四处在真实输入下是失效的**，且四处的输出全部显示"规则已配置"。

## 发现

### ① 红线规则在真实输入下几乎全不命中 🔴

实测（`tests/policy-redlines.test.ts` 已固化为回归用例）：

| 请求 | 期望 | 修复前实际 |
|---|---|---|
| `fs.delete "/tmp/.."` | deny（红线） | **ask** |
| `fs.delete "/home/ming"` | deny（红线） | **ask** |
| `self.modify "packages/kernel/src/policy/engine.ts"` | deny（红线） | **ask** |

根因是**规则的坐标系和请求的坐标系不是同一个**：红线写 `target: '~'`，而运行时传进来的一定是展开后的 `/home/ming`——这条红线永远不会命中；红线写 `'/'`，而 `/tmp/..`、`//`、`/.` 都是同一个位置却字符串不等。glob 是纯字面量匹配，没有规范化契约兜着，**拼写差异就是绕过手段**。

`red.fs-delete-home-root` 属于"从写下的那一刻起就没有生效过"。

### ② 注入降级只做了一半，而漏的正是起作用的那一半 🔴

ADR-0003 与 docs/06 §4.2 写的是"收紧一档：`allow → ask`，`ask → deny`"。实现只做了 `allow → ask`，且 `ask` 分支在 `evaluate()` 里直接 return，**根本没经过降级函数**。

这个缺口的形状很具体：注入攻击的典型模式是"读到外部内容 → 立刻做一次不可撤销的操作"，而那类操作（`git.push` / `fs.delete` / `net.fetch`）在平衡档默认规则里**本来就是 ask**。于是攻击路径上的判定压根没变过——弹出的是用户每天都在点的那个确认框。防御写了，但没长在攻击路径上。

### ③ 一条会话事件即可提权到 YOLO 🔴

`session.config` 事件的 payload 是 `ConfigPatch = Record<string, unknown>`，而配置分层里"会话覆盖"排在项目级之上。实测 `{ patch: { permission: { tier: 'yolo' } } }` 被 `reduce` 原样合入 `state.config`。

事件流的写入方将来会包括工具、插件宿主、以及小明自己（L4）。**任何能追加一条 session.config 的路径都等于一条提权通道**，`providers.*` 同理（改 baseUrl 即可把请求连同上下文导向任意端点）。

### ④ L4 红线只护住了判定逻辑，没护住判定的输入和护栏本身 🔴

原红线只有 `packages/kernel/src/policy/**`。但要让权限系统失效，根本不用碰判定逻辑：

- 改 `contracts/src/permission/capability.ts` 删掉一个能力词条 → 所有针对它的规则变成死规则，PolicyEngine 一行没动却全面失效
- 改 `scripts/check-secrets.mjs` → 密钥可以随提交外泄
- 改 `.dependency-cruiser.cjs` / `eslint.config.js` / `.github/workflows/**` → 架构护栏静默消失（ADR-0011 ⑨ 已经演示过一次：`includeOnly` 一行就让两条核心规则失效且输出全绿）

红线要护的从来不是某个文件，是**"改了它就没人拦得住后续改动"的那一组文件**。

### ⑤ 未来版本的事件被静默降级解释 🟠

`parseStoredEvent` 只处理 `v < 当前版本`（跑 upcaster），对 `v > 当前版本` 不作任何处理，直接把 `v` 改写成本机版本再 parse。实测写 `v=7` 读回来是 `v=1`，全程无报错。

`looseObject` 保留未知字段解决的是"字段丢失"，解决不了"**字段语义变了**"。旧代码按 v1 的理解读 v2 的数据，得到的是一个看起来正常、实际错误的状态。这与未知事件类型是同一类问题，处理方式必须一样：显式失败。

### ⑥ 写入路径无任何护栏 🟠

读取路径有校验、有 upcaster、有版本检查；写入路径是"手工拼一个对象字面量"，`v` 靠人记得填对。事件一旦落库就是永久的——`v` 写错会让日后的 upcaster 跑在错误的数据上，且要等到几个版本之后才暴露。

### ⑦ 会话级授权不进状态，回放不等价 🟠

`permission.decision(scope=session|always)` 只用来清空 `pendingPermission`，决定本身不落状态。于是"回放事件流得到的状态"≠"当时的真实状态"：一个授权过 `shell.exec` 的会话，回放出来看不出授权过。

在事件溯源系统里这是硬伤，而**安全决定恰恰是最不该丢的那部分**（审计要查、崩溃恢复要续、评测回放要复现）。

### ⑧ 三处扩展点在文档里存在、在代码里不存在 🟡

- `ToolSpec.available()`：docs/04 §4.3 的接口草案有它、ADR-0006 的派生约束提它、`ToolRegistry.descriptors()` 的注释提它——唯独 `ToolSpec` 上没有这个字段。于是 ADR-0007 的"Linux 上 computer 工具从模型视野消失"无法表达。
- `ToolContext.sessionId`：工具产出的事件、审计记录、子 Agent 派生都要挂在会话上，字段却不在。
- `ResultLimits` 只约束文本字节。截图不计入任何上限——M4 的浏览器自动化一次返回十几张截图是正常用法，"文本抠着算、图片随便塞"。

## 决策

### 安全边界

1. **引入路径规范化契约**。新增 `PATH_CAPABILITIES`（契约层）与 `normalizePathTarget()`（内核，纯词法）。对路径类能力，`evaluate()` 先规范化再匹配；**规范化失败直接 deny，不降级为 ask**——ask 的下一步是用户点"允许"。符号链接解析仍归运行时的能力网关（有文件系统才做得了），两层职责不重叠。

2. **红线参数化**：`redLineRules({ home, appRoot })`、`builtinRules(env)`。刻意做成**必填参数**而不是内置常量——内核零 I/O 拿不到 `homedir()`，就不该假装知道。忘了传编译不过，传错了红线测试会红。这是保证"红线里的路径和请求里的路径来自同一个坐标系"的唯一办法。

3. **glob 的 `/**` 结尾匹配目录自身**。朴素实现下 `/prod/**` 匹配不到 `/prod` 本身，而目录本身往往正是最该拦的目标（删目录 = 删掉它下面的一切）。

4. **Windows 大小写**：新增 `EvaluateInput.pathCaseInsensitive`，由知道平台的运行时显式传入。内核不猜平台（ADR-0007 禁 `process.platform`），但也不能装作 `C:/Windows` 和 `c:/windows` 是两个目录。

5. **补齐 `ask → deny`**，且让 `ask` 分支也过降级函数。

6. **L4 红线扩展到九组路径**：策略目录、权限契约、密钥契约、脱敏出口、`scripts/`、depcruise 配置、eslint 配置、githooks、CI workflow。

### 契约

7. **`restrictSessionPatch()`**：会话层不得触碰 `permission` 与 `providers`。两个调用点缺一不可——运行时写事件**前**调用，把 `rejected` 变成 notice 事件（符合"绝不静默"）；`reduce` 里**再过一次**，兜住历史数据与被篡改的库（reduce 发不了事件，只能静默丢弃）。

8. **`v > 当前版本` 抛错**，与未知事件类型同等对待。

9. **`createEvent()` 作为写入侧唯一入口**：`v` 从注册表取且**不接受调用方传入**，payload 当场校验，返回判别联合的精确分支。

10. **`SessionState.grants`**：记录 scope 超过 once 的权限决定，**allow 与 deny 都记**——只记允许，回放出的状态就偏松。

### 事件命名

11. **三个裸事件名补上前缀**：`usage` → `usage.recorded`、`notice` → `notice.posted`、`error` → `error.raised`。

    不是为了整齐。`ext.` 前缀机制、UI 按前缀订阅、策略按前缀匹配，全都建立在"每个事件名都有前缀"这个假设上——裸名是这套机制里的特例，而特例迟早会被某段按 `type.split('.')[0]` 分组的代码踩到。

    **代价窗口只有这一次**：目前没有任何数据落库，改名是纯文本替换；第一条事件写进 SQLite 之后，同样的改动就要配一个事件类型级的迁移。约定本身已固化成 `tests/registry.test.ts` 里的断言——只写在文档里的话，下一个加事件的人不会看到。

### 扩展点

12. 补 `ToolSpec.available()` + `ToolAvailabilityContext`（只含不随单次调用变化的事实，避免工具列表逐轮抖动导致 prompt cache 全失效）、`ToolContext.sessionId`、`ResultLimits.maxBlocks`（默认 4，超出的块丢弃并在**模型可见**的标记里说明丢了几个）。

## 后果

**正面**
- 四条失效的安全规则现在有 `tests/policy-redlines.test.ts` 按"攻击者会怎么拼这个字符串"来打，共 167 个测试全绿
- L4 自我修改的红线从"护住一个目录"变成"护住整条护栏链"，这是 M6 能开工的前提
- 契约包 6.72 kB（预算 15 kB），零依赖不变

**负面**
- `builtinRules` / `composeRules` 由常量变成函数，签名破坏性变更（当前无外部消费者，代价仅限本仓库）
- 规范化失败即 deny，意味着**运行时传错路径格式会立刻炸**。这是刻意的：宁可让配错的调用方当场暴露，也不要让它悄悄落到 ask
- `ask → deny` 会在"读过网页后立刻推代码"这类场景增加一次显式解除操作。ADR-0003 的重新评估触发条件（误触发率高到用户想关掉）继续适用

**重新评估的触发条件**
- 出现需要在内核里做符号链接解析的场景（说明规范化的层次划错了）
- `pathCaseInsensitive` 之外出现第二个平台差异渗进内核（说明该引入 `PlatformPort` 的抽象了）
- 会话级配置的禁用清单需要第三条（说明该反过来做成白名单）

## 沿用的纪律

ADR-0011 的那条在这次复审里第三次被证实，且这次的形态更隐蔽——**规则不仅可能"配了但没生效"，还可能"生效了但没长在攻击路径上"**（发现 ②）。

由此补一条：**安全规则的测试必须按"运行时真正会传进来的字符串"来写，而不是按"规则里写了什么"来写。** 用规则自己的字面量去测规则，测的是 `globMatch` 会不会用，不是红线会不会拦。
