# ADR-0025 · 敏感路径不许读：「读不改变状态」这句话在装上真实 fs.read 的那天就不成立了

- **状态**：🟢 Accepted（2026-08-07）
- **日期**：2026-08-07
- **相关**：落实 [docs/06 §3](../06-安全与权限模型.md) 默认策略里那条从未实现的 deny；依赖 [ADR-0023](./0023-权限规则的分层覆盖.md)（用户要有覆盖的出口）与 [ADR-0024](./0024-路径能力网关.md)（判定看到的路径必须是真实路径）；修正 [ADR-0003](./0003-默认权限策略.md) 中 `fs.read` 无条件放行的取舍

## 背景

`def.fs-read` 是无条件 allow，理由就写在规则上：

> `reason: '读取文件不改变任何状态'`

这句话在 M1-c 之前是**对的**，因为当时没有任何工具真的能读文件。M1-c 装上
`fs.read` / `fs.list` 的那一刻它变成了错的，而规则一个字没动。

读操作确实不改变磁盘。但它把内容**搬进了模型上下文**，而模型上下文会发给模型
服务商。对一个私钥来说，「被读到」和「被泄露」之间没有第二步。

docs/06 §3 从第一版起就列着这条：

```yaml
- { effect: deny, capability: fs.read, path: ["~/.ssh/**","~/.aws/**","**/.env*","~/Library/Keychains/**"] }
```

代码里**一条都没有**。M1-c 的计划里把它列为"本段不做"并写下"建议不晚于 M1-d"，
理由是 `web.fetch` 一上，"读到 + 发出去"就凑齐了一条完整链路。

本项目第 N 次「规则存在 ≠ 规则生效」，而这次程度更重一层：连规则都只存在于文档里。
前面几次至少代码里有个写错的东西，这次是一句话被读了很多遍、从没被实现过。

## 决策

### 一、挑选标准只有一条，写在代码里

> **这个文件的内容一旦进了模型上下文，就等于凭据已经泄露**，且拦掉它极少妨碍正经活儿。

这条标准是给后来加条目的人用的——没有它，这份清单会朝两个方向烂掉：要么越加越长
直到用户整体关掉它（红线一多等于全部失效，同一个道理），要么谁也不敢加。

按它判断的三个边界例子，一并记下来：

| | 判断 | 理由 |
|---|---|---|
| `**/*.pem` | **进** | EC2 密钥对就是这个后缀。误伤的是公开证书，读不到它的代价很小 |
| `**/*.key` | 不进 | 太多东西用这个后缀，误伤远大于收益 |
| `~/.bash_history` | 不进 | 里面**可能**有 token。"可能"不是这条标准说的"就是" |

### 二、是普通 deny，不是红线

红线不可覆盖。而"帮我看看这个项目的 `.env` 为什么没生效"是一个完全正当的请求。

放成普通 deny 之后，用户在自己的 `config.json` 里写一条 allow 就能放开某个路径
（分层覆盖，ADR-0023），而**模型自己写不了那个文件**——项目层只能收紧
（`tightenOnly`），用户级配置的写入要走 `saveUserConfig` 的构造期闸门。

红线留给"做了就回不来"。这里是"做了就泄露了"。两者的正确解法不同：

- 前者不给任何出口；
- 后者给一个**必须由用户显式打开**的出口。

给不出出口的安全措施，最后都会被整体关掉。

### 三、三个平台的路径全都写上，且不做平台判断

内核不知道自己跑在哪（ADR-0007 禁 `process.platform`）。
`~/Library/Keychains/**` 在 Linux 上永远匹配不到东西——这不是浪费，它是**零成本**的，
而少写它的代价是那个平台的凭据库整个敞着。

docs/06 原来那份清单是 macOS 视角的（只有 Keychains）。照着实现，
Windows 的 DPAPI 与 Linux 的 GNOME keyring 一条都不会有，而它们装的是同一批东西——
**包括小明自己的 API key**（ADR-0022 把它放进了操作系统钥匙串）。
所以这几条同时也是"模型不能把小明自己的密钥读出来"。

清单最终是 14 条家目录下的 + 6 条跟着项目走的，见
`packages/kernel/src/policy/defaults.ts` 的 `SENSITIVE_READ_UNDER_HOME` /
`SENSITIVE_READ_ANYWHERE`。

### 四、只挂 `fs.read`

**写入侧没做**，这是刻意的范围，不是遗漏。见下方遗留。

## 后果

- `fs.list` 声明的能力也是 `fs.read`，所以列 `~/.ssh` 同样被拦——不需要额外规则，
  这正是"红线按目标写、不按调用方自称在做什么写"（ADR-0014 那半个教训）的红利。
- YOLO 档跳不过它：YOLO 跳的是 ask，不是 deny（docs/09 C5 / ADR-0017 决策三）。
- 用户被拦时看到的 `reason` 里带着出口的说法（"在用户配置里对这个路径写一条 allow
  即可放开"）。一条只说"不行"的规则，用户的下一步是去关掉整个功能。

## 反向演练

| 演练 | 结果 |
|---|---|
| `builtinRules` 里去掉 `...sensitiveReadRules(env)` | 28 条转红 |
| 把这批规则改成 `immutable: true` | 3 条转红——**用户的出口是被用例钉住的，不是碰巧存在的** |
| 把 `effect` 从 `deny` 改成 `ask` | 27 条转红（含"用户根本没被问"与 YOLO 那两条） |

## 一个不能在本地证明的环节：大小写

macOS 与 Windows 的文件系统默认**大小写不敏感**——`~/.SSH/id_rsa` 打开的就是
`~/.ssh/id_rsa`。而规则匹配是字面的。两边各靠一个东西挡住：

- **Windows**：`pathCaseInsensitive`（`services.ts` 按 `platform.os` 传给 `evaluate`）；
- **macOS**：`realpath.native` 返回磁盘上真实的大小写，于是 `.SSH` 在进判定之前
  就已经变回 `.ssh`。**这一环我在本地证明不了**（开发机是 Linux，大小写敏感）。

所以 `gateway.test.ts` 里那条用例不写平台判断，写**文件系统的事实判断**：
换个大小写如果真能打开同一个文件，这个卷就是大小写不敏感的，网关就必须把它归回
真实大小写。Linux 上前提不成立、用例自证跳过；macOS / Windows 的 CI 上它是硬断言。

这个写法是 M1-c 那次 Windows 翻车的直接产物：**"我们有三平台 CI"不等于"我们测过
那个平台的语义"**——除非本地跑的那份用例，把该平台的前提也当成断言的一部分。

## 遗留

- **写入侧还敞着。** 往 `~/.ssh/authorized_keys` 追加一行是一条标准的持久化后门，
  而它现在只是 `def.fs-write` 的一个 ask——一个用户会顺手点掉的确认框。
  同理还有 `~/.bashrc`、`~/.zshrc`、`~/.config/autostart/**`、
  `~/Library/LaunchAgents/**`：这一批的共同形状是"写一次，之后每次开机/开终端都执行"。
  它与本 ADR 是同一个判断的两半，只是本轮的范围明确限于读取侧。
- **`env.read` 同样是无条件 allow。** `.env` 文件拦住了，`process.env` 没有——
  而 CI 环境、docker 容器里，凭据经常就在环境变量里。目前没有工具声明 `env.read`，
  所以它还是一条死规则；`shell.exec` 一上（M1-d），它就活了。
