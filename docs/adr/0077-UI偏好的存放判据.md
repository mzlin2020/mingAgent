# ADR-0077 · UI 偏好的存放判据：`localStorage` vs `config.json`

- **状态**：🟢 Accepted
- **日期**：2026-08-16
- **相关**：M3.5-b 起的第一批消费者；总纲 [12-桌面端界面与设置](../12-桌面端界面与设置.md) §5.3；
  不变量一（状态 = `reduce(events)`，[ADR-0015](./0015-进程与IPC边界.md)）；
  配置分层 [ADR-0023](./0023-权限规则的分层覆盖.md)

## 背景

M3.5 要持久化一批「纯界面」偏好：详情栏宽度、详情栏开关、主题档位、输入框 Enter 行为。
仓库里已有两条看起来能用的路：

- **事件流**。不变量一说「状态 = `reduce(events)`，不许有只写内存不写事件的状态」。
  字面读会把侧栏宽度也变成一条事件。
- **`config.json`**。配置分层、项目覆盖、权限判定都读它。把「侧栏宽度」塞进去，
  等于让一个纯视觉偏好参与 Agent 配置。

两条路都能「存下来」，但都会把一件不该进那一层的东西放进去。
本决策要的不是选一个存储 API，是**一道能不能进 `localStorage` 的判据**。

## 选项

### 选项 A：全部进事件流

- 优点：不变量一的字面最干净，重开会话 UI 也一致。
- 缺点：详情栏拖到多宽既不进模型请求，也不改变任何一次判定。
  为它落一条持久事件，是把「会话状态」的定义撑到「屏幕上的一切」。
  跨设备同步一条拖拽宽度没有产品意义，却会污染审计与回放。

### 选项 B：全部进 `config.json`

- 优点：已有加载器、已有分层、设置中心（e 段）反正要写配置。
- 缺点：`config.json` 会被项目层覆盖，也会被权限判定读到。
  「这个仓库的详情栏 400px」写进别人 clone 来的 `.xiaoming/config.json` 是错层。
  `tools.presentation` 那种**会改变模型看见什么**的字段必须进配置；宽度不是。

### 选项 C：`localStorage` + 一条否决判据（选定）

一项偏好能进 `localStorage`，当且仅当它**既不进模型请求、也不参与任何判定**。

- 优点：不变量一继续只约束会话状态；`config.json` 继续只住 Agent 配置。
- 缺点：多一处状态来源。判据本身要有人守——把 `tools.presentation` 误存进
  `localStorage` 不会有闸门变红，只会让重开会话后模型视野对不上。

## 决策

选 **C**。

**判据（可检验）**：问两句，任一句为「是」就不能进 `localStorage`：

1. 它会进入模型请求吗？（提示词、工具列表、可见工具集合）
2. 它会参与任何一次判定吗？（权限、红线、网关、呈现模式）

| 偏好 | 进哪 | 为什么 |
|---|---|---|
| 详情栏宽度 / 开关 | `localStorage`（`xm.ui.detailsWidth` / `xm.ui.detailsOpen`） | 两问都否。M3.5-b 落地 |
| 主题档位（跟随系统 / 浅 / 深） | `localStorage` | 两问都否。开关 UI 在 M3.5-e |
| 输入框 Enter 行为 | `localStorage` | 两问都否。开关 UI 在 M3.5-e |
| `tools.presentation` | **`config.json`** | 决定模型看得见哪些工具（ADR-0072） |
| `permission.rules` | **`config.json`** | 就是判定本身（ADR-0039） |
| 顶栏打开集合 `openIds` | **不持久化** | ADR-0037 已定：关 tab ≠ 删会话，打开集合是这一次窗口的 UI 态 |

读写失败（隐私模式、配额）吞掉，回默认值。不把存储异常抬成会话错误——
它不是会话状态，失败不该打断对话。

自动关闭详情栏**不是**一次偏好写入（ADR-0074 决策二）。
`localStorage` 里的宽度与开关只反映用户拖过、点过的值。

## 后果

**正面**

- 不变量一不被「侧栏多宽」稀释；`config.json` 不被视觉偏好污染。
- 第一批消费者（详情栏）在 M3.5-b 就能用，不必等设置中心。

**负面（必须写）**

- 多一处状态来源。判据没有自动化闸门——把不该进的字段写进 `localStorage`
  不会在 `pnpm verify` 里变红。缓解：本 ADR 的表是闭集，新开一行必须改这份文件。
- `localStorage` 不跨设备、会被用户清站点数据。可接受：这些偏好丢了只是回默认。
- 主题档位与 Enter 行为的键名要到 e 段才登记进上表的实现，本段不提前占位。

**什么条件下重新评估**

- 出现第三种「既像配置又像偏好」的字段，两问答不清。那时先写新 ADR，不许默默加键。
- 若将来要做多窗口且各窗口详情栏宽度必须一致，再议是否提升到用户级配置；
  即便提升，也不得进事件流。
