## 二、验收

- 设置是模态，Esc / 遮罩关闭；打开时焦点在关闭按钮，关掉后回到打开它的控件。
- 六节齐：通用、模型与 Provider、工具与呈现、权限、数据与存储、关于与安全边界。
  没有 MCP / Skill / 插件空节。
- `code` 档旁边写明：模型直接点名别的工具会得到「未知工具」，不是被拒绝。

- 红线清单来自 `projectRedLines(redLineRules())`，不再用 `protectedResources` 那四行散文。

## 三、反向演练，逐条看它红过一次

闸门在主进程 `ipc.ts` 的 `handle()`：Zod 不过就返回 `{ ok:false, code:'invalid_input' }`，
`services.updateSettings` **不会被叫到**。渲染层藏不藏按钮无关。

| # | 构造 | 实际报错 |
|---|---|---|
| 1 | `permissionDenies[].effect: 'allow'` | `IPC 入参不合法：Invalid input: expected "deny"` |
| 2 | 顶层 `apiKey: 'sk-secret'` | `IPC 入参不合法：Unrecognized key: "apiKey"` |
| 2b | `providers[0].apiKey`（嵌套） | `IPC 入参不合法：Unrecognized key: "apiKey"` |
| 3 | `workspace.mode: 'nope'` | `IPC 入参不合法：Invalid option: expected one of "choose"\|"fixed"\|"home"` |

第 2 条拆成顶层和嵌套各一次：`strictObject` 只挡本层，Provider 条目也必须是没有密钥字段的窄对象，
否则「把 key 放进 providers 里」会从门缝滑进去。

前置（ADR-0076）：旧 `config.json` 残留 `logging: { level: '随便写的级别', redact: false }`
**不**让整份配置退回默认；下次写入时这个键被剥掉。证据在
`packages/platform/tests/config.test.ts`。
