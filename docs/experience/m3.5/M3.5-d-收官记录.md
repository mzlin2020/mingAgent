## 一、交付了什么

| 层 | 落点 |
|---|---|
| 纯函数 | `lib/call-material.ts`：`lookupCallMaterial` / `childDispatches` / `nextDetailsTab` / `detailsScrollHost` |
| 子调用投影 | `shared/code-dispatch.ts` 的 `CodeDispatchView`：**显式没有 `forModel`**。`toDispatchView` 只抄审计字段 |
| 打开会话 | `readSession` 增加必填 `dispatches`。与 `extRecords` 同一次 `runtime.read({ types })`，不进 `SessionState` |
| 增量 | `details-slice.ts` 的 `mergeDispatch`：`applyEvent` 碰到 `tool.code.dispatch` 补进 Map |
| 对话流 | 父工具行展开后按 `parentCallId` 挂 `DispatchRow`。源码仍不出现任何内建工具名 |
| 右栏 | `workbench-panel.tsx` 两个 tab；内容用 `hidden` 切可见性，不按 tab / collapsed 卸载 |
| 样式 | `.details-code`：组件层 r12 / pad16 / mono 13-22；`.panel-tab` 与顶栏 tab 同字号 |

模型发起的调用：入参 / 结果都在 `reduce()` 出来的 `messages` 里（`tool_use` / `tool_result`），
与 ADR-0065「由 callId 反查」查的是同一份状态。

子调用：`reduce()` 对 `tool.code.dispatch` 只推进 `lastSeq`（ADR-0072），所以不能靠 SessionState。
打开会话走 ADR-0057 已经开过的「按类型过滤读」；之后的增量跟着事件走。这不是新数据源，
是事件流上已有的审计记录第一次被详情栏读到。

## 二、验收

- 点工具行 → 选中、切到详情 tab；右栏若关着会打开（`shouldOpenDetailsOnSelect`）。
- 无选中时 `nextDetailsTab` 落在工作区；同一选中下用户点「工作区」会留在工作区。
- 工作区四块仍是 `TodoPanel` / `LiveCalls` / `TerminalPanel` / `CheckpointPanel`。
- 渲染层不认识具体工具：`dispatch-row.tsx` / `details-view.tsx` 加入工具名源码闸门。
- 📌 **待补**：真机点工具行、点子调用、关栏再开保住滚动的截屏。与 a/b/c 同一笔欠账。

## 三、反向演练，逐条看它红过一次

| # | 构造 | 实际报错 |
|---|---|---|
| 1 | `detailsScrollHost(true)` 改成返回 `'gone'`（关闭即卸载） | `expected 'gone' to be 'mounted'` |
| 2 | `toDispatchView` 把入参上的 `forModel` 抄进返回值 | `expected { …(8) } to not have property "forModel"`（Received 里是 `SECRET_BODY`） |

第 1 条实测日期 2026-08-16：期望写的是字面量 `'mounted'`，不是「跟函数返回值比」——
函数被改成随 collapsed 变身份时，期望不会跟着漂。

第 2 条是**确认设计**（阶段划分原文）：payload 里没有 `forModel` 的位置，投影再抄一份也
必须被剥掉。详情 Output 因此结构性地只能是「已执行 / 失败原因」，并写明「不是数据缺失」。
有人若给 `tool.code.dispatch` 加 `forModel`「把详情补全」，会同时撞上 ADR-0072 与这条用例。

1. 消息仍来自 `reduce(events)`；`selectedCallId` 是纯 UI 态；`dispatches` 是事件投影，切会话即丢。
2. 渲染层不认识任何具体工具：子调用靠 `parentCallId` 挂到父行，不判断工具名。
3. preload 未增通用入口；`readSession` 只多一个只出不进的投影字段。
4. `ALLOWLIST` 未增行。`store.ts` 391 行，未破 400。
