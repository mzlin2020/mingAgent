## 二、这次到底改了什么

一句话：**工具第一次能把结构交给程序，而不是把结构渲染成中文再让程序去认。**

三分从此写进契约：

| 字段 | 给谁 | 落不落库 |
|---|---|---|
| `forModel` | 模型 | 落 |
| `presentation` | 回放期卡片投影 | 落 |
| `output` | **程序** | **不落** |

"不落库"是这份 ADR 里唯一可能被后来者顺手改掉的决定，所以理由写在了三个地方
（契约注释、ADR §二、用例名）：规范值与另两个字段大量重复且体积不受控
（`fs.read` 的规范值带着文件正文），落库就是把同一份内容存两遍——
ADR-0050 与 ADR-0070 已经在这个形状上修过两次。

## 三、迁移过程本身抓到的四处"结构上说不出话"

这是这批工作真正的收获——它们不是为了 Code Mode 才有价值：

1. **`fs.list` 的大小**以前是渲染好的字符串，`"（读不到大小）"` 与 `"0 B"` 在结构上
   无从分辨。现在是 `size?: number`，**缺席就是读不到**——而这正是那个函数原本的注释
   （"不要显示一个编的大小"）想表达但表达不了的东西。
2. **`shell.exec` 的六种结局**以前只存在于那句中文开头语里（"超时，已连同…"、
   "输出超过 256 KB 上限"…）。现在是闭集 `kind`，且 `exitCode` **缺席不等于 0**：
   被信号杀掉、被截断中止、根本没起来都没有退出码，而散文里的 `?? -1`
   会让人把"没跑成"读成"跑失败了"。
3. **两条搜索实现**（ripgrep 与纯 Node 退路）各自把位置拼成 `path:line:col: 文本`。
   现在位置是结构，字符串由共用的 `formatHit()` 现拼。这条不只是好看：
   **Windows 绝对路径自带冒号**，从那种字符串里切行号是一件看起来能做、实际会错的事。
4. **`git` 那一族的信封**以前是 `Record<string, unknown>`，`kind` 那一列的十个取值
   靠口口相传。现在是闭集。

顺带修掉一处旧漏：`generate-docs` 的 `allTools()` 不传 `index`，于是
`search.symbol` / `search.indexed` 两个**真实工具**从来没进过那张"全部内建工具"的目录。
工具数 20 → 22。

## 四、差点漏掉的那个静默失配

`search.symbol` / `search.indexed` 在索引不可用时退到 `search.text`，做法是把内层工具的
`ToolProgress` 改一改再 yield 出去。规范值加上之后，那条路会把**内层的规范值**原样透传——
而两者形状不同。

后果不是报错：`parseOutput` 按失败关闭把它丢掉，模型照常拿到结果，程序拿到 `undefined`，
日志里什么也没有。现在 `fallback()` 显式把内层的 `hits` 翻译进外层形状。

写进 ADR 附录是因为**这类失配在每一处"包一层别的工具"的地方都会重现**，
M3-h 的子调用尤其。

同一个理由让 `pty-tools.ts` 里写了两个具名构造器（`openResult` / `sessionResult`），
而不是一个收 `unknown` 的通用构造器——静默丢弃只能在编译期拦。

## 五、反向演练

两条新护栏，都先看它红过一次：

1. **拿掉 `fs.write` 的 `outputSchema`** → `generate-docs --check` 红：
   `这些内建工具没有声明 outputSchema：fs.write。`
2. **把 `output` 写进 `tool.end`** → "规范值不落库"那条用例红：
   `expected '[{"id":...' not to contain '仅规范值可见-9f3c'`。

第 2 条的**形状**值得单记：断言不是"`tool.end` 的 payload 里没有 output 字段"，
而是**整份事件流的 JSON 里搜不到那个只出现在规范值里的哨兵字符串**。
前者换个字段名就绕过去了，后者绕不过去。同一条用例里还反过来断言了
"事件流里确实有模型可见的那句话"——否则一个空事件流也能让它通过。
