# H2 隔离机制验证记录 · Code Mode 的客体域

> 日期：2026-08-15
> 结论：✅ H2 定案为 **QuickJS-WASM 客体域 + worker 线程**，决策见
> [ADR-0069](../../adr/0069-CodeMode的隔离机制.md)。原倾向（独立子进程 + Node permission
> model）在实测中被证伪：它挡得住文件与子进程，**完全挡不住网络**。

本文只记实测数据。所有数字来自 2026-08-15 的本机（Linux，Node v22.23.2，
Electron 43.3.0 内置 Node 24.18.1），可执行的那部分固化在
`evals/spikes/h2-code-runtime-isolation.test.ts`，随 `pnpm test` 跑。

---

## 一、为什么否掉原倾向：Node permission model 不管网络

`node --permission`，不给任何 `--allow-*`：

| 探针 | 结果 |
|---|---|
| `fs.readFileSync('/etc/hostname')` | `ERR_ACCESS_DENIED` ✅ |
| `child_process.execSync('echo hi')` | `ERR_ACCESS_DENIED` ✅ |
| `net.createConnection('127.0.0.1:9')` | **允许**——拿到 `ECONNREFUSED`，说明 connect(2) 真的发出去了 ❌ |
| `fetch('https://registry.npmjs.org/-/ping')` | **HTTP 200，真的出网了** ❌ |
| `import('node:net')` / `import('node:dns')` | 模块照常加载 ❌ |

Node 的权限模型没有网络这一档，也没有开关能补上。

这条为什么是决定性的：程序可以先用工具读一个文件——那一步有闸门、有 `tool.start` /
`tool.end` 事件、有污点传播——然后**裸 `fetch` 把内容发出去**，这一步没有闸门、没有事件、
不经过 [ADR-0028](../../adr/0028-web.fetch的IP级SSRF判定与DNS重绑定防护.md) 的 IP 级判定。
一次完整的外泄，审计里只看得见"读了个文件"。

顺带确认了两件事，免得后来者以为是"跑不起来"才换的方案：

- **Electron 认这个 flag。** `ELECTRON_RUN_AS_NODE=1 electron --permission` 下
  `fs` 同样是 `ERR_ACCESS_DENIED`（`process.versions.node = 24.18.1`）。
  原方案不是不可行，是**挡错了地方**。
- `--experimental-permission` 这个旧名在 Electron 43 上是 `bad option`，别照旧文档写。

## 二、客体域的全局面（QuickJS 0.32.0 / wasmfile-release-asyncify）

`Object.getOwnPropertyNames(globalThis)` 在客体域里的**完整**结果，62 个名字：

```
AggregateError Array ArrayBuffer BigInt BigInt64Array BigUint64Array Boolean DataView Date
Error EvalError FinalizationRegistry Float16Array Float32Array Float64Array Function Infinity
Int16Array Int32Array Int8Array InternalError Iterator JSON Map Math NaN Number Object Promise
Proxy RangeError ReferenceError Reflect RegExp Set SharedArrayBuffer String Symbol SyntaxError
TypeError URIError Uint16Array Uint32Array Uint8Array Uint8ClampedArray WeakMap WeakRef WeakSet
decodeURI decodeURIComponent encodeURI encodeURIComponent escape eval globalThis isFinite isNaN
parseFloat parseInt undefined unescape
```

清一色 ECMAScript 内建。`require` / `process` / `fetch` / `XMLHttpRequest` / `WebAssembly` /
`std` / `os` / `setTimeout` / `console` **一个都没有**。

用例里这张表是按"**允许存在什么**"写的，不是按"不允许存在什么"写的——后者会漏，
因为写清单的人想不到 `std`。QuickJS 升级后多出任何一个名字，闸门都会红，由人来判断。

四条穿透探针（**两个世界共用同一段源码**）：

| 探针 | QuickJS 客体域 | 朴素 Node worker |
|---|---|---|
| `require('node:fs')` | 拿不到 | **拿到了** |
| `typeof process` | 拿不到 | **拿到了** |
| `typeof fetch` | 拿不到 | **拿到了** |
| `Function('return process')()` | 拿不到 | **拿到了** |

右边这一列就是反向演练：把提供者换成朴素 worker，"全部拿不到"那条断言当场变红，
四个字段一个不落地翻成"拿到了"。没有这一列，左边那一列只是一句无法证伪的断言。

`import()` 三种写法（`node:child_process` / `node:fs` / `fs`）全部拒绝，
理由统一是 `could not load module '…'`——客体域根本没装模块加载器。

## 三、必须写给 M3-h 的四条实测结论

**一、客体域自带 `Date` 与 `Math.random`。** 它们是 ECMAScript 内建、不是宿主 API，
客体域挡不住，也不该挡。但这意味着 Code Mode 若不在装载绑定时把它们换成
`ctx.clock` / `ctx.ids` 的投影（[ADR-0066](../../adr/0066-时钟与ID的注入.md)），
就是确定性闸门上的一个洞——`pnpm check:determinism` 扫的是仓库源码，
扫不到模型现写的一段程序。实测覆盖是可行的：赋值 `Date.now` / `Math.random` 后立即生效。

**二、绑定在客体域里是同步形态。** asyncify 把宿主那侧的 `async` 折叠掉，程序写
`const a = callTool(...)`，不写 `await`。50 次连调稳定。

`await` 那条路**实测不可靠**：module 模式下串行两次 `await` 会让程序静默半途而废，
随后在 wasm 层抛 `null function or function signature mismatch`。
所以 [ADR-0061](../../adr/0061-CodeMode与工具SDK生成.md) §五 那句"把每个可见工具生成成一个
**TS 异步函数**"要按这个事实改写：**SDK 生成同步签名**。

**三、interrupt handler 是 CPU 预算，不是墙钟预算。** 程序停在一个永不 settle 的 promise 上时，
客体域里没有任何字节码在跑，interrupt handler 被问一次之后再也不会被问到，而求值调用早已返回。
`run_code` 因此**必须另有一个宿主侧的墙钟截止时间**，把"到点仍未完成"判成失败。
只靠 interrupt handler 会漏掉这一整类——而且漏得很安静。

**四、一个程序一个 WASM 模块。** 内存上限在"已经有别的 runtime 用过"的模块上不再生效，
实测直接把宿主的 V8 堆撑到 2 GB 崩掉。别为了省那 21 ms 去复用模块。

## 四、成本基线

给 [ADR-0061](../../adr/0061-CodeMode与工具SDK生成.md) 的"重新评估条件"留一个量化起点：

| 项 | 实测 |
|---|---|
| WASM 模块首次加载 | 21 ms |
| realm 冷启动（20 次均值） | 2.25 ms |
| 绑定往返（200 次） | 40 ms，单次 **0.20 ms** |
| 客体域字符串处理 vs 宿主 V8 | 137 ms vs 9 ms（**15.2×**），结果一致 |
| TS 6 编译器 API 首次加载 | 778 ms（惰性，且应当在 worker 里付） |
| `ts.transpileModule` 剥类型 | 43 ms |

单次绑定往返 0.20 ms，相对一次模型往返（秒级）可以忽略——Code Mode 的收益来自省掉往返，
这个开销吃不掉它。**15.2× 是要记住的那个数**：客体域适合编排，不适合重计算。
真需要算，就调工具让宿主算。

预算机制两条都实测有效：`setInterruptHandler` 在 300 ms 处打断死循环（`InternalError:
interrupted`，实际 305 ms 返回）；`setMemoryLimit(1 MB)` 让一次大分配失败为
`InternalError: out of memory`，宿主毫发无伤。

## 五、依赖

`quickjs-emscripten-core@0.32.0` + `@jitl/quickjs-wasmfile-release-asyncify@0.32.0`
（MIT，纯 JS + 一个 `.wasm`，无 `install`/`postinstall` 脚本，所以
`pnpm-workspace.yaml` 的 `allowBuilds` 不需要动）。目前是**根 devDependency**——
本批只交付验证，不建 `@xm/code-runtime` 包。

**不装** umbrella 包 `quickjs-emscripten`：它会一次拖进四个变体（debug/release ×
sync/asyncify），而我们只用一个。

打包时要注意：`wasmfile` 变体带一个独立的 `.wasm` 文件，进 asar 之后加载器拿到的不是真实路径——
与 `better-sqlite3` 和 tree-sitter 同一个坑，`electron-builder.yml` 的 `asarUnpack` 到时要加一行。
这件事留给 M3-h，因为现在还没有任何产品代码引用它。

## 六、这次踩到的、值得记一笔的

**第一版把"并发绑定调用"写成了"打不了"，还配了一整段分析。** 现象是：两次宿主调用都真的
发生了、没有任何报错，程序却停在 pending、最后一行永不执行。补上一句
`executePendingJobs()` 之后它立刻变成 fulfilled，结果完全正确。

差一点就把一条"宿主忘了 drain job queue"写成"这个机制不支持并发"，还会顺手在 ADR 里
留下一条编造出来的架构约束。留这一笔是因为**它在日志里不留任何痕迹**——没有异常、
没有超时、没有告警，只有一个安静地没跑完的程序。M3-h 会正面撞上同一个坑。
