## 1. 交付边界

- 在 `@xm/kernel/src/container/` 落地服务、插件、效果、类型化事件与作用域五个概念；
  生产代码保持纯逻辑、零 I/O、零 `node:*`，全部文件小于 400 行。
- 四种事件派发模式已实现：同步 `emit`、有序 `serial`、可短路且可取消的异步 `waterfall`、
  全部结算后聚合错误的 `parallel`。监听器错误保留原始对象，不静默吞掉。
- 插件按 `inject` / `provide` 做固定点装配；缺失提供者、声明与实际提供不一致、同层冲突、
  依赖环和中途启动失败均失败关闭并回滚已生效的效果。
- `ctx.fork()` 采用“根层 + 自己”的两级扁平解析，同时保留所有权树的级联清理；
  该决策由 [ADR-0067](../../adr/0067-子Agent作用域的两级扁平语义.md) 固化。
- kernel 提供确定性 `clock` / `ids`，platform 提供保持现有行为的 local 实现；
  runtime 中 M0–M2 遗留的时间与 ID 直调由 `check-determinism-boundary.mjs` 冻结，M3-b 迁移后归零。
- 插件显式服务声明与装配收敛规则由
  [ADR-0068](../../adr/0068-插件服务声明与装配收敛.md) 固化。

本段刻意没有接入 runtime / desktop，没有新增 profile、`@xm/compose`、`@xm/tool-runtime`、
回合扩展点、执行收据或渲染器。现有用户行为与事件流不变。
