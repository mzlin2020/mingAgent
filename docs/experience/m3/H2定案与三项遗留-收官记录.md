## 一、H2 定案

**QuickJS-WASM 客体域 + worker 线程。** 详细数据见
[H2 隔离机制验证记录](./H2-隔离机制验证记录.md)，这里只记决策链条。

先去实测了文档里写着的倾向（独立子进程 + Node permission model），结论是它兑现不了
ADR-0061 §一 的承诺：

```
node --permission（零 allow flag）
  fs / child_process → ERR_ACCESS_DENIED   ✅
  net.createConnection → 允许（connect 真发出去了）❌
  fetch('https://registry.npmjs.org/-/ping') → 200  ❌
```

**Node 的权限模型没有网络这一档。** 而这恰好是这里最该防的一格：程序可以用工具读文件
（有闸门、有事件、有污点），再裸 `fetch` 发出去（什么都没有，还绕开 ADR-0028 的 IP 级判定）。

顺带确认 Electron 43 在 `ELECTRON_RUN_AS_NODE` 下**认** `--permission`——
**否掉它不是因为跑不起来，是因为它挡错了地方。** 这一句写进 ADR，免得后来者以为
"当时环境不支持"，回头又把它捡起来。

选中的机制是 deny-by-default 的**结构性**隔离：客体域全局面只有 62 个 ECMAScript 内建，
`require` / `process` / `fetch` / `std` / `os` 一个都没有。断言按"**允许存在什么**"写，
不按"不允许存在什么"写——后者会漏，因为写清单的人想不到 `std`。

**验收当场兑现**：ADR-0061 §一 自己写着"选完必须看它红一次"。
把提供者换成朴素 Node worker 跑**同一段探针**，四个字段一个不落地翻成"拿到了"：

```
- "fetch": "拿不到"        + "fetch": "拿到了"
- "functionCtor": "拿不到"  + "functionCtor": "拿到了"
- "process": "拿不到"       + "process": "拿到了"
- "require": "拿不到"       + "require": "拿到了"
```

只写 ADR 不验证的话，ADR-0069 就和降级前的 ADR-0061 处在同一个位置上。

### spike 里翻出来的四条实测结论

它们全部写进了 ADR-0069 §三，M3-h 必须遵守：

1. **客体域自带 `Date` 与 `Math.random`**（语言内建，挡不住也不该挡）→
   宿主必须显式覆盖成 `ctx.clock` / `ctx.ids` 的投影，否则 Code Mode 是确定性闸门上的一个洞。
2. **绑定是同步形态**，asyncify 把宿主那侧的 `async` 折叠掉 → ADR-0061 §五
   "生成成一个 TS 异步函数"要改成**同步签名**；`await` 那条路实测会让程序静默半途而废
   并在 wasm 层崩。
3. **interrupt handler 是 CPU 预算，不是墙钟预算** → 程序停在永不 settle 的 promise 上时
   它一次都不会再被问到，`run_code` 必须另设宿主侧截止时间。
4. **一个程序一个 WASM 模块** → 内存上限在被别的 runtime 用过的模块上不再生效，
   实测把宿主 V8 堆撑到 2 GB。

## 二、会话状态副表有界化（ADR-0070）

`presentations` 与 `editProposals` 过去只增不删，`context.compacted` 不碰它们，
而它们整份跟着 `readSession` 过 IPC、整份进快照。问题不在条数在**体积**：
一份改三个文件的提案带三段完整 diff 加全部替换文本，可以比产生它的那条消息大一个量级。
与已经修过一次的 G4/G5 是同一个形状。

- `presentations`：留 256，按插入顺序淘汰最旧；缺失时走 **ADR-0058 本来就有的**通用卡片降级。
- `editProposals`：留 64，**优先淘汰终态**；被淘汰后再引用命中 `edit.apply` 里已有的
  "找不到当前会话中的编辑提案"——复用一条已经测过的失败路径，不新增错误语义。
- 实现落在新文件 `packages/kernel/src/state/bounded-index.ts`：`reduce.ts` 当时 394/400 行，
  规模纪律要求拆分不是豁免。

**必测的那一条**是快照一致性：淘汰按插入顺序做，所以"从快照 + 尾部回放"必须与
"全量回放"给出同一张表。这是这次改动唯一可能引入静默不一致的地方。

## 三、离线不变量扫描器

兑现 M3-g 收官记录里那条遗留（"不变量只跑在写入路径上，历史库里已存在的违例查不出来，
要查得单写一个离线扫描器"）。

判断逻辑在 `@xm/runtime` 的 `scanAllSessions()`，CLI 是 `pnpm scan:invariants`。
**它自己不写任何判断**——回放一遍，把 `{ event, before, after }` 原样交给同一个注册表。
与写入路径唯一的差别是**不抛**：离线扫历史库停在第一条毫无用处。

**它是诊断不是闸门**（不进 `verify` 的失败判定），所以配了三条用例替它跑：真 SQLite 脏库里
两处违例连 seq 一起被捞出来、干净库零违例、遇到违例不中断后续会话。

顺带确认一件事：**"seq 空洞"在真库上根本造不出来**——`SqliteEventStore.append()`
自己校验 seq 连续。所以扫描器的价值域是**载荷层面的失配**（谁跟谁配对、谁在谁之前）。

## 四、H5 与 C2 的边界澄清（纯文档）

- **H5**：写明 **Code Mode 不构成第二个执行世界**，因此不触发"未定案前不得实现第二个执行世界
  提供者"那道门槛。`run_code` 的客体域自己碰不到文件系统，程序里每一次工具调用都回到宿主、
  经 `ctx.executor` 的 local 提供者执行，判定与执行仍在同一个命名空间。
  不写这句，下一个人很容易因为"隔离"两个字把 M3-h 也当成被 H5 挡着。
- **C2**：把"Node 权限模型不管网络"的实测结论转记进去。将来做"沙箱模式开关"或
  "不可信来源代码自动切容器执行器"时，别把 `--permission` 当网络边界用。

## 五、这次踩到的两个坑，都是"反向演练本身失效"

**一、有界化的反向演练第一次没跑起来。** 用例里的循环条数是从上界常量算的
（`for (i < PRESENTATION_LIMIT + 40)`），于是把上界调大之后测试自己跑到内存耗尽——
**那不叫红，那叫没跑**。改成写死条数（296 / 74）之后三条淘汰用例才真的红：
`expected 296 to be 100000`、`expected 74 to be 100000`、`expected 69 to be 100000`。

**二、spike 差点把一条编造的架构约束写进 ADR。** 第一版"并发绑定调用"的用例现象是：
两次宿主调用都真的发生了、没有任何报错，程序却停在 pending、最后一行永不执行。
我据此写了一整段"这个机制不支持并发、并发要归宿主"的分析——补上一句
`executePendingJobs()` 之后它立刻 fulfilled，结果完全正确。

差别在于：那不是机制的限制，是**宿主忘了 drain job queue**。
留这一笔是因为它在日志里不留任何痕迹——没有异常、没有超时、没有告警，
只有一个安静地没跑完的程序。M3-h 会正面撞上同一个坑。
