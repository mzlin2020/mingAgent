# 体验测试归档

> 聚拢小明各里程碑 / 版本的**体验测试用例**与**体验报告**。  
> 自动化单元测试与 headless 冒烟仍在仓库根的 `pnpm verify` / `evals/`；本目录只收「真人驱动的端到端体验」产物。

## 目录约定

```
docs/experience/
  README.md                 ← 本索引
  m1/                       ← 按里程碑分册（后续 m2/、m3/ …）
    测试方案.md             ← 该版本用例与执行协议
    体验报告.md             ← 跑完后的详细体验报告（完成后落盘）
  m2/                       ← 示例：下一版本新建同结构
    ...
```

规则：

1. **一里程碑一子目录**，目录名用小写里程碑号（`m1`、`m2`…）；若同里程碑多轮复测，可再加日期后缀（如 `m1-2026-08-09`）。
2. 每个子目录至少两份核心文档：`测试方案.md`、`体验报告.md`。
3. 沙箱产物（小明实际写出的文件）仍放在 `~/Desktop/test/_e2e/`，不进本仓库；报告正文与结论必须沉淀到本目录，便于版本对比与优化跟踪。
4. 旧轮次只增不改；修正结论时新开一轮目录或在报告末追加「勘误」节。
