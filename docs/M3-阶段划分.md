# M3 · 阶段划分（微内核化重构）

> **状态（2026-08-14）**：规划完成，尚未开工。总纲见 [11-微内核与插件容器](./11-微内核与插件容器.md)，
> 十份决策见 [ADR-0052 ~ 0061](./adr/README.md)。
>
> **总目标**：把「一切皆插件」这条从 M0 就写下、但从未被落实的原则变成可执行的机制，
> 同时**不削弱**M0–M2 攒下的安全底座。每个阶段结束时仓库都必须处于可运行、可单独验收的状态。

## 1. 拆分原则

1. **一次只实现一个阶段。** 当前阶段通过验收并更新文档后，才开始下一阶段。沿用 M2 的纪律。
2. **行为等价优先于结构优雅。** M3-b 与 M3-c 是搬家，不是重写：同一输入跑出的事件流
   要与迁移前**逐条对齐**。想顺手改进的，记下来放到迁移完成之后。
3. **安全底座只增不减。** 任何一段结束时，[ADR-0053](./adr/0053-微内核的特权底座与扩展点边界.md)
   的六项底座必须仍然不可绕过。做不到就停在这一段。
4. **每段可停。** M3-a 之后的任何一段都可以是终点。停在哪一段，仓库都是可发布的。
5. **不恢复第二套权限系统。** 沿用 ADR-0039 的 `allow | deny`。参考实现的 `ask`
   与审批接缝不得随插件化一并搬入。
6. **架构决定先写 ADR。** 十份 ADR 已定案；实施中若需偏离，先补 ADR 再改代码。

所有阶段共同的基础门槛（与 M2 一致）：

- 开始前记录当前 `pnpm verify` 基线；结束时再次全量通过。
- 新机制至少包含确定性单元测试、跨层集成测试，以及一个与实际使用入口一致的 smoke。
- **护栏类改动必须先做反向演练**，证明缺少护栏时测试确实会红。本里程碑的护栏改动密度
  高于以往，这条格外要紧。
- 真实失败进入 `evals/regression/`；阶段材料归档到 `docs/experience/m3/`。

## 2. 阶段总览

| 阶段 | 独立交付 | 主要依赖 | 单独验收入口 |
|---|---|---|---|
| **M3-a · 容器与效果** | `@xm/kernel/src/container/` 落地，现有代码零改动、行为零变化 | 无 | 容器自身用例；卸载插件后注册物全部消失 |
| **M3-b · 装配迁移** | `services.ts` → profile 插件树；desktop 与 headless 共用一条装配路径 | M3-a | 同输入的事件流快照与迁移前逐条对齐；删掉业务行仍能启动 |
| **M3-c · 驱动器扩展点化** | checkpoint / 截断 / 上下文预算 / 上限兜底全部变插件，`turn.ts` 只剩驱动 | M3-b | 恶意监听器试图翻案红线被 guard 拦下；行为快照不变 |
| **M3-d · Agent 句柄与 Inbox** | `followup` / `steer` / `inject` 三入口；回合中可排队与纠偏 | M3-c | 注入落库并在重开会话后仍可见；空闲 Agent 不被 `inject` 唤醒 |
| **M3-e · 能力接缝与执行世界** | `ctx.executor` 接缝完整，local 提供者行为与今天一致 | M3-b | 换一个假提供者，全部 fs/shell/pty 工具跟着换，无绕过 |
| **M3-f · 渲染意图** | 新增工具不改渲染层即可出卡片；`edit-review` 专用通道退役 | M3-c | 真实旧库回放不崩；M2-e 全套用例仍绿 |
| **M3-g · 扩展事件与自省闸门** | `ext.*` 通道 + 不变量注册表 + 五张生成表进 `pnpm verify` | M3-d | 文档漂移一处闸门必红；伪不变量被脚本拒收 |
| **M3-h · Code Mode** | 一段程序连调三个工具，往返 3 次降到 1 次 | M3-e、M3-f | 程序内撞红线的调用被拒且理由一致；worker 死循环不拖垮主循环 |

依赖表示"复用已完成能力"，不表示必须合并实现。

**推荐顺序即上表顺序**，但 M3-e 与 M3-f 之间没有硬依赖，可按 M2 收官记录里的真实痛点调序。

## 3. 各阶段范围

### M3-a · 容器与效果

**做什么**

- 在 `@xm/kernel/src/container/` 实现五个概念：服务、插件、效果、类型化事件、作用域。
- 四种派发模式，`waterfall` 的 `next()` 语义与参考实现一字不差。
- `inject` 依赖解析；装配收敛时若仍有插件在等待，**报错并列出等待链**。
- 前置：补齐 M2 验收留痕（见 [M2 收官记录](./experience/m2/收官记录.md)）。

**不做什么**

- 不接任何现有代码。本段结束时容器是一个没有消费者的纯逻辑模块。
- 不做 HMR、不做 `!!js` 配置表达式、不做完整 fiber 生命周期。

**验收**：容器用例全绿；`pnpm verify` 全绿；文件全部在 400 行以内（拆分而非豁免）。

**反向演练**

1. 插件卸载后其注册的工具 / 监听器 / 提示词段**必须**全部消失——漏撤销一处就要红。
2. 一个插件 `inject` 一个永不出现的服务 → 装配期报错并指名，**不许静默挂起**。
3. 构造依赖环 → 报错并打印环路。
4. `waterfall` 监听器不调 `next()` → 后续监听器确实不执行。

### M3-b · 装配迁移

**做什么**

- 新增 `@xm/compose`：profile 解析、patch 合并、内建 profile、装配期断言。
- 把 `services.ts` 拆成插件行；desktop 与 headless 共用同一条装配路径。
- 基线层标记与断言落地（[ADR-0053](./adr/0053-微内核的特权底座与扩展点边界.md) 六项）。
- `--dump-config`：打印实际装配的行，密钥经 `redact()`。
- depcruise 新增两条规则。

**不做什么**

- **不改任何业务行为。** 这一段是搬家。
- 不做 `cli` profile 的产品化（新 M4），M3 只保证它能跑通。
- 不做可分发 bundle 格式（新 M4）。

**验收**：同一输入在迁移前后跑出的**事件流快照逐条一致**；删掉全部业务行后应用仍启动、
工具列表为空、UI 有明确提示；headless 冒烟仍在 `pnpm verify` 里。

**反向演练**

1. patch 试图删除或替换 `baseline.*` 任一行 → 拒绝启动。
2. 项目目录放 `.xiaoming/profile.patch.json` → **完全不生效**（项目目录不参与装配）。
3. patch 引用不存在的 `id` → 报错，不静默忽略。
4. 一个插件冒充基线层的服务 key → 装配期断言拒绝启动。

---

### M3-c · 驱动器扩展点化

**做什么**

- 按 [ADR-0055](./adr/0055-Turn驱动器的扩展点契约.md) 把 `turn.ts` 拆成驱动器 + 五个回合级扩展点。
- 工具执行链固化为十二步；①~⑤ 特权链段不可插入。
- `ContextBuilder`、多模态能力检查、checkpoint、结果截断、`maxIterations` / `max_tokens`
  兜底全部搬成插件。
- 红线判定改为单调 `guard`；`tool/pre-execute` waterfall 的单调性检查落地。

**不做什么**

- 不改判定语义、不改闸门顺序、不引入 `ask`。
- 不改 `turn.ts` 的三条不变量（seq 单点、先落库后广播、执行前必过闸门）。
- `turn.ts` 本身**不变成插件**，它仍是特权文件。

**验收**：行为快照与 M3-b 后一致；`turn.ts` 降到 200 行以内；checkpoint 插件缺席时装配拒绝启动。

**反向演练**

1. 恶意 waterfall 监听器在红线 deny 之后返回 allow → 单调性检查必须拦下。
2. `tool/pre-execute` 试图改写 `input` 里的路径 → 接口上拿不到写入口；若有口子，
   用符号链接（Windows 上用 8.3 短名）构造判定与执行分叉，必须红。
3. 卸载截断插件 → 超大结果必须让预算测试红，而不是悄悄发给 Provider。
4. `tool/execute` 环绕插件跳过 `next()` 返回伪造成功 → 必须被识别或结构上做不到。

---

### M3-d · Agent 句柄与 Inbox

**做什么**

- `Agent` 句柄三入口：`followup` / `steer` / `inject`；认领语义。
- 新增 `context.injected`（persisted）事件，`source` 可区分 plugin / subagent / job / cron / watcher。
- 子 Agent 回传统一走 `inject`，粘性污点照 [ADR-0049](./adr/0049-M2-i串行只读子Agent.md) 不变。
- 桌面端：回合进行中可排队第二条消息、可纠偏。

**不做什么**

- **不做并行子 Agent**（仍串行）。
- 不做后台任务 / 定时任务本身（新 M5/M6），本段只提供它们的落点。
- 不做目标域（goal）与外层循环——记在 [09-待讨论的开放问题](./09-待讨论的开放问题.md)。

**验收**：注入内容在重开会话后仍可见且顺序正确；空闲 Agent 收到 `inject` 保持空闲。

**反向演练**

1. **让 `inject` 不落事件** → 重开会话后模型看到的历史与注入前不一致，测试必须红。
   这是本段的核心约束，没有这条演练等于没有这条约束。
2. 对空闲 Agent `inject` → 必须保持空闲。动起来即一级缺陷。
3. 注入一段来自 `net.fetch` 的网页内容 → 污点必须传播。
4. 回合中 `followup` ×2 + `steer` ×1 → 认领顺序与 FIFO 守恒可断言。

---

### M3-e · 能力接缝与执行世界

**做什么**

- `port/` 正名为接缝定义，统一提供者注册与消费者注入形状（**不改任何端口签名**）。
- `ctx.executor` 接缝：fs / process / pty 三类操作收敛到一处；交付 local 一个提供者。
- depcruise 规则：`tools-core` 的工具实现不得 import `node:fs` 等，只有 local 提供者可以。

**不做什么**

- **不做容器 / 远端提供者**（新 M5/M6）。但接口形状现在就要完整。
- 不改路径网关的位置（仍在判定之前）。

**验收**：写一个**假 executor 提供者**（记录调用、不做真实 I/O），全部 fs/shell/pty 工具
跑在它上面必须跑通——跑不通即说明有绕过。

**反向演练**

1. 任一工具直接 import `node:fs` → depcruise 必须红。
2. 假提供者下有工具仍产生真实文件系统副作用 → 说明有绕过，必须查出来。
3. 远端语义预演：让假提供者返回一个与入参不同的路径 → 必须被拒绝
   （提供者不得重新解析路径）。

---

### M3-f · 渲染意图

**做什么**

- `presentCall` / `presentResult` 纯函数投影 + 落库的 `presentationMeta`。
- 四种卡片：generic / terminal / diff / search；无匹配渲染器降级为摘要。
- 渲染器注册表；渲染层三个安全开关一个不动。
- `edit-review` 专用通道退役，M2-e 的权限语义（[ADR-0045](./adr/0045-M2-e-diff审阅不是权限审批.md)）一字不改。

**不做什么**

- 不加第五种卡片。
- 不把 UI 格式化塞进模型可见结果。

**验收**：新增一个工具（含卡片）不触碰渲染层任何文件；M2-e 逐块接受/拒绝全套用例仍绿。

**反向演练**

1. 在 `presentCall` 里读一次文件 → 回放测试必须红（实时与回放两次投影不一致）。
2. 喂**真实旧库**里的畸形 / 旧版参数事件 → 必须降级为通用卡片，**绝不能让会话打不开**。
   用真实尺寸的库跑，不用小夹具。
3. 注册一个没有对应渲染器的卡片种类 → 降级为摘要，不白屏。

---

### M3-g · 扩展事件与自省闸门

**做什么**

- `ext.persisted` / `ext.transient` 两个信封；未声明即拒绝写入；`reduce()` 恒等。
- 插件的窄写入口 `recordExt`，`pluginId` 由运行时按身份填。
- 不变量注册表 + 各包 `./invariant` 伴生模块 + `check:invariants`。
- 五张生成表（接缝图、事件生产消费表、扩展点挂载表、工具目录、配置目录）进 `pnpm verify`，
  放 `docs/generated/`。

**不做什么**

- 不提高覆盖率门槛（kernel 85% 不变）。
- 不做双语文档。

**验收**：`pnpm verify` 多出两道闸门并全绿；生成表与代码一致。

**反向演练**

1. 手改一处生成的接缝图 → 闸门必须红。
2. 写一个断言"`ctx.tools` 服务存在"的伪不变量 → `check:invariants` 必须拒收。
3. **把 `trustLevel` 改回硬编码 `'model'`** → 判定路径不变量必须在第一个真实会话里红。
   这一条要抓住一次已经真实发生过的事故，是本段的立身之本。
4. 写一条清单里没声明的 `ext` 事件 → 当场拒绝。
5. 读一个含未安装插件事件的历史库 → `reduce()` 恒等、事件不丢、UI 有说明。

---

### M3-h · Code Mode

**做什么**

- `ctx.codeRuntime` 接缝 + Node worker 提供者（TypeScript 一种语言）。
- `run_code` 工具 + 从工具 schema 生成的 SDK 类型。
- 子调用重入 ADR-0055 完整十二步链，携带父 token，落 `tool.code.dispatch`（persisted）。
- 呈现模式 `native`（默认）/ `code` / `both`。

**不做什么**

- 不做 Python 运行时。
- 不给程序任何直通能力（网络 / 文件 / 进程）。
- 不做嵌套 `run_code`。
- **默认不开**——Code Mode 是 opt-in。

**验收**：一段程序连调三个工具，往返 3 次降到 1 次；`run_code` 卡片显示程序全文与每次子调用。

**反向演练**

1. 程序里调撞红线的工具（写 `.git/index`、读 `~/.ssh/id_rsa`）→ 拒绝，理由与直接调用一致。
2. 程序里用符号链接路径 → 网关照常规范化并回写；跳过网关则用 8.3 短名构造分叉，必须红。
3. 程序死循环 / OOM → worker 被终止，主循环不受影响。
4. 程序 `require('fs')` / `import('node:child_process')` → 拿不到。
5. 父 `run_code` 被允许、内部 `fs.write` 应被拒 → 必须拒。复用父判定即一级缺陷。
6. 程序 catch 掉被拒的子调用并继续 → 审计里仍有那条 `tool.code.dispatch`。

## 4. M3 总验收（DoD）

1. **删掉全部业务插件行后应用仍能启动**，工具列表为空，UI 有明确提示——
   [01-愿景与设计原则](./01-愿景与设计原则.md) 原则二那条从未落实的约束，第一次通过。
2. 同一引擎被 `desktop` / `headless` / `cli` 三条 profile 各装配一次，跑通同一任务。
3. **新增一个工具（含 UI 卡片）不触碰 `turn.ts`、`services.ts`（已不存在）、渲染层任何文件。**
4. [ADR-0053](./adr/0053-微内核的特权底座与扩展点边界.md) 的六项底座在装配期断言下不可绕过；
   四条恶意插件演练全部被拦。
5. 三条 M0 起的不变量仍然成立：seq 单点分配、先落库后广播、工具执行前必过闸门。
6. `pnpm verify` 全绿，含新增的 `check:invariants` 与图谱生成两道闸门。

## 5. 风险与已知代价

| 风险 | 应对 |
|---|---|
| **静态护栏变弱**（依赖关系从 import 图挪到运行时） | 包边界规则一条不改、插件不新建细粒度包、生成接缝图补盲区。见 [ADR-0052](./adr/0052-插件容器与效果模型.md) 后果段 |
| **错误从编译期挪到装配期** | 未满足的 `inject` 必须 fail loud 并列出等待链（M3-a 反向演练二） |
| **搬家阶段引入静默回归** | M3-b / M3-c 用事件流快照逐条对齐，不靠"看起来还行" |
| **M3-e 改动面最大** | 单独成段；假 executor 提供者是硬验收，不是可选检查 |
| **M3-h 是最大单件** | 排在最后，可砍，不影响前七段 |
| **把体验问题误当结构问题** | [11 §9](./11-微内核与插件容器.md) 列出插件化解决不了的几类；真实痛点清单待补 |

## 6. 之后是什么

M3 完成后，原路线图顺延：**新 M4「能扩展」**（三方插件隔离决议、MCP、Skill、
多 Provider 角色路由、配置中心、`xm` CLI 产品化）——它的绝大部分交付，
在 M3 之后都变成"写一个插件"。
