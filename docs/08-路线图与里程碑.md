# 08 · 路线图与里程碑

> 排序原则：**先立地基（契约、事件、权限、持久化），再堆能力**。参考项目的问题恰恰是能力堆得快、地基没打——后期每加一个工具都要改三处。
>
> 每个里程碑都必须"可用"，不做半成品堆叠。

## 里程碑总览

| 里程碑 | 主题 | 关键交付 |
|---|---|---|
| **M0** | 骨架 | monorepo + 契约包 + 内核空转 + 架构守护 |
| **M1** | 能对话、能干活 | 流式对话 + 文件/终端工具 + 权限闸门 + 桌面 UI |
| ↳ M1-a | ✅ 三个前置 | 解除入口 + target 规范化契约 + 流式渲染 |
| **M2** | 能改代码 | 多文件编辑 + diff 审阅 + 检索 + git + checkpoint |
| **M3** | 能扩展 | 插件宿主 + MCP + 多 Provider + 技能 |
| **M4** | 能操作电脑 | 浏览器自动化 + computer use + 后台任务 |
| **M5** | 能自省 | Trace + 评测集 + 记忆 + 技能自动生成（L0–L2） |
| **M6** | 能自改 | 工具/插件自动生成 + 内核自修改闭环（L3–L4） |

## M0 · 骨架

**目标**：把架构约束用代码固定下来，之后所有开发都在护栏内进行。

M0 分两段：**M0-a 契约与内核纯逻辑**（返工成本最高、可完全离线验证）、**M0-b 外壳与持久化**。

- ~~**`@xm/contracts` 全量落地**~~ ✅ 23 个事件 payload + 注册表 + upcaster 骨架、`ToolDescriptor` + `assertToolSchema()` + 截断契约、能力闭集、`PolicyRule`/`Verdict`、`ModelRequest`/`Chunk`、配置树与 `SecretRef`。**零依赖（仅 zod）、6.47KB min+gzip**

- ~~`BlobStore` 端口 + 文件实现~~ ✅ 内容寻址 + 写临时文件→fsync→rename，10 条契约用例

- ~~**Vite / electron-builder 在双装工具链下的构建验证**~~ ✅（ADR-0010 遗留项关闭，见 [ADR-0016](./adr/0016-原生模块与打包.md)）
- ~~**headless 冒烟测试**~~ ✅ 无 GUI 跑通一轮完整对话：建会话 → 流式输出 → 工具过闸门 → 落真 SQLite → 重开库回放出**完全一致**的状态。同时有 vitest 版（源码）与独立脚本版（`dist/`），后者补上"产物能不能用"这一格

**M0-b DoD 达成情况**：`pnpm verify` 全绿（287 测试 / 125 模块 371 边零违规）；headless 冒烟在无 Electron 环境下跑通；三段产物能构建、`electron-builder --dir` 能打包、`.node` 被正确 asarUnpack 出来。

> ⚠️ **一项欠着：应用没有在真机上启动过。** 本轮开发环境缺 GUI 系统库（libatk / libgtk）且无安装权限。这一格由 CI 的 `desktop` job 补（三平台 `XM_SMOKE=1 electron .`，Linux 走 `xvfb-run`，跑的是打包产物），与"三平台 CI 实跑"是同一个前提：需要远端仓库。

## M1 · 能对话、能干活

**目标**：第一个真正有用的版本——能聊天、能读写文件、能跑命令，且不会把电脑搞坏。

M1 分两段。**M1-a 是三个前置**：它们全部是"接上真实 Provider 之后就会带着假防线上线"的
缺口，而且**接之前做成本最低、之后做成本最高**（新增事件类型越晚改历史会话越多；
动 target 判定路径越晚改调用点越多；定"什么样的第二份状态是允许的"越晚定 UI 里的临时状态越多）。

### ~~M1-a · 三个前置~~ ✅ 已于 2026-08-05 完成

- ~~**G1 不可信标记的解除入口**~~ ✅ → [ADR-0019](./adr/0019-不可信标记的解除入口.md)。
  `PolicyEngine` 拒绝时说的"请显式解除本轮的不可信标记后重试"，此前是一句**无法兑现的承诺**——
  标记一旦置上就是终身的。新增 `trust.cleared` 事件 + 运行时入口 + 常驻横幅；
  解除只到下一次引入外部内容为止；`ToolContext` 里没有记录事件的入口，工具在结构上解除不了
- ~~**C4 / G3 非路径 target 的规范化契约**~~ ✅ → [ADR-0020](./adr/0020-非路径target的规范化契约.md)。
  反向演练当场打出代价：去掉 host 规范化后，一条 `deny net.fetch *.evil.com` 被**八种写法全部绕过**。
  `TargetKind` 穷尽映射；`host` 完整落地；`command` 契约定死、实现随工具落地（失败关闭的闸门顶着）；
  **红线不得建立在没有规范化契约的 target 上**（构造期断言）
- ~~**G6 流式渲染**~~ ✅ → [ADR-0021](./adr/0021-流式渲染与第二份状态的边界.md)。
  ADR-0008 与 ADR-0015 两条各自正确的约束合出的洞：`message.delta` 到达时 UI 什么也不做。
  内核里加一份纯函数 live buffer，判据是"同一段文字不会同时在 buffer 和 messages 里"

**M1-a DoD 达成**：`pnpm verify` 全绿（372 测试 / 134 模块 412 边零违规 / contracts 6.96 kB）；
11 项反向演练全部当场转红并逐一还原。

### M1-b · Provider、工具与审批

- Provider：Anthropic（首发）+ OpenAI 兼容；全流式
- **`SecretStore`**：钥匙串实现 + 口令加密文件实现；运行时探测后端能力，**退化时显式告知用户，绝不静默明文**（Linux 无 keyring 环境、容器、CI 都会走到这条路径）
- 工具集：`fs.read` / `fs.write` / `fs.list` / `shell.exec` / `shell.session`(PTY) / `web.fetch`
  - **`shell.exec` 必须一并实现 ADR-0020 决策三的 argv 契约**——M1-a 那道失败关闭的闸门绕不过去
  - **`web.fetch` 必须在能力网关按解析出的 IP 再判一道**（内网段 / link-local / DNS 重绑定），host 归一只管"写法"
- **权限闸门全链路打通**：PolicyEngine + 默认策略 + 审批 UI（本次/本会话/永久）
- **G2 污点传播**：MCP 工具默认按不可信内容源处理；子 Agent 的污点在 `subagent.end` 并回父会话。
  G1 落地之后，这是注入防御上**唯一**剩下的绕过路径，接 MCP / 子 Agent 前必须做
- 多模态：图片可以贴进对话并被模型看到
- UI：会话列表、消息流（含思考过程折叠）、工具调用卡片、终端视图、**停止按钮**（`message.interrupted` 目前没人发）
- 崩溃恢复：重启后运行中会话有明确状态
- 用量与成本展示

**DoD**：能用它完成"读这个目录、总结代码结构、写一个 README"；中途点停止能在 200ms 内真停；`rm -rf ~` 被拦；重启不丢会话。

## M2 · 能改代码

**目标**：达到"日常写代码可以用它"的水平。

交付：

- `edit` 工具：精确字符串替换 / 多文件批量编辑，带冲突检测
- diff 审阅 UI：改动预览、逐块接受/拒绝
- 检索：ripgrep 集成 + tree-sitter 符号索引 + FTS5
- `git` 工具集：status / diff / commit / branch（push 单独审批）
- Checkpoint 与一键撤销
- `todo` 工具（模型自主任务拆解，替代参考项目的硬编码 Planner 状态机）
- 上下文管理：token 预算器 + 分层压缩 + prompt cache 友好的前缀
- 子 Agent（隔离上下文，只回传结论）

**DoD**：用小明自己完成 mingAgent 仓库的一个真实功能开发（自举的第一步）。

## M3 · 能扩展

**目标**：验证扩展体系的表达力——外部能力接入不需要改内核。

交付：

- 插件宿主：进程隔离 + 能力网关 + 清单校验 + 懒激活
- `@xm/plugin-sdk` v1 + 插件开发文档 + 示例插件
- MCP 客户端：stdio/SSE/http，tools + resources + prompts
- 多 Provider 管理：模型档案、角色路由（主循环/子 Agent/摘要/嵌入）、降级链
- Skill 系统：加载、匹配、元数据常驻 + 正文懒加载
- 渲染器注册表：工具自带展示契约
- 配置中心 UI（对标参考项目的配置页，但密钥走 `SecretStore`）
- **`xm` CLI 正式产品化**（架构约束自 M0 起就在，这里只是补产品层：参数解析、无人值守的权限模式、终端渲染）

**DoD**：删掉所有一方插件应用仍能启动；接一个三方 MCP server 无需改任何内核代码；换 Provider 只改配置；`xm` 能在无桌面环境的 Linux 上完成一个真实任务。

## M4 · 能操作电脑

**目标**：从"代码 Agent"跨到"通用 Agent"。

交付：

- 浏览器自动化（Playwright）：导航、点击、填表、截图、抓取；截图进上下文（**三平台均可用**，是 Linux 上"操作电脑"的主力）
- Computer Use：屏幕捕获 + 鼠标键盘注入 + 窗口枚举，**仅 macOS / Windows**（[ADR-0007](./adr/0007-平台支持分级.md) Tier 3）。Linux 上该能力经 `PlatformPort` 探测为不可用，工具自动从模型视野消失，UI 灰显并说明原因
- 观察面板：终端 / 浏览器 / 文件 diff / 屏幕 四视图（信息布局参考 manusAgent 的设计稿）
- 容器执行器：不信任代码走 Docker
- 后台任务：长任务脱离窗口生命周期，托盘通知
- 定时/触发式任务

**DoD**：能完成一个跨应用任务（例如"打开网页查数据 → 整理成表格 → 存到本地 → 发通知"）；GUI 操作有明确的用户在场检测。

## M5 · 能自省（L0–L2）

交付：

- Trace 完整记录 + 回放能力
- `evals/` 评测集（单元/任务/回归三类）+ 评测运行器 + 指标看板
- 记忆系统：三作用域、检索召回、记忆面板（可见/可编辑/可删/带来源）
- 技能自动提炼 + 效果统计 + 自动淘汰
- 提示词版本化，变更强制关联评测结果

**DoD**：任一历史运行可完整回放；用户说过一次的偏好一周后仍被正确应用且可溯源；至少 3 个自动生成的技能在评测集上有正向收益。

---

## M6 · 能自改（L3–L4）

交付：

- 工具/插件自动生成流水线（脚手架 → 容器内构建测试 → 权限展示 → 用户确认 → 热加载）
- 内核自修改闭环：worktree 分支 → 实现 → 全量验证 → 变更报告 → 人工审批 → 合并 → 回滚点
- 红线清单硬编码 + 安全模块修改的二次确认
- 改进议题的自动发现（失败聚类）与低峰期调度

**DoD**：至少 1 个小明自主生成并被采纳的工具在日常使用；至少 1 个小明自主提出、实现、通过全量评测并被合并的核心改动。

## 贯穿始终的工程纪律

| 项 | 要求 |
|---|---|
| 每个里程碑 | 必须可发布、可日常使用，不做半成品堆叠 |
| 每个真实失败 | 必须固化成 `evals/regression/` 用例 |
| 每个架构决策 | 必须有 ADR |
| 每次接口变更 | 文档同批更新，否则视为未完成 |
| 自举 | 从 M2 开始，小明的开发尽量用小明自己做——它是自己的第一个用户，也是最严格的测试 |
