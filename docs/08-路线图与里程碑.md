## M1 · 能对话、能干活

**目标**：第一个真正有用的版本——能聊天、能读写文件、能跑命令，且不会把电脑搞坏。

**M1-a 是三个前置**：它们全部是"接上真实 Provider 之后就会带着假防线上线"的
缺口，而且**接之前做成本最低、之后做成本最高**（新增事件类型越晚改历史会话越多；
动 target 判定路径越晚改调用点越多；定"什么样的第二份状态是允许的"越晚定 UI 里的临时状态越多）。

余下部分拆成 **M1-b ~ M1-e 四段**。（**M1-d.5** 是 2026-08-08 地基复审三之后
新插入的一段，不在最初的四段规划里——它本身就是这份路线图承认"计划要跟着复审
结果调整，不能死守最初拆法"的证据，见 [ADR-0032](./adr/0032-地基复审三-M1收尾前的原则符合度审查.md)。）

> **体验时点已定（2026-08-06）：M1 全部完成后再上手打磨。**
> 中途不停下来做体验，所以每一段的验收只能靠自动化——这反而抬高了对反向演练的要求：
> 没有人在中间用真实输入替我们兜底。

### 排序依据：四条硬依赖

拆分顺序不是偏好，下面四条是"做 A 就必须先有 B"：

1. **`SecretStore` 必须早于 `shell.exec`。** 子进程继承环境变量。任何"先把 key 放
   `ANTHROPIC_API_KEY` 里"的省事路径，一旦与 shell 工具同时存在，小明跑的每条命令
   都能读到它。所以密钥归宿在 M1-b 就定死，不留过渡态。
2. **`shell.exec` 必须一并实现 ADR-0020 决策三的 argv 契约。** M1-a 那道闸门是失败关闭的
   （带非空 target 的命令类判定一律 deny），不实现契约，shell 工具根本跑不通。
3. **审批 UI 必须与第一个会判 `ask` 的工具同段落地。** 平衡档下 `fs.write` 判 ask，
   没有应答入口时它等价于 deny——工具装上了却用不了，比没装更难排查。
4. **`web.fetch` 必须在能力网关按解析出的 IP 再判一道**（内网段 / link-local / DNS 重绑定）。
   ADR-0020 的 host 归一只管"写法"，管不了"这个名字解析到哪"。

### M1 的两个环境前提

- **打包产物要在有桌面的机器上启动。** 当前开发机缺 GUI 系统库（`libatk` / `libgtk-3`）、
  无 `DISPLAY`、无 `xvfb-run`，与 M0-b 记的那笔账一样。M1 期间的验证全部走
  `pnpm verify` + headless 冒烟 + CI 的 `desktop` job；**手工体验必须换机器**，这件事可以与开发并行安排。
- **真实 Provider 调用要花钱，所以 CI 里一次也不调。** 涉及模型的用例走
  `ScriptedProvider` 或**录制的 SSE fixture**（`packages/providers/tests/fixtures/*.sse`）。
  ✅ **这笔债已于 2026-08-06 还清**：`live-deepseek-*.sse` 是从真实服务端原样抓下来的字节，
  `recorded.test.ts` 回放它们（CI 跑，不要 key）；`live.test.ts` 打真实 API
  （`XM_LIVE_PROVIDER=1` 才跑，CI 永不跑）。那一轮验收照出了一个真 bug，见 ADR-0022 的补记。

### ~~M1-b · 能开口~~ ✅ 已于 2026-08-06 完成 → [ADR-0022](./adr/0022-Provider传输层与密钥归宿.md)

**主题**：把 `ScriptedProvider` 换成真模型，并把密钥的归宿一次定死。

**DoD 达成**：`pnpm verify` 全绿（446 测试 / 155 模块 503 边零违规 / contracts 7.13 kB）；
14 项反向演练全部当场转红并逐一还原。三处值得单记：
**① 端口中立性第一次被检验**——接第二家的第一小时抓到三处绑死 Anthropic 的假设；
**② 中断必须落两条事件**（`message.end` + `message.interrupted`），只发后者会当场破掉
ADR-0008 的包含性不变量；**③ scrypt 的 `maxmem` 默认 32 MB 卡住 N=32768**，
差 1.5 MB，是一条真实的"存不进密钥"路径，被第一条用例照出来。

**~~仍欠一格~~ 已补**（2026-08-06 当天）：真调了一轮，**当场照出一个用户看得见的 bug**——
点停止会收到一条红色报错（`turn.ts` 纠正了 `stopReason` 却没清 `failure`）。
根因是 `ModelProvider` 端口**从没规定过取消时迭代器怎么结束**，于是调用方各自去猜。
现已把「取消时正常结束迭代，不抛」写进端口，两个适配器与一道兜底一起落。
详见 [ADR-0022 补记](./adr/0022-Provider传输层与密钥归宿.md)。

- **Provider 端口 + Anthropic 实现**，全流式。端口在内核（零 I/O），实现在独立包；
  OpenAI 兼容实现同段落地——**只有第二个实现能证明端口没有把第一家的形状焊死**
- **`SecretStore`**：钥匙串（Electron `safeStorage`，零新增原生模块）+ 口令加密文件
  （scrypt + AES-256-GCM）+ 不可用兜底三档；`set()` 在存不了时**抛**而不是返回 false。
  配置里只存 `SecretRef`，明文密钥在配置加载时被点名拒绝，`redact()` 覆盖日志与审计。
  ⚠️ 加密文件那一档**还没有入口**——它需要一个"设置主口令"的界面，那属于配置中心（M3）。
  在此之前无钥匙串环境走的是"明确存不了"，并发一条 `secrets.degraded` 的 notice
- **停止按钮**：`AbortSignal` 从 UI 贯通到 Provider 的流式读取，落 `message.interrupted`。
  live buffer 已经处理了这个事件（ADR-0021），只差发出者
- **用量与成本展示**：token 计数取自 Provider 响应，不自己估算
- **配置加载**：`Config` schema 与合并语义从 M0 起就写好了，但**没有任何代码读过一个
  配置文件**——本段是它第一次被真实文件喂到。分层为 内置默认 < 用户级 < 项目级，
  **环境变量层刻意不做**（那等于给密钥开一条会被 `shell.exec` 继承的路）
- **价格表是配置且仓库里不带默认值**：算不出成本时 `costOf()` 返回 `undefined` 而不是 0，
  UI 显示"≥ $X（N 次未计价）"。带一份默认价格等于发布一个会过期的事实
- **CI 一次也不打真实调用**：CI 里的用例走 `ScriptedProvider` 或**真实录制**的 SSE fixture，
  不花钱、不需要 key。真调用挂在 `XM_LIVE_PROVIDER=1` 后面，手动跑

**DoD**：能和真模型对话并逐字流式显示；中途点停止能在 200ms 内真停；
密钥不出现在任何日志、审计、配置文件里；杀掉 keyring 后启动会明确告知降级方式。

- ~~**联网搜索每个网址都要授权一次**，开到「帮我批准」/「完全访问权限」也没用~~
  ✅ 已于 2026-08-10 修复 → [ADR-0034](./adr/0034-知情授权穿透注入降级.md)。
  根因是一个**自我污染循环**：`net.fetch` 既在 `UNTRUSTED_CONTENT_CAPABILITIES`（污点源）

  新目标仍然照问一次。端到端实测同域名三次 fetch 的确认框 3 → 1。

- ~~**搜一个今日新闻仍然点了 10+ 次「允许」**，即便开着「完全访问权限」~~
  ✅ 已于 2026-08-10 修复 → [ADR-0035](./adr/0035-注入降级感知审批档位.md)
  + [ADR-0036](./adr/0036-只检查的主张.md)。

  ADR-0034 消掉的是"**同一个**域名被反复问"，而一次搜索里**每个域名都是新的**——
  一条都不在它的覆盖范围内。它自己的「后果」段就写着这条残留，
  只是当时没意识到那等于"用户的症状一点没变"。实测查出**两个相乘的因子**：

  1. **注入降级排在 YOLO 之后**（第 5 步 vs 第 4 步），把 YOLO 刚放行的又整批打回来问。
     修法是让降级感知档位：新增闭集 `CRITICAL_UNDER_UNTRUSTED`（严重项 =
     后果留在本会话之外的 `git.push` / `package.install` / `system.settings`），

     同时给 ADR-0034 的条件 ③ 补上条件 ④（callId 对齐），修掉"第一个域名被问两遍"。
  2. **网关为 SSRF 判定产出的"解析出的 IP"主张也命中了 `def.net-fetch` 的 ask**，
     于是每次 `web.fetch` 本来就弹两个框（一个域名 + 一个裸 IP）。
     修法是 `PermissionClaim.checkOnly`：只查 deny，不问用户。

  端到端实测（照抄用户原话的场景）：yolo 档 SERP + 5 个各不相同的域名，
  `permission.request` **6 → 0**，6 次工具调用全部执行；同档下 `git.push` 仍问一次。

  > **教训**：修完一个降噪问题，要按**用户的原始场景**数一遍框，不要按"我修掉的
  > 那条路径"数——ADR-0034 的用例断言"3 条降到 1 条"，绿了，症状还在。
  > 另：噪音是**相乘**的，只修掉其中一个因子用户感觉不到差别。
  > **仍然欠着**（刻意不做，见 docs/09 C9）：① 没有 `web.search`，一次搜索仍是
  > N 次 `web.fetch`（消的是请求数不是确认框）；②「永久允许」重启后落到 `user` 层，
  > 穿不透降级，每个新会话仍会被问一次——语义上说得通，但和按钮上的"永久"对不上。

## M3.5 · 桌面端界面与设置

**目标**：把 M2/M3 已经交付、但在界面上根本不存在的能力放出来，顺带换掉视觉调性。

> 与 M1.5 同一性质：真实体验驱动的插段，不是新能力。
> 总纲见 [12-桌面端界面与设置](./12-桌面端界面与设置.md)，分段见 [M3.5 阶段划分](./M3.5-阶段划分.md)。

起因是一次实测对照（2026-08-16）：`config.json` 的 17 个字段里，桌面端能改的只有 **3 个**。
`tools.presentation`（M3-h 刚做完的 Code Mode 开关）、`permission.rules`
（ADR-0039 之后**唯一**的用户侧权限入口）、以及三个角色的模型选择，
在界面上一律不存在——换模型要手编 JSON 并重启。
继续做 M4 只会放大这个差距，因为 M4 的每一件交付都需要一个设置出口。

同批换掉配色调性：现在的暖白底 + 三个米白填充分层实测偏糊，
改用参考实现那套「亮色靠描边、暗色靠填充」的分层反转（见总纲 §1.1）。

交付（六段，a→f，每段独立可用）：

- **a** 设计 token 换轨：三层 token（调色板 / 语义别名 / 组件专用）+ 亮暗分层反转 + `check:design-tokens` 闸门
- **b** 两栏让位链：纯函数列宽求解器 + 可拖拽右栏（**不引入左侧会话侧栏**，ADR-0037 的顶栏 tabs 决定不变）
- **c** 对话流重制：hero→docked 输入区、sticky + 像素渐变遮罩、**工具调用压成 24px 单行**、回合统计
- **d** 右栏升级为「详情 + 工作区」两档：点工具行看该次调用的入参与结果，Code Mode 子调用同样可点
- **e** **设置中心**：模态 + 左导航六节；模型与 Provider、权限拒绝清单、呈现模式第一次有入口
- **f** 上下文占用环（唯一越出渲染层的一段，可单独砍）

**DoD**：一屏可见的工具调用数 ≥ 12（现状 ~3）；UI 可改的 `config.json` 叶子字段 ≥ 10
（含 `tools.presentation` 与 `permission.rules`）；ADR-0073–0077 写完并进索引；
九条反向演练逐条留下红色证据；`pnpm verify` 全绿且 headless 冒烟数字一条不变。

**明确不做**：左侧会话侧栏、插件贡献 UI 的插槽体系、MCP/Skill 的设置空节
（空节会让人以为功能已经在了）、`allow` 方向的权限编辑、红线开关。

## M5 · 能操作电脑

**目标**：从"代码 Agent"跨到"通用 Agent"。

交付：

- 浏览器自动化（Playwright）：导航、点击、填表、截图、抓取；截图进上下文（**三平台均可用**，是 Linux 上"操作电脑"的主力）
- Computer Use：屏幕捕获 + 鼠标键盘注入 + 窗口枚举，**仅 macOS / Windows**（[ADR-0007](./adr/0007-平台支持分级.md) Tier 3）。Linux 上该能力经 `PlatformPort` 探测为不可用，工具自动从模型视野消失，UI 灰显并说明原因
- 观察面板：终端 / 浏览器 / 文件 diff / 屏幕 四视图（信息布局参考 manusAgent 的设计稿）
- 容器执行器：不信任代码走 Docker
- 后台任务：长任务脱离窗口生命周期，托盘通知
- 定时/触发式任务

**DoD**：能完成一个跨应用任务（例如"打开网页查数据 → 整理成表格 → 存到本地 → 发通知"）；GUI 操作有明确的用户在场检测。

交付：

**DoD**：至少 1 个小明自主生成并被采纳的工具在日常使用；至少 1 个小明自主提出、实现、通过全量评测并被合并的核心改动。

## 贯穿始终的工程纪律

| 项 | 要求 |
|---|---|
| 每个里程碑 | 必须可发布、可日常使用，不做半成品堆叠 |
| 每个真实失败 | 必须固化成 `evals/regression/` 用例 |
| 每个架构决策 | 必须有 ADR |
| 每次接口变更 | 文档同批更新，否则视为未完成 |
| 自举 | 从 M2 开始，小明的开发尽量用小明自己做——它是自己的第一个用户，也是最严格的测试 |
