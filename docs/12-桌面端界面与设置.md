## 1. 为什么现在做

### 1.1 明面上的理由：暖白底 + 填充分层，实测就是糊的

现在的 `styles.css` 亮色是 `canvas #faf9f5` / `surface #ffffff` / `surface-2 #f2f0e9`，
分层**靠三个挨得很近的米白填充**，边框 `#e5e2d8` 也在同一个色域里。三者放在一屏上，
边界既不靠对比也不靠描边，看久了就是一片糊。

参考实现的做法正好相反，而且**亮暗两套是反着来的**：

| | 亮色 | 暗色 |
|---|---|---|
| `bg-base` / `layer-1` / `layer-2` / `layer-3` | **全是纯白**，四个值完全相同 | `#151517` / `#232324` / `#2c2c2e` / `#353638`，逐层提亮 |
| 层次从哪来 | **全靠描边**：黑色 alpha `0.04 / 0.10 / 0.12 / 0.16` 四档 | **全靠填充**；描边换成白色 alpha，最重才 `0.20` |

亮色下不画填充只画描边，暗色下不画描边只画填充 —— 这是这套界面干净的**结构性原因**，
不是配色偏好。小明现在两边都用填充，于是亮色糊、暗色靠"卡片与底色刻意贴得很近"
（`styles.css` 里已有的那句注释）勉强兜住。

### 1.2 更要紧的理由：M3 做完的能力，界面上不存在

`config.json` 一共 **17 个字段**（`docs/generated/配置目录.md`），桌面端能改的只有 **3 个**：

| 字段 | UI 可改？ | 现状 |
|---|---|---|
| `model.main` / `model.subagent` / `model.summarize` | ❌ | 换模型必须手编 JSON 并重启。设置页写着"归入 M3 配置中心"——**M3 已经收官，配置中心没做** |
| `providers`（地址、类型） | ❌ | 同上 |
| `prices` | ❌ | 花费统计的价目表只能手编 |
| `permission.rules` | ❌ | ADR-0039 之后这是**唯一**的用户侧权限入口，UI 上零暴露 |
| `tools.presentation` | ❌ | M3-h 刚花一整段做完 Code Mode，**用户看不到开关** |
| `tools.disabled` | ✅ | |
| `workspace.mode` / `workspace.defaultPath` | ✅ | |
| `logging.level` / `logging.redact` | ❌ | 见 §9.1——它们是**死配置** |

再往下做 M4（MCP、Skill、多 Provider 角色路由）只会让这个差距更大：M4 的每一件交付
都需要一个设置出口，而设置中心现在是一句占位文案。**先把出口做出来，再往里加东西。**

## 3. 不拿什么，以及为什么

**这一节比上一节更重要**——照着参考实现改界面的人，最容易把这里刻意删掉的东西补回来。

### 3.1 不拿左侧会话侧栏

参考实现是三栏：`sidebar | center | details`，会话列表常驻左侧。
**小明是两栏**：`center | details`，会话在顶栏 tabs、全部会话在 Home。
这是 [ADR-0037](./adr/0037-桌面端壳层导航与会话入口.md) 已经拍过板的决定，产品本次再次确认。

因此 §5.2 的让位链求解器**只有两栏**：参考实现里"侧栏永不让位、正文最后兜底"那条链缩成
"详情栏先让位、正文兜底"。**不要照抄三参数签名**——一个恒为 0 的参数会让人以为侧栏只是没接上。

### 3.2 不拿 slot 注册表与插件贡献 UI

参考实现的每一处界面都是插槽（`settings.section`、`settings.general.item`、
`conversation.composer` …），三方插件靠注册进去。小明的渲染层现在只有
`installBuiltinRenderers()` 注册四种卡片种类（ADR-0058 §五），**这一层不动**。
插件贡献 UI 是 M4 三方插件隔离定案之后的事，现在做等于先定一个还没有使用者的契约。

### 3.3 不拿一角色一包的前端切分

参考实现有 30+ 个 `ui-*` 包。小明渲染层 4301 行、全部住在 `apps/desktop/src/renderer/`，
**本次不新建任何包**。理由与 `docs/11 §4.4` 同一条：包边界规则（depcruise）的价值来自
边界少而稳，不来自边界多。

### 3.4 不拿 CSS Modules

参考实现用 CSS Modules（每个组件一份 `.module.css`）。小明用 Tailwind v4 的 `@theme`，
且已经把命名空间清零、把"想跑偏必须先回文件里登记一档"变成了**编译期事实**。
换成 CSS Modules 会把这条约束退回人的自觉。**token 体系换，承载方式不换**。

### 3.5 不拿 Figma 坐标注释

参考实现的 CSS 里满是 `figma 75:8208` / `I54:42735;43:41479`。我们没有那份 Figma 源，
抄过来就是**永远无法核对的注释**——比没有注释更坏。本次所有尺寸注释写"为什么是这个值"，
不写它在谁的画板上叫什么。

### 3.6 不拿 i18n 与双语流水线

中文优先不变。

### 3.7 不拿"设置页能配的东西越多越好"

参考实现的设置面板可配项极多。小明有三条**明确不放**，见 §8.3。

## 4. 设计 token：三层体系怎么落在 Tailwind v4 上

### 4.1 三层各住哪

| 层 | 内容 | 住在哪 | 生成工具类？ | 组件可以用吗 |
|---|---|---|---|---|
| **调色板** | `--p-neutral-50…1000`、`--p-blue-*`、`--p-red-*`、`--p-green-*`、`--p-amber-*` | `:root` 的普通 CSS 变量，**不进 `@theme`** | ❌ | **不可以** |
| **语义别名** | `--color-canvas / -surface / -surface-2 / -border / -border-strong / -fg / -muted / -faint / -accent* / -danger*` | `@theme` | ✅ `bg-surface` / `text-muted` … | **只能用这一层** |
| **组件专用** | `--xm-composer-card-max-width`、`--xm-chat-content-width`、`--xm-scrollbar-thumb` … | 组件根节点上的局部变量，绑到别名层 | ❌ | 组件自己声明、自己消费 |

**调色板层亮暗同值**（参考实现就是这样：`body` 与 `body[data-ds-dark-theme]` 里的
`--dsw-static-*` 一字不差）。换主题只重定义**别名层** —— 这正是"组件里一个 `dark:` 变体
都不需要"能成立的原因，现在的 `styles.css` 已经是这个思路，只是缺了调色板那一层。

> **别名的名字沿用小明现有那一套，不改成参考实现的 `bg-base` / `label-primary` / `border-l1..l4`**
> （2026-08-16 落地时的决定，见 [ADR-0073 §决策一](./adr/0073-设计语言换轨与三层token.md)）。
> 换名会把一段纯 CSS 改动变成 300 多处类名的大扫荡，而 **a 段的价值恰恰在于组件文件零改动**。
> 代价是照参考实现补代码的人找不到 `label-primary` 这类名字——对应关系写在 `styles.css` 文件头。

### 4.2 强调色：换成冷调蓝

**决定：中性冷灰 + DeepSeek 蓝（`#4176E6` 亮 / `#5686FE` 暗）。**

理由不是"蓝好看"，是**整套别名层的 hover / active / selected 都是冷灰的 alpha 叠加**
（`rgba(38,49,72,0.06)` 这类）。把暖橙塞进冷灰底里，橙色在灰上会发脏，
而把 hover 也改暖就等于没换调性。

**逃生口留着**：强调色集中在 `--color-accent` / `-hover` / `-weak` / `--color-on-accent`
四个别名上，换回 Claude Code 暖橙是**改四行**，不碰任何组件。

### 4.3 主题开关

现在深色只跟随系统（`@media (prefers-color-scheme: dark)`），应用内无开关。
本次加"跟随系统 / 浅色 / 深色"三档，实现要求：

- 别名层的深色定义要**同时**挂在 `@media (prefers-color-scheme: dark)` 与 `:root[data-theme='dark']` 上，
  并且 media 那份要写成 `:root:not([data-theme='light'])`，否则手动选浅色在深色系统下不生效。
- 偏好存 `localStorage`，见 §5.3。

### 4.4 这条约束怎么变成闸门

新增 `scripts/check-design-tokens.mjs`（已落地，进 `pnpm verify` 与 CI 的 lint job），
扫 `apps/desktop/src/renderer/**`：

1. **禁止字面色值**：`#rgb` / `#rrggbb` / `rgb(` / `color-mix(` …
2. **禁止组件引用调色板层**：出现 `--p-` 即失败。
3. **禁止 Tailwind 自带调色板族名**（`text-white` / `bg-gray-100` …）。
   命名空间清零之后它们**不报错、只是什么也不生成**——一次静默失效，
   肉眼看是"这行样式没生效"，很难联想到是被清零了。写闸门时才发现的，原计划里没有。
4. **`lib/cn.ts` 的 theme 表与 `@theme` 一一对应**；
   **两处深色定义逐字节一致**；跟随系统那份的选择器必须带 `:not([data-theme='light'])`。

第 4 条的前半是**顺手补上的旧洞**：`cn.ts` 顶部现在写着"这张表必须和 `styles.css` 的
`@theme` 一一对应——加 token 时两处一起改"。那是一句靠自觉的约定，而本仓库栽过八次的
正是这个形状。后半是给**换轨自己引入的**重复上锁——CSS 没有 mixin，深色只能写两份，
**新增一个靠自觉的点就必须同批给它配一把锁**。

豁免只有一条并附了理由：`terminal-panel.tsx` 传给 xterm 的 `'#00000000'`
表示"全透明"而不是一个颜色。脚本会反过来检查豁免是否已经过期。

## 5. 布局

### 5.1 顶栏：形态不变，样式换

保持 44px 单行：`汉堡 | Home | tabs | ……… | 右栏开关`。只换两处：

- tab 选中态从"填充 `surface`"换成 **13/16 wt500 文字 + 底部 2px 指示条**（选中为强调色）。
  现在的填充选中态在顶栏上要求顶栏与 tab 不同色，指示条没有这个约束，顶栏可以坐在页面底色上。
- 右栏开关按钮的按下态跟着别名层的 `interactive-bg-active`，不再自己写 `bg-surface-2`。

### 5.2 两栏让位链（纯函数）

`renderer/lib/columns.ts`：

```ts
export interface Columns { center: number; details: number }
export const CENTER_MIN = 640;
export const DETAILS_MIN = 300;
export const DETAILS_MAX = 520;
export const DETAILS_DEFAULT = 360;

/** 纯函数：输出只是 (视口宽, 详情栏偏好) 的函数，没有迟滞——窗口拉宽自动恢复 */
export function computeColumns(viewport: number, details: number): Columns;
```

让位顺序（契约，不可改序）：

1. 都放得下 → 各自用偏好宽度。
2. 放不下 → **先把详情栏压到 `DETAILS_MIN`**。
3. 还放不下 → **自动关闭详情栏**（`details: 0`），正文吸收剩余亏空，此时才允许低于 `CENTER_MIN`。

**关键约束：自动关闭是派生结果，绝不回写偏好值。** 窗口拉宽后详情栏必须自己回来，
用户不需要再点一次。这条正是把它做成纯函数的理由——它可以被单测钉死，
而"拖拽 + 窗口变化 + 自动收起"三者交互的 bug 在集成测试里几乎抓不到。

**详情栏关闭时宽度为 0，但组件保持挂载**（不 unmount）：卸载会丢掉滚动位置和展开状态。
配套 CSS：`[data-details-collapsed]` 下去掉左边框，否则零宽也会画出一条 1px 缝。

拖拽把手：8px 命中带（跨在列边界上、`margin-left:-4px`），中央 12×32 药丸，
**默认透明，指针进入详情栏或把手时才显形**。拖拽期间关掉列宽过渡，否则列会追不上指针。

### 5.3 UI 偏好存哪：`localStorage`，且要说清为什么不违反不变量一

要持久化的：详情栏宽度、详情栏开关、主题档位、输入框 Enter 行为。

**存 `localStorage`，不进事件流，也不进 `config.json`。** 理由：

- 不变量一说的是「**状态** = `reduce(events)`，不许有只写内存不写事件的状态」，
  指的是**会话状态**——模型看得见的、决定 Agent 行为的那份。详情栏拖到多宽既不进模型请求，
  也不改变任何一次判定的结果，它不是会话状态。
- 不进 `config.json`：那个文件是 **Agent 的配置**，会被项目层覆盖、会被权限判定读到。
  把"侧栏宽度"塞进去，等于让一个纯视觉偏好参与配置分层。

**判据（写进 ADR）**：一项偏好能进 `localStorage`，当且仅当它**既不进模型请求、也不参与任何判定**。
主题档位满足，`tools.presentation` 不满足（它决定模型看得见哪些工具）——后者必须进 `config.json`。

## 6. 对话流

### 6.1 hero → docked：一个组件的位移

新会话（零消息）时，输入卡**居中**在正文列里；发出第一条后**位移到底部贴底**。
参考实现在这里还有一层蓝色背景光晕（`.heroGlow`），**我们不拿**——那是一张跟着卡片缩放的
矢量资源，收益是氛围，成本是又一份要维护的资产。

**这与 Home 不冲突**：Home 是"全部会话"的入口视图，hero 是"某个会话还没开始"的空态。
两者现在被合并成了同一个 `HomeView`，本次拆开。

### 6.2 sticky 输入区

现在输入区在滚动容器**外面**，靠 `scrollbar-gutter: stable both-edges` 把两条竖线对齐
（`App.tsx` 里那段注释写得很清楚）。改成输入区**进滚动容器、`position: sticky; bottom: 0`**：

- 好处：滚轮在输入区上方也能滚动正文；正文与输入卡天然同轴。
- 遮罩：`linear-gradient(180deg, bg-base/0 0px, bg-base 36px)`。
  **36px 必须是像素不是百分比**——用百分比的话，输入框长高时渐变带会跟着拉长，
  正文会被越糊越多。
- `scrollbar-gutter: stable` **仍要保留**（单侧即可，不再需要 `both-edges`）：
  sticky 元素贴的是滚动容器的 content box，滚动条出现与否会让它整体横移。

### 6.3 工具调用压成单行 —— 本次最大的变化

现在 `cards.tsx` 把每次工具调用画成块状卡片，一屏放不下几条。改成 **24px 单行**：

```
[16px 图标] gap6 [工具名 14/24] gap8 [2×2 圆点] gap8 [摘要，单行省略号] … [耗时]
```

- **收起态**是这一行；**展开态**才是 ADR-0058 的四种卡片种类（`generic` / `terminal` / `diff` / `search`）。
- **点这一行 = 在右栏打开它的详情**（§7）；**点行首的箭头 = 就地展开卡片**。两个动作分开。
- 运行中：300px 宽的玻璃光带从左扫到右（背景色 60% 的渐变），**不是 spinner**。
  一屏十几条调用时，十几个转圈是灾难，扫光带只是"这一行在动"。
- 失败：摘要用 `state-error-primary` 显示错误首行。

**这不破坏 M3-f 的成果**：渲染层仍然只认识四种卡片种类，不认识任何具体工具。
单行的图标与摘要来自已有的 `ToolCardPair` 投影，**不新增渲染层对工具的知识**。

### 6.4 回合级呈现

- **回合状态**：shimmer 文字（渐变 `background-clip: text` 循环扫过）+ 等宽数字计时器，
  替掉现在的"运行中"徽标。`prefers-reduced-motion` 下静止。
- **回合统计**：回合结束后一行居中 12/20 灰字 —— `tokens 输入/输出 · 用时 · 花费`。
  数据**已经在** `turn.completed` 的 `usage` 与 `costUsd` 里，不需要新事件。
  `costUsd` 缺失与 0 是两回事（payload 注释已写明），UI 要区分"未知"与"0"。
- **回到底部**：零高度 sticky 槽 + 34px 圆钮，`margin-top: -34px` 使它**不撑高 scrollHeight**
  （否则它自己会把"是否贴底"的判定推翻）。

### 6.5 上下文占用环（唯一要动 runtime 的一项）

发送键旁 14px 环，点开显示三段分解：系统提示词 / 工具 schema / 对话。

**成本诚实说**：小明现在**没有**这份投影。`usage` 是上一次请求的实际用量，
不等于"当前上下文占了多少"——后者要在 `ContextBuilder` 组装完请求后按段估算并上报。
所以它**单独排在最后一段（f）**，前面五段不依赖它。

## 7. 右栏：从「工作区」升级成「详情 + 工作区」

用户要保留的交互不变：**右上角图标展开右栏**。变化在内容。

右栏顶部两个 tab：

| tab | 内容 | 何时自动选中 |
|---|---|---|
| **详情** | 选中的那次工具调用：`Input`（入参 JSON）+ `Output`（结果）。代码段 r12 / pad16 / mono 13-22 | 点击任一工具行时 |
| **工作区** | 现有的 `TodoPanel` / `LiveCalls` / `TerminalPanel` / `CheckpointPanel` | 没有选中调用时；手动切回时 |

详情的材料**从已落库的事件流反查**，不新增数据源——这与 ADR-0065 卡片动作通道
"由 `callId` 从已落库事件流反查工具"是同一条路。

**Code Mode 的子调用也要能选中**：`tool.code.dispatch` 是持久事件，
一条 `run_code` 展开后每个子调用都应该是一行、都能点进详情。
参考实现的 `DetailsPanel` 正是这么做的（`settledMaterial` 注释里写着 "native call or
run_code sub-dispatch"）。**注意**：子调用的 payload 里没有 `forModel`（ADR-0072），
详情栏的 `Output` 段对子调用只能显示"已执行 / 失败原因"，不能显示结果正文——
**那份正文本来就没有落库，这是设计，不是缺数据**。UI 文案要说清，否则下一个人会去给
`tool.code.dispatch` 加一个 `forModel` 字段"把详情补全"。

### 8.1 形态：模态面板 + 左导航，不是第三个主视图

现在设置是 `shellView === 'security'`，与 Home / chat 并列 —— 进设置等于**离开会话**，

**`config.json` 可从 UI 改的叶子字段：3 → 10。**

**红线展示要新开一条只读投影。** 现在 `StatusResult.security.protectedResources` 是
`desktop-host.ts` 里**硬编码的四行中文概述**（"运行数据、事件库与 checkpoint/blob"…），
不是规则本身——拿它当红线清单显示，用户看到的是一段散文，对不上任何一次实际拒绝。
本次要从 `packages/kernel/src/policy/defaults.ts` 导出一份
**`{ target, capabilities, why }` 的只读投影**，UI 逐条列出。
这同时顺手做成一件好事：红线为什么同时挂在三个能力上（ADR-0017 的教训）
终于在界面上说得出来。

**这条投影是单向的**：`UpdateSettingsRequest` 里不得出现任何红线字段。

### 8.3 三条明确不放

1. **不提供 `allow` 方向的规则编辑。** ADR-0039 之后"收紧的表达方式只有一种：往规则表里加 deny"。
   UI 只给"新增拒绝规则"。
   **而且这条要在主进程 IPC 层校验，不是靠 UI 不显示** —— 渲染层是不可信输入侧，
   `UpdateSettingsRequest` 收到一条 `effect: 'allow'` 必须直接拒绝。
2. **不提供红线的关闭开关。** 红线是六项安全底座之一，只读展示，附一句"内置核心保护不能在设置页关闭"（现有文案已有，保留）。
3. **不提供 `logging.redact` 开关。** 见 §9.1——它既是死配置，也**本来就不该可配**。

### 8.4 密钥的入口形状

`SetApiKeyRequest` 已经存在且刻意不做格式校验（"这个通道的风险不是传进来一个坏 key，
是把 key 传出去，而那条路根本不存在"）。设置页只需：输入框 + 保存 + `hasApiKey` 的已配置指示。
**已保存的 key 不回显、不提供"查看"按钮** —— 没有读回通道是这个设计的一部分。

## 9. 动手前必须先处理的两个发现

### 9.1 `logging.level` 与 `logging.redact` 是死配置

`Config` schema 里有这两个字段、`DEFAULT_CONFIG` 里有默认值，
**全仓库没有任何一行代码读它们**（已 grep 确认：只有 schema 定义与默认值两处）。
`redact()` 是在 `sealEvent()` 里**无条件**执行的。

给死配置做设置行，等于给用户一个不生效的开关——这比没有开关坏得多。处置：

- **`logging.redact` 从 schema 删除。** 它是六项安全底座之一（ADR-0053），
  "可配置的脱敏"本身就与底座定义冲突。留着一个永远为 `true` 的字段，
  只是在邀请下一个人把它接上。
- **`logging.level` 二选一**：接到实际日志出口上，或一并删除。
  建议先删——目前没有可配置的日志出口，接一个只为了让设置页多一行不值。

删配置字段是契约变更，要写 ADR。

### 9.2 `cn.ts` 与 `@theme` 的人工同步

见 §4.4 第 3 条。token 换轨这一批必须顺手把它变成闸门。

## 10. 收益 / 真损失 / 值不值

### 收益

- **一屏能看到的工具调用**：块状卡片 ~3 条 → 单行 ~15 条。这是"看得懂 Agent 在干什么"的量变。
- **`config.json` 可从 UI 改的叶子字段：3 → 10。** 换模型不再需要手编 JSON + 重启。
- **Code Mode 第一次有开关。** 刚花一整段做完的能力，现在没有任何用户路径能打开它。
- **权限规则第一次有出口。** ADR-0039 之后它是唯一的用户侧权限入口，却零 UI。
- 视觉：亮色不再是三个米白糊在一起；深色不再靠"贴得很近"兜底。

### 真损失（不是风险，是确定会付的代价）

1. **渲染层 4301 行里大部分要动**，`styles.css` 基本重写。M3.5 期间桌面端会有一段不稳定期。
2. **推翻两条已采纳决策的一部分**：ADR-0004「风格贴近 Claude Code 桌面端」与
   ADR-0037「主题色仍与 Claude Code 一致（不换 openCode 灰白调）」。
   要写 `Supersedes`，**不许静默改写旧文件**。
3. **`docs/experience/` 里所有界面截图与描述作废。** 体验记录是资产，作废一批是真损失。
4. **多一处状态来源**（`localStorage` 的 UI 偏好）。§5.3 给了判据，但判据本身要有人守。
5. **上下文占用环要动 `@xm/runtime`** —— 本次唯一越出渲染层的改动。
6. **删两个配置字段**是对外契约的收缩，别人的 `config.json` 里可能已经写了它们（虽然没生效）。
   加载器要能容忍（未知字段的处理方式需在 ADR 里写死）。

### 值不值：值

判据不是"更好看"。是：**M2/M3 交付的能力有一半在界面上不存在**——呈现模式、权限规则、
多模型角色路由、价目表。继续做 M4（MCP、Skill、多 Provider）只会让"做了但用不到"的差距
按倍数放大，因为 M4 每一件交付都需要一个设置出口。**出口要先于内容**。

视觉换轨则是搭车：token 体系反正要为设置中心扩一圈（状态色、层级色现在都没有），
在扩它的同一批换掉调性，比先扩暖色再改冷色便宜。
